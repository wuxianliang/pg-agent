# v24 S3 六动词与 run 状态机：Deep plan

## Goal

让四个写动词（`start/cancel/steer/respond`）共用 `advance`、两个读动词（`poll/wait_check`）零写，并把 `runs` 从 S1 的纯 DDL 变成可驱动的状态机：`start` 原子写 run、run pins、首个 `model_call`；`cancel` seal 并撤销发布权；`steer` 推进 epoch/driving generation 并决定立即续链或 pending_steer；`respond` 消费 waiting interaction；`poll/wait_check` 返回可增量读取的投影。同时关闭 G3 的 run-pin 半部：run pin 挡 provider release、withdraw 后新 start 失败、start/dispose 双序。

### S2 的一个实质缺陷（S3 W1 修复）

S2 的 `v24.resolve` 是 `SECURITY INVOKER`，体内 SELECT `scopes/slots/episodes/fibers`；三个协议角色**零表权**。S2 测试只以 migration owner 调用过它，所以 gate 绿了；以 service 调用实际会 `42501 permission denied for table`。S3 的 `poll/wait_check` 有同样问题，因此 W1 统一改为读面 DEFINER allowlist，并补上「真实 service/operator 调用读面」的断言。S2 的矩阵/README 在 S3 收尾时回写更正（不得静默）。

### S1/S2 的既有实现基线

- `advance` 唯一**可写**入口；G 首锁；十表；claim/T2；`host_prepare`/`host_release` settlement。
- S2：`resolve`、`fiber_control`（on/off/retry、activation pin 屏障、E1→E2）、child install、leaf `dispose`、`check_policy` v1。
- `runs` 表存在但无写入者；`revision` 在 S1/S2 恒为 0（C2 空洞）。S3 的 start 首次写入 `revision=1`，并在每次改变 run 可见状态的 advance 递增。
- `pins` 已有 `consumer_type=run` 的 XOR/唯一约束与「run terminal 且无引用 effect 时才可释放」的 schema 约束口径（DDL 层未强制，由 advance 实现）。

## 2. 定位与边界

### 2.1 在设计稿中的位置

S3 是「控制面」：把 S1 的 admission/replay、S2 的 episode/pin/resolver 组合成可运行的 run 状态机。S4 才执行 model/tool；因此 S3 的 run 会停在「有一个 ready `model_call`」的状态，由 S4 的 settlement 推进。S3 的 `cancel/steer/respond` 只写控制事实与后继资格，不执行外部 IO。

### 2.2 发布合同（S4/S5/S7 消费）

| 合同 | 内容 |
|---|---|
| **C12 run handle/revision** | `run_id` + `registration_generation`（start 恒为 1）；`revision` 从 1 起，每次改变 run 可见状态的 advance +1；poll/wait 只读 |
| **C13 input/pins** | `p_input.requires[]` 决定 run pin；ownerless 必须为空；run pin 的 `consumer_run_id/consumer_epoch=1` |
| **C14 read shapes** | poll/wait_check 的 JSON 形状与 cursor 语义（revision / event seq） |
| **C15 interaction** | `runs.interaction` 的字段闭集与 respond 消费规则；生产归 S4 |
| **C16 control** | cancel/steer/respond 的 CAS、终态、pending_steer 与后继规则 |

### 2.3 明确不做

- 不做 model/tool 执行、批次屏障、`chat_tool_v1` reducer、continuation（S4）。
- 不做完整 T2 排空、unknown wall、seal 成本（G2b/S4）；cancel 只做控制面 seal。
- 不做 spawn/child run（S4）；不做 owner 清理/scope close（S5）。
- 不做 LISTEN/等待的 SDK 循环；只提供 `wait_check` 短事务读函数。
- 不做 interaction 的生产（S4）；S3 只消费 fixture seed 的 interaction。
- 不做 provider 切换后的新 run 自动重试；withdraw 后新 start 直接失败。

### 4.1 run 身份、授权与 revision

**owner**：`run_owner(p_run uuid) RETURNS uuid`，SQL STABLE DEFINER，读：

```sql
SELECT e.requester_id FROM v24.effects e
 WHERE e.run_id = p_run AND e.kind = 'command_start'
 ORDER BY e.created_at LIMIT 1;
```

**授权**（读）：`session_user` 的 principal = owner，或 `pg_has_role(session_user,'v24_admin','USAGE')`；否则读函数返回 `{v:1,error:{code:"not_found_or_denied"}}`。
**授权**（写）：owner 或 admin；否则 W0 `unauthorized`。

**revision**：`runs.revision` 在 start 置 1；此后每个改变 run 可见状态（status/epoch/driving/interaction/pending_steer/result/预算）的 advance 递增 1。读函数不写、不递增。

### 4.2 `start`

```sql
CREATE FUNCTION v24.start(p_scope_id uuid, p_owner_fiber_id uuid,
  p_input jsonb, p_budget jsonb, p_request_key text) RETURNS jsonb
LANGUAGE plpgsql SECURITY INVOKER SET search_path=pg_catalog,v24;
```

wrapper 只做长度/类型快检并构造 `command_start` outcome（payload `{scope_id,owner_fiber_id,input,budget}`）。

**`p_input` 闭集**：必须 object；可选 `requires` 数组，元素 `{key: text}`，1..16 项、key 唯一且 1..256；其余成员原样保留在首 `model_call.request.input`，不解释。ownerless 时 `requires` 必须为空。

**`p_budget` 闭集**：object，键只允许 `steps/tool_calls/tokens/wall_ms`：

| 键 | 规则 |
|---|---|
| `steps` | 必填整数 1..1024（>256 ⇒ `budget_exceeded`） |
| `tool_calls` | 必填整数 0..1024 |
| `tokens` | 可选整数 0..10^12 |
| `wall_ms` | 可选整数 1..86400000 |

非整数/负值/未知键 ⇒ W0 `invalid_args`；超出部署上限 ⇒ W1 `budget_exceeded`。

**前置（顺序）**：

1. scope 存在且调用者是其 owner 或 admin；否则 `unauthorized`。
2. `scope.close_requested_at IS NOT NULL` ⇒ W1 `scope_closed`。
3. `p_owner_fiber_id` 非空时：fiber 必须存在（否则 W0 `invalid_args`）、`fiber.scope_id = p_scope`（否则 W0 `invalid_args`）、未 disposed、`want_on=true`、`current_episode_id` 指向 active episode、其 install `installed`；否则 W1 `provider_unavailable`。
4. 每个 `requires[].key` 用 `resolve(p_scope_id, keys)` 解析：无 live ⇒ W1 `dependency_unresolved`（零 run/pin/model effect）。
5. ownerless 且 requires 非空 ⇒ W0 `invalid_args`（O8）。

**成功写序**（同一 advance）：

```text
1. INSERT runs: status='running', epoch_no=1, registration_generation=1,
   turn_no=0, driving_generation=1, remaining_*=budget, revision=1,
   owner_fiber_id/owner_episode_id（owner 时）, created_at/updated_at=now()
2. INSERT pins (每个 live require): consumer_type='run', consumer_run_id=run,
   consumer_epoch=1, key, slot_id, provider_fiber_id/provider_episode_id,
   descriptor_digest, created_by_effect=command effect
3. INSERT model_call (ready): run_id, scope_id, fiber_id/episode_id（owner 时）,
   epoch_no=1, generation=1, ordinal=0, parent_effect_id=command effect,
   request={run_id,epoch_no,generation,input:p_input,budget:p_budget},
   replay_policy='no_replay'
4. events: run_started（run）、model_call_requested（run）
```

响应 `emitted=[run_id, model_effect_id]`、`revision=1`。run handle = `run_id` + `registration_generation=1`（v1 恒定；不扩封套成员，D-S3-3）。

`u_effects_model_call (run_id) WHERE kind='model_call' AND status IN ('ready','claimed')` 保证每 run 只有一个未结算 model_call；start 的同事务插入受该索引兜底。

### 4.3 `poll` / `wait_check`

```sql
CREATE FUNCTION v24.poll(p_run_id uuid, p_after_revision bigint DEFAULT 0)
RETURNS jsonb LANGUAGE sql STABLE SECURITY DEFINER
SET search_path=pg_catalog,v24;

CREATE FUNCTION v24.wait_check(p_run_id uuid, p_registration_generation bigint,
  p_epoch bigint, p_after_event_seq bigint) RETURNS jsonb ...
```

**投影**（`run_projection(run_id)`，读面 DEFINER）：

```json
{"run_id","scope_id","status","epoch_no","registration_generation","turn_no",
 "driving_generation","interaction","pending_steer","close_intent","result",
 "remaining_steps","remaining_tokens","remaining_tool_calls","remaining_wall_ms",
 "revision","created_at","updated_at","ended_at","owner_fiber_id","owner_episode_id"}
```

**poll 返回**：

```json
{"v":1,"revision":R,"changed":R>p_after_revision,"run":{...},
 "events":[{"seq","event_kind","payload","created_at"}...]}
```

`events` 是该 run 的 `entity_type='run'` 事件，按 seq 升序，最多 64 条；`changed` 只表达 revision 游标。run 不存在/无权 ⇒ `{v:1,error:{code:"not_found_or_denied"}}`。

**wait_check 返回**：与 poll 相同的 `run`，`events` 过滤 `seq > p_after_event_seq`，另加：

```json
"wake":{"ready":true|false,"reason":"event|terminal|interaction|epoch|none"}
```

reason 优先级：`terminal`（status ∈ completed/failed/cancelled/blocked_unknown）> `interaction`（interaction 非空）> `epoch`（p_epoch ≠ run.epoch_no）> `event`（有待读事件）> `none`。
`registration_generation` 不匹配 ⇒ `{v:1,error:{code:"registration_stale"}}`；run 不存在/无权 ⇒ `not_found_or_denied`。两函数均零写、不取 G、不取行锁。

### 4.4 `cancel`

```sql
CREATE FUNCTION v24.cancel(p_run_id uuid, p_expected_generation bigint,
  p_request_key text) RETURNS jsonb ... SECURITY INVOKER;
```

解释器 `interpret_cancel`：

1. run 不存在 ⇒ W0 `invalid_args`；owner 不符 ⇒ W0 `unauthorized`。
2. `p_expected_generation <> runs.driving_generation` ⇒ W1 `stale_generation`。
3. terminal ⇒ W1 `already_terminal`（同 key replay 由 advance 处理）。
4. 写 run：`status='cancelled'`、`ended_at=now()`、`interaction=NULL`、`pending_steer=NULL`、`close_intent={kind:'cancel',generation,at}`、`driving_generation+1`、`revision+1`。
5. effects：
   - `kind IN ('model_call','tool_call') AND run_id=run AND status='ready'` ⇒ `status='cancelled'`、`settled_at=now()`、`outcome=NULL`（CHECK 要求 cancelled 无 outcome）。
   - `status='claimed'` ⇒ `cancel_requested=true`（保持 claimed）。
6. run pin 释放：`pins.consumer_run_id=run AND released_at IS NULL`，且不存在引用它的 effect（`effects.pin_id=pin AND (status IN ('ready','claimed') OR (status='unknown' AND resource_quiesced_at IS NULL))`）⇒ `released_at=now()`、`released_by_effect=command effect`。
7. 事件：`run_cancelled`（run）payload `{run_id,generation}`。
8. 响应 `emitted=[]`、`revision=runs.revision`（新值）。

`cancel` 不退役共享 fiber、不改 activation pin、不改 `effects.fence`。

### 4.5 `steer`

`steer(p_run_id, p_expected_generation, p_instruction text, p_request_key)`，`p_instruction` 1..8192 字符。

1. run/owner 校验；CAS；terminal ⇒ W1 `already_terminal`。
2. 归档旧 ready business effect（`model_call`/`tool_call` 的 ready）⇒ `cancelled` + `settled_at`、outcome NULL。
3. 旧 claimed business effect 存在？
   - **无**：`epoch_no+1`、`driving_generation+1`、`interaction=NULL`、`status='running'`、`pending_steer=NULL`、`revision+1`；创建新的 ready `model_call`（generation=新值，request.input 沿用 run 的输入，instruction 写入 request.instruction）。
   - **有**：同样递增 epoch/driving、清 interaction、`status='running'`、写 `pending_steer={instruction,generation:new,epoch:new}`、`revision+1`；**不**创建 `model_call`；旧 claimed 保持，由 S4 的最后结算消费 pending_steer。
4. run pins 不变（能力 pin 只随 run terminal/资源静默释放）。
5. 事件：`run_steered`（run）payload `{run_id,generation,deferred:bool}`。

`steer` 不清 install/scope/pin；等待中的 run 清 interaction 后必须置 running（`waiting iff interaction` CHECK）。

### 4.6 `respond`

`respond(p_run_id, p_interaction_id, p_response jsonb, p_expected_generation, p_request_key)`。

`runs.interaction` 闭集（S4 生产、S3 消费）：

```json
{"interaction_id": uuid, "origin_effect_id": uuid, "generation": bigint,
 "schema_digest": "\\x..", "prompt_digest": "\\x..", "created_at": timestamptz}
```

1. run/owner 校验；terminal ⇒ W1 `already_terminal`。
2. run.status 必须 `waiting` 且 interaction 非空、`interaction_id` 精确匹配；否则 W1 `interaction_mismatch`。
   **interaction 检查先于 CAS**：两个不同 key 争答同一 interaction 时，后者看到已消费 ⇒ `interaction_mismatch`，而不是 `stale_generation`（§4.7 的负例口径）。
3. CAS：`p_expected_generation = runs.driving_generation`，不符 ⇒ W1 `stale_generation`。
4. 消费：`interaction=NULL`、`status='running'`、`driving_generation+1`、`revision+1`；创建新的 ready `model_call`（generation=新值，request 带 `response` 与 `origin_effect_id`）。
5. 事件：`interaction_responded`（run）payload `{run_id,interaction_id,generation}`。
6. 响应 `emitted=[model_effect_id]`、`revision`。

两个不同 key 争答：G 序列赢家先消费；后者看到 interaction 已空 ⇒ `interaction_mismatch` 零领域写（W1）。同 key 重放由 advance 先返回首次 response。

### 4.7 delta 足迹与 applier

新增四个 command 的 footprint：

| kind | 允许写 |
|---|---|
| `command_start` | `runs` insert、`pins` insert、effects（command 自身 + `model_call` successor）、events（run）、successors |
| `command_cancel` | `runs` update、`effects` update（ready→cancelled / claimed→cancel_requested）、`pins` update（release）、events（run） |
| `command_steer` | `runs` update、`effects` update（archive/cancel_requested）、successors（model_call）、events（run） |
| `command_respond` | `runs` update、effects update（archive 旧 ready，如有）、successors（model_call）、events（run） |

`effect` 补丁扩展可选 `run_id`（command effect 归属），校验该 run 存在且与 payload 的 run_id 一致；`command_start` 另允许 `run_id` 指向本 delta 新插入的 run（在 domain insert 之后校验）。记 D-S3-2。

applier 对 `runs` 的 update 只允许闭集列：`status/epoch_no/driving_generation/interaction/pending_steer/close_intent/result/revision/ended_at/updated_at`；对 `effects` 的 update 只允许命令所属 run 的 `model_call`/`tool_call` 行，且状态迁移只允许 `ready→cancelled`、`claimed→claimed+cancel_requested`。

### 4.8 run pin 释放规则

一个 run pin 可释放 iff：

1. 其 run 已 terminal；且
2. 不存在 `effects.pin_id = pin` 且 `status IN ('ready','claimed')` 的 effect；且
3. 不存在 `effects.pin_id = pin AND status='unknown' AND resource_quiesced_at IS NULL` 的 effect。

S3 在 `cancel` 的同一 advance 里执行该检查（只处理 ready/claimed；unknown 无生产者，条件自然满足）。`steer`/`respond` 不释放 pin。S4 的 model/tool settlement 结束后按同一规则释放。

### 4.9 错误码：S3 的新生产者

| 码 | 写类 | 生产者 |
|---|---|---|
| `provider_unavailable` | W1 | start 时 owner fiber disposed/未 active/install 非 installed |
| `budget_exceeded` | W1 | start 的预算超部署上限 |
| `interaction_mismatch` | W1 | respond 的 interaction 不匹配/已被消费 |
| `not_found_or_denied` | N/A（读面 JSON） | poll/wait 的 run 不存在或非 owner |
| `registration_stale` | N/A（读面 JSON） | wait_check 的 registration_generation 不符 |

S3 新增 5 个生产者后，仍未产生的只剩 2 个：`blocked_unknown`（S4）、`cleanup_cycle`（S5）。`not_found_or_denied` 与 `registration_stale` 由读面返回（W0/读面 JSON），不经 `advance` 的 W 类。

### 4.10 ACL 与读面 DEFINER

- 读面 DEFINER allowlist：`resolve`（S2 修复）、`run_owner`、`run_projection`、`poll`、`wait_check`；全部 `SET search_path=pg_catalog, v24`、体内零 DML、无 `pg_advisory_xact_lock`。
- 写 wrapper：`start/cancel/steer/respond` INVOKER；GRANT EXECUTE 给三个协议角色。
- G1-A 对齐：`prosecdef=true` 集合从 `{advance}` 扩为 `{advance, resolve, run_owner, run_projection, poll, wait_check}`；断言除 advance 外全部只读（无 `INSERT/UPDATE/DELETE`、无 advisory lock），且 advance 仍是唯一可写 DEFINER。
- `50_permissions.sql` 的 fail-closed 块继续断言 owner/search_path/PUBLIC；额外断言读面 allowlist 恰为上述集合。

### 4.11 开放项裁决

**O8**：ownerless start 不建 episode/pin，requires 必须为空（Oracle 1A）。
**D-S3-1** 读面 DEFINER allowlist + S2 `resolve` 修复（Oracle 7A）。
**D-S3-2** `effect` 补丁允许 `run_id` 归属。
**D-S3-3** run handle 由 `emitted[0]` + `registration_generation=1` 表达，不扩封套。
**D-S3-4** cancel 把 ready business effect 置 `cancelled`（outcome NULL），不新建 archive 表。
**D-S3-5** steer 的立即续链以「无旧 claimed business effect」为界（Oracle 6A）。
**D-S3-6** interaction 生产归 S4；S3 只消费 seed。
**D-S3-7** owner fiber 的 scope 必须等于 start 的 scope。

## 5. gate G2a 与 G3b

### 5.1 G2a 具名断言

| ID | 断言 | 证据形式 |
|---|---|---|
| G2a-1 | owner start：run 字段（status/epoch=1/reg=1/turn=0/driving=1/revision=1/预算）、run pins 精确、首 `model_call` ready（run_id/generation=1/request）、事件 2 条；replay byte-equal、同 key 不增行 | 行快照 + effect 计数 |
| G2a-2 | ownerless start：无 episode/pin，`requires` 为空；非空 ⇒ W0 `invalid_args` | 行快照 + 错误码 |
| G2a-3 | start 失败：scope_closed、provider_unavailable（disposed / 非 active / install 非 installed）、dependency_unresolved（withdrawn slot）、budget_exceeded、unauthorized；全部零 run/pin/model effect（W1 仅 command receipt） | 错误码 + diff |
| G2a-4 | poll：投影键闭集、`changed` 随 revision、events ≤64、零写；非 owner ⇒ `not_found_or_denied`；不取 G/行锁 | `pg_locks` + 全库 diff |
| G2a-5 | wait_check：registration 不符 ⇒ `registration_stale`；event/terminal/interaction/epoch 四种 wake reason 各一次；event seq 过滤；零写 | 返回封套 + diff |
| G2a-6 | cancel：CAS、terminal、ready→cancelled、claimed→cancel_requested（不结算）、run seal、revision+1；pin 仅在无引用时释放；同 key replay；新 key `already_terminal` | 行快照 + effect 计数 + pin 列 |
| G2a-7 | steer：epoch+1、driving+1、interaction 清空；无 claimed ⇒ 新 model_call；有 claimed ⇒ `pending_steer` 且无新 model_call；terminal ⇒ `already_terminal`；pins 不变 | 行快照 + effect 计数 |
| G2a-8 | respond：seed waiting interaction；消费后 interaction NULL、generation+1、新 model_call、事件；错 id ⇒ `interaction_mismatch`；terminal ⇒ `already_terminal`；同 key replay | 行快照 + 错误码 |
| G2a-9 | 四写共用 advance：每个 command effect 同事务 settled + request response；两读前后十表 diff 为空 | `state()` diff |
| G2a-10 | 预算：`remaining_*` 精确；`steps=0`/负数/未知键 ⇒ `invalid_args`；超上限 ⇒ `budget_exceeded`；零写 run | 行快照 |

### 5.2 G3b 具名断言

| ID | 断言 | 证据形式 |
|---|---|---|
| G3b-1 | run pin 挡 provider release：A run pin 住 B 的 slot；B off ⇒ deferred（slot withdrawn 未 released）；A cancel 且无引用 effect ⇒ pin 释放；B 再 off 完成 close | 逐列 + 两阶段 |
| G3b-2 | claimed 引用挡释放：fixture seed 一个 claimed `tool_call`，`effects.pin_id` 指向 run pin；cancel ⇒ 该 effect `cancel_requested`、pin **保留**；effect 结算/静默后（S4）才释放 | pin 列 + effect 状态（完整释放标「未验证 / S4」） |
| G3b-3 | withdraw 后新 start：B off 撤 slot；新 start 需要该 key ⇒ `dependency_unresolved`；已有 run pin 仍有效，不影响既有 run | 错误码 + diff |
| G3b-4 | start/dispose 双序：start 先 ⇒ run pin 让 dispose 等（保持 dispose_pending）；dispose 先 ⇒ fiber 墓碑/episode closed，start `provider_unavailable`；无悬空 pin | 两条已提交顺序场景；不作为并发/锁屏障证明 |
| G3b-5 | start/off 双序（G 序列）：start 先 ⇒ off deferred；off 先 ⇒ start `dependency_unresolved` | `pg_blocking_pids()` + 两序 |

### 5.4 证据粒度与夹具

- `state()` 十表全快照；W1 用 `domain_state`（去 effects/requests）。

- 并发只用双连接 + `pg_blocking_pids()`/`pg_locks`，不用 sleep。
- FakeHost 不用于 S3（无外部 IO）；S4 才需要。
- `v24/s3/test_g2.py` 复用 `v24/s1/setup_db.py` 与 S2 seed helper；独立退出 0。
- S1/S2 全部 gate 回归：`load.py`、`s1/setup_db.py --self-check`、`s1/test_ddl.py`、`s1/test_g1.py`、`s2/test_g3a.py`。

## 6. 风险与回退

| 风险 | 最脆弱处 | 缓解 | 停手条件 |
|---|---|---|---|
| R1 读面 DEFINER 越权 | 读函数成为第二类 DEFINER | 封闭 allowlist + 固定 search_path + 零 DML/advisory 断言 + 真实 service 调用 | 任一读函数可写或可锁 ⇒ 停工 |
| R2 revision 语义漂移 | 多写点各自 +1 | 只允许 applier 的 run update 路径递增；poll/wait 不写 | 读面改变 revision ⇒ 停工 |
| R3 steer 新旧驱动重叠 | pending_steer 与 model_call 并存 | 「有 claimed ⇒ 不建 model_call」硬规则；G2a-7 两分支 | 两者同时存在 ⇒ 停工 |
| R4 cancel 释放 pin 过早 | ready 刚取消、claimed 仍引用 | 释放前逐 pin 查 `effects.pin_id` 引用；claimed 保留 | 出现悬空释放 ⇒ 回滚该步 |
| R5 S2 resolve 修复影响旧 gate | G1-A/ACL/矩阵 | 只改 DEFINER 与授权，不改返回形状；S1/S2 全量回归 | 任一旧 gate 红 ⇒ 修断言前先停 |
| R6 start 与 dispose 竞态 | 悬空 run pin / 幽灵 run | G 下同事务；run pin 先则 dispose 等；dispose 先则 start 拒绝 | 出现 pin 指向 disposed install ⇒ 停工 |
| R7 读函数形状被 S4 误用 | poll 的 events 语义 | 在 README/矩阵冻结：poll 的 `changed` 用 revision，wait 用 event seq；S4 不得混用 | S4 计划未引用 C14 ⇒ 回写 |

## 7. 与设计稿的分歧点清单

| # | 分歧 | 设计位置 | 采用 | 理由 |
|---|---|---|---|---|
| D-S3-1 | 读面是 DEFINER allowlist | §B.3 只写 `resolve ... SQL STABLE`，未定 security | `resolve/poll/wait_check/run_owner/run_projection` 均 DEFINER + 固定 search_path + 零 DML | 协议角色零表权，INVOKER 读面会 `42501`；这是 S2 的实测缺陷修复 |
| D-S3-2 | `effect` 补丁可写 `run_id` | §4.14.4 delta 形状无 run 归属 | 可选 `run_id`，校验存在/一致 | command effect 需要按 run 归属以支撑 run_owner/审计 |
| D-S3-3 | run handle 不扩封套 | §4.2「start 返回的 run handle」 | `emitted[0]`=run_id，`registration_generation` v1 恒 1（poll 回显） | 避免改 §2.1 的六键封套；v1 无重连换代 |
| D-S3-4 | cancel 的 ready effect 置 `cancelled` | §4.5「归档未 claim 后继，取消 ready effect」 | `status='cancelled'`、`settled_at`、outcome NULL | `c_effects_outcome` 要求 cancelled 无 outcome；不新建 archive 表 |
| D-S3-5 | steer 立即续链的边界 | §4.6「旧 claimed 时等结算」 | 无 claimed ⇒ 立即 model_call；有 ⇒ pending_steer | Oracle 6A；避免新旧驱动重叠 |
| D-S3-6 | interaction 生产归 S4 | §4.7 由 model outcome 生产 | S3 只消费 seed | pre-plan S3 发布合同只写「interaction 消费」；S4 消费合同 |
| D-S3-7 | owner fiber scope 必须等于 start scope | §4.2 未要求 | W0 `invalid_args` | 避免跨 scope 解析 run pin 的歧义 |

**D 清单是披露机制，不是规格修订。** 若实施发现需要改设计语义，先走设计稿修订 + Oracle 复审。
