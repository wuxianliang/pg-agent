## 2. 定位与边界

### 2.1 位置

顺序是 `S1 → … → S6 → S8 → S7`。S8 只补设计 §5.5 的 spawn/child run；S7 才做三面并发矩阵，G6 必须消费 G7 的 spawn 证据。

### 2.2 只做什么

- `agent.spawn` 作为 model outcome `tool_calls[]` 的**保留 intent key**：不是 effect、不可 claim、无外部 IO。
- 同一 advance 内：校验 args/digest/父状态/quota/owner；创建 child run、spawn edge、child 首 `model_call`；扣父 quota、写 child 初始 quota；可选 owner run pin；写父/子事件；返回 `spawned`。
- 幂等：`(parent_run_id,spawn_key)` 唯一；同 bytes replay 同 child；异 bytes `spawn_key_conflict` W0。
- G7-A…H + 7 负例；child 首 model 的 recovery 由 S6 `command_recover` 覆盖（G7-G）。

### 2.3 明确不做

- 不 install child fiber、不建 child install/slot/provide；child 是 run。
- 不建 escrow 表、责任账、第二 replay 合同、第二 claim/queue。
- 不做 S7 的完整三面并发矩阵；G7 只做 spawn 自身的双连接负例。
- 不把 spawn 做成 effect；`agent.spawn` 不进入 `effects` 表。
- 不新增表/列/索引；`runs` 的 spawn 三列与 `u_runs_spawn` 已在 S1 存在。

### 4.1 `agent.spawn` intent schema

`args` 精确键集（多/少一个都 `invalid_outcome` W0）：

```json
{
  "v": 1,
  "spawn_key": "1..128 chars",
  "input": { "...": "child first model input" },
  "scope_id": "<uuid>",
  "budget": {
    "steps": 1,
    "tokens": 1000,        // 或 null（仅当父 remaining_tokens 为 null）
    "tool_calls": 1,
    "wall_ms": 60000
  },
  "owner_fiber_id": "<uuid>",      // 可选，必须与 owner_episode_id 成对
  "owner_episode_id": "<uuid>"
}
```

冻结规则：

- `spawn_key` 长度 1..128，字符集 `[A-Za-z0-9._:-]`；同一父 run 内唯一。
- `scope_id` 必须等于父 run 的 `scope_id`（v1 不做跨 scope spawn；跨 scope 需要独立授权合同，留后续）。
- `budget` 四字段全必填；`steps/tool_calls/wall_ms` 为正整数；`tokens` 为正整数或 JSON null；null 仅当父 `remaining_tokens IS NULL`。
- `owner_fiber_id/owner_episode_id` 同时有或同时无；有则必须满足 §4.6。
- `spawn_request_digest = sha256(canonical_json(args))`；`args` 含 `spawn_key`，所以同 key 异 bytes 必然 digest 不同。
- 一个 model outcome 至多 **1** 个 `agent.spawn`（v1）；多于 1 个 `invalid_outcome` W0。该限制记 D-S8-7。
- `agent.spawn` 与 `tool_calls[]` 中的普通 tool **不得混用**（v1）：同一 outcome 同时有 spawn 和普通 tool → `invalid_outcome` W0。这样避免“spawn + batch”双重 successor 语义；后续可扩。

### 4.2 C19 保留 key 分流（Oracle Q2=A）

`48_loop.sql` 的 `interpret_model_settlement` 在 C19.0 结构校验中：

1. 遍历 `tool_calls[]` 时识别 `key='agent.spawn'`；它必须只有 `{key,args}`，`args` 按 §4.1 校验；**不计入** `max_tool_calls`、不进入 `v_n_tools`、不参与 pin 成员检查。
2. 普通 tool 的 `max_tool_calls` 计数保持原样；spawn 单独 `v_spawn_count <= 1`。
3. C19 语义段（`48_loop.sql:480–489`）的 pin 循环跳过 `agent.spawn`；否则它会因为没有 pin 被判 semantic unknown。
4. spawn 与 `final`/`interaction` 互斥：任一存在 → `invalid_outcome` W0。
5. spawn 的结构/语义错误在**任何 DML 前**返回；不得把 model effect 结算成 unknown/failed，effect 保持 claimed。

### 4.3 执行顺序（同一 advance，全部在 `interpret_model_settlement` 内）

1. C19.0 结构校验（含 §4.2 分流）；失败 W0。
2. 父 run 读取：必须存在、`status='running'`；`cancelled/completed/failed/blocked_unknown` → `already_terminal` W0（不产生 child）。
3. spawn args 校验（§4.1）；失败 `invalid_outcome` W0。
4. 计算 `spawn_request_digest`；查 `runs` 中 `(parent_run_id,spawn_key)`：
   - 存在且 digest 相同 → **replay**：不新建、不扣 quota、不建 effect；response 返回既有 child handle；继续正常 model settlement（model effect 仍结算成功）。
   - 存在且 digest 不同 → `spawn_key_conflict` W0，整次 settlement 不写。
   - 不存在 → 继续。
5. 父 quota 检查：child 四项初始值逐项 ≤ 父 remaining；`tokens` 的 NULL 规则见 §4.4；超限 → `budget_exceeded` W0。
6. owner 校验（若提供）：§4.6；失败 `dependency_unresolved`/`provider_unavailable` W0。
7. 生成 child `run_id = md5(parent_run_id::text || ':spawn:' || spawn_key)::uuid`；同 key 同 digest 的 replay 必然同 id。
8. 在同一个 delta 内：INSERT child run；UPDATE parent run 扣 quota + `revision+1`；可选 INSERT run pin；INSERT child 首个 `model_call` effect（§4.5）；INSERT 父 `run_spawned` + 子 `run_started` 事件；response 加 `spawned`。
9. 任一步失败 → 整个 advance 回滚（W0）；无 child、无 edge、无 quota 差、无 effect、无事件。
10. 之后按既有 C19 逻辑结算 model effect（success/failure/unknown）；spawn 不改变 model effect 的 receipt 规则。

### 4.4 child run 与 quota 守恒（Oracle Q4=A）

child run 行：

| 列 | 值 |
|---|---|
| `run_id` | `md5(parent_run_id||':spawn:'||spawn_key)::uuid` |
| `scope_id` | 父 run 的 `scope_id` |
| `parent_run_id` / `spawn_key` / `spawn_request_digest` | §4.1 / §4.3 |
| `owner_fiber_id` / `owner_episode_id` | 可选；§4.6 |
| `status` | `running` |
| `epoch_no` / `registration_generation` / `turn_no` / `driving_generation` / `revision` | `0 / 1 / 0 / 0 / 0` |
| `remaining_steps/tokens/tool_calls/wall_ms` | child 初始 quota（§4.1 `budget`） |
| `created_at/updated_at` | `now()` |

父 run 更新：

- `remaining_steps -= child_steps`；`remaining_tool_calls -= child_tool_calls`；`remaining_wall_ms -= child_wall_ms`。
- `remaining_tokens`：父为 NULL → 保持 NULL；父 finite 且 child finite → 相减；父 finite 且 child NULL → `invalid_outcome` W0（不能凭空放大）。
- `revision += 1`；`updated_at=now()`。
- 守恒式（finite 字段）：`Q_parent_before = Q_parent_after + Q_child_initial`；tokens 为 NULL 时不做算术，父子都保持 NULL。

child 首 `model_call` 的 reservation **已含在** child 初始 quota 内：`reserve.tokens = coalesce(child_tokens, 0)`；父不再额外扣；child 的 `remaining_tokens` 就是初始值，settlement 按 S4 既有 refund 规则处理。

### 4.5 child 首个 `model_call`（Oracle Q3=A）

- `effect_id = md5(child_run_id::text || ':model_call:0')::uuid`。
- `parent_effect_id` = 本次被结算的父 model effect；`ordinal=0`；`kind='model_call'`；`status='ready'`；`run_id=child`；`fiber_id/episode_id` = child 的 owner pair（若 NULL 则 NULL）；`epoch_no=0`；`generation=0`；`pin_id` = 可选 child run pin；`replay_policy='no_replay'`。
- request：C17 兼容 + `cause='spawn'`：

```json
{"v":1,"cause":"spawn","run_id":"<child>","epoch_no":0,"generation":0,
 "input":{...},"reserve":{"tokens":<coalesce(child_tokens,0)>},
 "digests":{"policy":"...","schema":"...","toolset":"..."},
 "spawn_key":"...","parent_run_id":"..."}
```

- `digests` 用 child run 的 `model_digests(child_run_id)`；child 无 fiber/episode 时 toolset digest 为空集。
- `interpret_model_settlement` 的 cause 校验扩为 `start|steer|continuation|respond|spawn`；`spawn` 要求 `parent_effect_id` 为父 model effect、`run_id` 为 child、`spawn_key` 匹配 child 行，且 `effect_id` 为上述确定 id。
- child 首 model 与 S6 recovery 兼容：它是 `no_replay`，过期 claimed 时 `command_recover` 转 unknown；G7-G 断言。

**delta 形状（承重）**：child 首 model 必须走 `inserts.effects`，**不能**走 `successors[]`——后者要求 successor 的 `run_id` 等于父 effect 的 `run_id`，而 child run 是新 run。`inserts.effects` 行显式给 `effect_id/parent_effect_id/ordinal=0/run_id=child/scope_id=parent.scope_id/fiber_id?/episode_id?/kind='model_call'/status='ready'/epoch_no=0/generation=0/replay_policy='no_replay'/request`。`validate_and_apply_delta` 的 spawn footprint 必须校验：恰好 1 条 child effect、`run_id` 等于本次新插 child、`parent_effect_id` 等于被结算的父 model effect、`scope_id` 等于 child scope、`ordinal=0`；否则 `invalid_outcome` W0。事件允许 `entity_type='run'` 指向新插 child（`run_started`）和父 run（`run_spawned`），但不允许任意跨 run 事件。

### 4.6 可选 owner run pin（Oracle Q5=A）

- 有 owner pair 时：
  - `owner_fiber_id` 必须存在且 `want_on=true`、`current_episode_id=owner_episode_id`；
  - `owner_episode_id` 必须 `active`；
  - 必须存在 live activation pin：`consumer_episode_id=owner_episode_id AND released_at IS NULL`，其 `provider_slot_id/provider_episode_id/provider_fiber_id` 作为 child run pin 的 provider；
  - INSERT `pins`：`consumer_type='run'`、`consumer_run_id=child`、`consumer_episode_id=owner_episode_id`、`consumer_epoch=owner_episode.epoch`、`key='run'`、provider 三列、`descriptor_digest` 取 activation pin 的 digest、`created_by_effect`=父 model effect。
  - 任一不满足：`dependency_unresolved`（无 live activation pin）或 `provider_unavailable`（fiber/episode 不 active）；W0。
- 无 owner pair：child `owner_fiber_id/owner_episode_id` 为 NULL，不建 pin；child 是 ownerless run，按 S3 ownerless 规则运行。
- 不允许只给一个；不允许 owner pair 指向已 disposed/closing 的 install。

### 4.7 response / events / error

- 父 model settlement 的 response 在六键 envelope 外增加可选 `spawned`（仅本次含 spawn 时）：

```json
{"spawned":[{"run_id":"...","spawn_key":"...","child_effect_id":"...","replayed":false}]}
```

  replay 时 `replayed:true`，其余字段相同。Oracle Q7=A。
- 事件：
  - 父 run：`entity_type='run', entity_id=parent, event_kind='run_spawned'`，payload `{child_run_id,spawn_key,child_effect_id,spawn_request_digest}`。
  - child run：`entity_type='run', entity_id=child, event_kind='run_started'`，payload `{run_id,parent_run_id,spawn_key}`（与 start 的 run_started 同形）。
  - child 首 model effect 不额外发 `model_call_created`；由 effect 行自身承载。
