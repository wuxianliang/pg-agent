2026-10-01。Loop Orchestrate turn 4 / D3。方案来源：Oracle grok 轨（chat D104A6，group 897F5A1E）单轨出具——codex 轨当日配额断供（$182/$180，北京时间 07:00 重置），**终局 L4 评审必须等 codex 恢复后双轨补齐**。冻结检查：13 道（12 stage+smoke）gate 全绿（只加不改；装载序断言按 D1/D2 先例前缀化）+ 新 gate 绿 + Oracle 双轨 PASS；无真栈判据（FakeTool 契约）。AGENTS.md 不在 loop scope：真实 socket 工具入口只写「待用户授权」文书，本轮 gate 零网络。

## 0. 方案骨架（grok 裁定）

与 `bind_invoke` 平行、不进 invoke 树的延续协议：`jaz.bind_tool` 语句在事务内只做校验+实参求值+挂起（invoke→`tool_wait`）；FakeTool 在事务提交后、`call_started` 提交后运行；结算按同迭代 `resume_stmt` 送达 `kind=var`。对现有租约/attempt/deliver 机器做**定向扩展**，不做统一 attempt 引擎重构。LLM 路径、D05 同步 `jaz.tool`、D14 reclaim 不插 attempt、外部 IO 不进事务——全部保持。

**对齐 bind_invoke 的**：`resume_stmt=stmt_index+1`、同迭代不再次 LLM、成功送达 `kind=var`/`provenance=delivery`/`show_in_prompt=true`、名字被 `input`/`scope`/`tool` 占用则冲突不覆盖、`repl_exec` 等待期间不 exit、进入等待 **fence 不加**、租约清除、`tool_wait` 不可 `v15_claim`。
**显式不同的**：无子 invoke、无 `parent_invoke_id` 边、无深度变化、不看 `recursion_available`、不建 scratch、不跑子 open、不调 `v15_on_phase`；状态名 `tool_wait`（不是 `suspended`，避免与等子树混淆）；`statements.child_invoke_id` 保持 NULL。

## 1. 语句与挂起

- 新 kind `bind_tool`；规范拼写 `SELECT jaz.bind_tool('<bind_ident>', '<tool_name>', <jsonb-expr>);`。执行环不调用该 SQL 函数；`jaz` 包装下函数体存在，被真正执行即抛 `V15_INVOKE_FORM`、不插 request。
- 同回复可混排 `bind_tool`/`bind_invoke`、可多条 `bind_tool`，严格按 `stmt_index` 一次只挂起一条；无并发工具 attempt（D06 单租约）。
- 分类器加识别（记号流，字符串/注释/dollar-quote 内不算）；`v15_io_store_statements` stage 13 替换：旧 6 kind 字节不变；`bind_tool` 恰 7 键（多 `tool_name`，匹配 `^[a-z][a-z0-9_]{0,53}$`）。
- `statements` 加可空列 `tool_name`（仅 bind_tool 行非空）；`invokes.status` CHECK 经 stage 13 `ALTER` 增加 `tool_wait`（约束名以目录为准）。
- 实参求值走 D24 同路：prepare 后以 `v15_repl` 求 `arg_sql`；写记号/会写的 jaz.* → `V15_INVOKE_FORM` 不挂起；结果文本超 `protocol.max_invoke_input_length` → `V15_VALUE_INVALID` 不挂起（复用现成上限，不开新配置键）。
- `v15_suspend_for_tool(invoke, iteration, stmt_index, owner, args)` 返回闭集：`{"action":"wait","request_id"}`（随 worker 事务提交：插 open request、语句 running、迭代 suspended、invoke tool_wait、清租约、fence 不变、revision+1、审计 `op=tool_suspend`；不插 attempt、不预留池、不发 span）或 `{"action":"reject","code":...}`（语句 failed+`v15_io_error`，不插 request，invoke 仍 leased，同迭代继续下一条，不 skip_after、不关 repl_exec）。
- reject 校验序：语句 pending 且 kind=bind_invoke 形状 → invoke leased+holder（`v15_repl_check_holder`）→ tool_name 在 catalog → 本 invoke 有 `bindings.kind=tool` 且 name=tool_name 且有 `tool_grants` 行 → **external=true**。缺 catalog/binding/grant = `V15_TOOL_UNAUTHORIZED`（与同步路径同码，D17）；`external=false` = 新码 `V15_TOOL_BINDING`。

## 2. 表机器（spec §3 表数 21→23，写明本修订唯一例外）

`tool_requests`：request_id PK、(invoke_id,iteration,stmt_index) 唯一、tool_id FK、bind_name、args、args_digest=md5(args::text)、status 闭集 open|settled|failed|exhausted、revision。
`tool_attempts`（镜像 LLM attempt 租约列，不镜像 messages）：attempt_id PK、request_id FK、n 从 1 连续唯一、status 闭集 leased|settled|failed|unknown、fence（插时 1）、lease_owner/until、pool_id、reserved_calls/cost、call_started、calls_charged、result jsonb 可空、revision；同一 request 至多一行 leased（部分唯一索引）。
`tool_wait` 不变量：恰一条 running bind_tool 语句（child NULL、stmt_index=open request）、恰一条 open request、leased attempt ≤1、无 suspended 子等待、无其他 running 语句、repl_exec 已 enter 无 exit。
`v15_next_tool()` 只读：tool_wait+open request+无 leased attempt，按 invoke_id 排序；不改租约不发 IO。`v15_next_runnable`/`v15_claim` 过滤保持正向 `status='runnable'`（若源码是反向过滤，停，见 §6）。

## 3. worker 三函数 + FakeTool

- `v15_begin_tool(invoke, owner, lease)`：require_worker；锁序同 begin_llm（先 invoke 后池）；tool_wait 才行；已有 leased attempt → `P1523`；`n_next>governance_io`（`v15_baseline_max(invoke,'governance_io')`，与 LLM request 的 n 各自计数）→ request exhausted、语句 `V15_TOOL_EXHAUSTED` 非fatal 收束、不插 attempt；池预留 (1,0) 失败 → request failed、`V15_BUDGET_EXHAUSTED` fatal、`v15_io_terminal`、无 leased attempt；成功 → 插 leased attempt（fence=1、call_started=false）、审计 `op=attempt_leased`、返回 proceed+attempt_id/n/tool_name/args/args_digest。
- `v15_mark_tool_started(attempt, fence, owner)`：attempt 行锁校验（leased、fence、owner、未 started、父 invoke 仍 tool_wait、语句仍 running）→ call_started=true；fence 错 `P1501`、余 `P1523`。
- `v15_settle_tool(attempt, fence, owner, result)`：必须 leased+call_started+fence/owner 匹配；他态 `P1502`（迟到结果不写 binding，对齐 D14）、未 started `P1523`；result 键闭集恰 `{"ok":true,"value":<jsonb>}` 或 `{"ok":false}`，坏形状 `P1524` 整笔回滚 attempt 仍 leased；先 `v15_io_pool_release(charge_calls=true, cost_delta=0)` 再 settled/calls_charged/清租约/写 result；不接受 FakeTool 上报 cost；同事务做 §4 送达/失败收束；不调 on_phase、不写新 span 名。
- worker 环（reclaim 之后、next_runnable/claim 之前）：`v15_next_tool` 逐个 → begin **提交** → 非 proceed 下一个 → mark **提交** → `faketool.call(tool_name,args)`（Python 异常收成 `{"ok":false}` 结算，不得逃出循环、不得留 leased 到超时）→ settle **提交**。`faketool` 与 `fakellm` 并列的单注入位，按 tool_name 派发；默认未注册名返回 `{"ok":false}`。
- 崩溃窗口同 LLM：begin 未 mark → reclaim failed 不计 calls；mark 后消失 → unknown 计 calls；二次 settle → `P1502`。

## 4. 失败与送达

- **调度前** reject/求值失败：语句 failed、无 request、同迭代继续、invoke 不终态。
- **成功**：request settled；binding 不存在插 `kind=var`/provenance=delivery/show_in_prompt=true；已存在且 kind=var 更新（恰 1 行否则 `P1527`）；语句 done、迭代 executing、resume_stmt+1、invoke runnable、fence 不变、审计 `op=deliver`；不写 repl_history；同迭代剩余语句继续（可再 bind_tool/bind_invoke）；两次工具间 llm_requests 不增。
- **名字被占**（input/scope/tool）：attempt 仍 settled（已计 calls）、request settled、binding 不改、语句 `V15_DELIVERY_CONFLICT` → 非fatal 收束。
- **ok=false**：request failed、不写 binding、语句 `V15_TOOL_FAILED` → 非fatal 收束。
- **耗尽**：request exhausted、语句 `V15_TOOL_EXHAUSTED`、不计新 calls → 非fatal 收束。
- **非fatal 收束**（复制 deliver_completed 冲突分支写入顺序，码换三新码之一）：skip_after；观测文本=capture+`[v15 exception <CODE>]`；迭代 done/continue；repl_history.repl_exception=v15_io_error；插 observation llm_messages；插 iteration+1 pending；`v15_repl_close_span('repl_exec','failed',fence)`；invoke runnable 清租约不加 fence；审计 `op=tool_failed`（payload 带 code）；不调 finish_exec（不发 repl_exec/complete）。
- **reclaim**：替换后的 `v15_reclaim_expired` 在 LLM 逻辑前并 tool_wait invoke 入锁种子；call_started → release 计 calls/unknown；未开始 → failed 只释放；request 仍 open、invoke 仍 tool_wait；审计 `op=tool_retry`；无工具行时与原函数同态（12 道回归命门）。`v15_io_reclaim_invoke` 替换：tool_wait 或 running bind_tool → `P1523`（禁止打回 pending 丢 request）；余分支字节级保持。

## 5. external 切割 / 错误码 / 回放 / 身份

- 同步 `jaz.tool` 对 external=true 仍 `V15_EXTERNAL_TOOL`；`bind_tool` **仅** external=true；external=false 的 bind_tool → 新码 `V15_TOOL_BINDING`。external=true 的 catalog 行仍要 handler：登记纯函数桩（owner `v15_tool_<name>`、体只抛 V15_EXTERNAL_TOOL、满足全部登记检查），bind_tool 不调用它。
- 新码恰 3 枚（§18 表尾，止于 P1545 共 45 行，P1546–P1548 不分配）：`V15_TOOL_BINDING=P1543`、`V15_TOOL_FAILED=P1544`、`V15_TOOL_EXHAUSTED=P1545`。fence/不可结算复用 P1501/P1502；形状=V15_INVOKE_FORM；未授权=V15_TOOL_UNAUTHORIZED；冲突=P1527；预算=V15_BUDGET_EXHAUSTED。
- 回放裁掉：stage 12 导出/导入见 `bind_tool`/`tool_wait` → `V15_VALUE_INVALID`/P1524（不用 P1542，保 D2 码义）；回放驱动不调 FakeTool；stage 12 计划 Follow-up 加一行。
- 新函数一律 DEFINER/owner v15_owner/search_path=pg_catalog/REVOKE PUBLIC；EXECUTE 只给 v15_worker 的五函数 suspend/begin/mark/settle/next；v15_repl 只得总会失败的 jaz.bind_tool；体内无 SET ROLE。演示角色 `v15_tool_fake_search` 只进 stage 13 种子（NOLOGIN；全局 DROP ROLE 已按 v15_tool_* 前缀清理）；catalog 名 `fake_search`、external=true。
