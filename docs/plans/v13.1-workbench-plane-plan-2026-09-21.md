## 1. 定位与边界

### 1.1 在 v13 版图中的位置

DP1–DP8 是**上下文平面**（`v13-context-on-pg.md`），已终检收口
（`docs/reviews/v13-dp1-8-cross-coverage-final-check-2026-09-21.md`：无缺口无重叠），
但代码树尚未开工（仓库无 `v13/` 目录）。教程 ch9 规划的「超级工作台」
（G6/G7 部分）不在该设计文的 normative 面内——**工作台平面是 v13 版图里
唯一没有实施计划的承重族**。v13.1 补这一块，与用户的定调逐字对应：

| 用户定调 | v13.1 载体 |
|---|---|
| postgres 作为 agent 底座 | DP1 已规划的核心（sessions/events/effects/decisions/thresholds/tools/artifacts/meta + parse/advance/claim/complete + PGMQ 唤醒）。**本 plan 零重建、零旁路**：选台是 decisions 里的行，激活是 thresholds 带上的谓词，工作台是目录维度的外键，执行是 effect，产物是 artifact |
| duckdb 作为数据/代码/文本的超级工作台 | 三条工作台合同行（§1.2），一个 digest 钉死的 bundle 族，每 effect 借出的 fresh `:memory:` 实例（教程 ch9 三层唯一性的兑现，v6/v6.1 纪律移植） |
| jev 判断当前任务启用哪个工作台 | 逐台存在性 Noul（`wb::<name>`）进 `v13_needed_judgments`，经 pg_typesafe 在解析相落 decisions 行，**激活谓词=版本化 thresholds 带**；Jev 只产证据，动作授权独占于 SQL 策略（设计 §6.1 原样适用） |

一句话立场：

> **PG 是唯一的 agent 底座——状态、判断、路由、账本、目录、产物全部是行；
> DuckDB 是按 digest 钉死、按 effect 借出、按 artifacts 进出的超级工作台；
> Jev 只回答「当前任务需要哪台」的证据问题（逐台 Noul），启用与否、谁能看见，
> 全部是 SQL 里的数据与谓词。**

### 1.2 基座决策：三层唯一性 + 「三台两 bundle」

教程 ch9 的架构判断原样继承，并按 v6.1 的 ABI 墙事实收紧：

| 层 | 唯一性 | v13.1 载体 |
|---|---|---|
| **镜像层** | bundle digest | `workbenches.bundle_digest = sha256(canonical manifest)`；worker 启动自检 + 领取时校验，不匹配拒绝（fail-closed，结构化错误信封） |
| **合同层** | 目录行族 | `tools.wb` 外键 → `workbenches` 注册行；选台判断与可见性谓词作用于此层 |
| **实例层** | 每 effect | fresh `:memory:`，毫秒级起停；正确性不依赖任何易失进程状态（工具间只经 artifacts 交换） |

四项裁决（含理由与被拒替代）：

**裁决 1：三个工作台合同行，不是一个进程也不是一棵全局工具树。**
`duck_data`（数据分析：duck SQL over PG 白名单快照）、`duck_code`（代码：
sitting_duck AST 即数据）、`duck_text`（文本：duck_block_utils/markdown 文档块）。
「一个超级工作台」成立于镜像/合同层（教程 ch9 原话），但**选台粒度=工作台行
（域）**：数据/代码/文本是三种语义上可分辨的任务域，逐台 Noul、逐台阈值、
逐台审计。被拒替代：字面一个共享 duck 进程——单写者排队、跨会话状态渗漏
（v6 W4 专测过）、一崩全崩、常驻服务器要人伺候，唯一买到的东西（热缓存）
在合同内部拿不回（温实例已台账化，§7）。

**裁决 2：两 bundle，不是一 bundle——ABI 墙的诚实承载。**
v6.1 实测：DuckDB 一个进程只能装一个精确版本，社区扩展（sitting_duck/
duck_block_utils，面向 released 版构建）与 v6 的 fork dev 构建**不能互载**，
`allow_unsigned_extensions` 不绕过。repo 根 `pyproject.toml` 钉的是 v6 fork
（kernel freeze 纪律，不能动）。因此：

- **bundle A（`duck_data`）**：repo 已有 fork duckdb，**零扩展**（纯分析 SQL），
  handler=`'duck'`——M3 的真执行器 gate 在本仓库离线全绿（嵌入式、确定性、无网络）。
- **bundle B（`duck_code` + `duck_text`）**：released duckdb + 本地预构建社区扩展
  （路径+SHA-256，LOAD 不 INSTALL），handler=`'duck_codex'`，独立 worker 进程
  + 独立 uv 环境（repo 根 pin 不动）。repo 内 gate 跑**合同级**（FakeCodeBench）；
  真扩展集成 = env marker（v6 grammar 先例，§3.4）。

v6.1 的「双平面」结论由此简化为 v13 形态：**两 bundle = 两个 handler，
每个 handler 只是 claim 过滤键 + 一个 worker 进程**（教程 ch8：handler 是
开放词表，新增 handler 零 DDL）。镜像层分离承载 ABI 墙；合同层三行统一
选台；实例层同构。将来 fork 退役/统一后合并 bundle = 改 digest 数据，零结构变更。

**裁决 3：选台是两段式「SQL 预筛 + Jev 终选」的又一次兑现，不是新机制。**
- 确定性预筛（SQL）：`enabled=false` 的工作台不可见（目录纪律原样）；
  bundle 未注册（无 worker 存活信号/digest 缺失）的工作台不进候选。
- 语义判断（Jev）：对预筛后的每个工作台问一个**存在性 Noul**
  （`wb::<name>`：当前任务是否需要该台能力）。**为什么是逐台 Noul 而不是
  全集 Choice**：Choice 必选一，不能表达「数据+代码都要」与「都不要」
  （设计 §6.2 触点 3 砍在线 triage 的同一理由）；逐题 Noul 各自按
  `request_hash` 缓存、逐题阈值路由、永不组合 p 与 1−p（v12 风险规避表）。
- 动作授权（SQL）：激活谓词 = thresholds 带（`signal='wb::<name>'`,
  `action='pass'`, lo=阈值）；**缺省方向=超集**——未答/缺行/无带 ⇒ active
  （能力更多而非更少；方向对齐设计 §6.2 触点 5「低置信/缺失→绑超集」，
  代价只是候选集变大，不是能力丧失）。

**裁决 4：选台层形式上可推导（工作台活跃 ⇔ 其工具被选中），仍然显式建层。**
它买到三样东西：判断成本（tool Choice 的候选 map 缩一个数量级——ch6
「consumes/produces 预筛」的同型收益）、审计（「为什么这个任务开了 DuckDB」
= 一行 decision）、执法点（镜像层 digest 门与 per-台 预算的落点）。
诚实记录：若实测 wb 族判断费用超过其节省（台账触发条件，§7），收窄层
可整体退役回全目录 Choice——机制上只是 needed 函数换体，无结构债务。

### 1.4 不变量（本 plan 全程有效，违反即设计背离）

0. **继承**：教程 ch15 九条不变量 + DP1 §1.4 七条不变量，逐字有效。
1. **镜像是部署单元**：worker 本地 bundle digest ≠ 注册行当前值 → 拒绝启动/
   拒领，fail-closed 结构化错误（`WB_BUNDLE_MISMATCH`），不静默降级、不换台执行。
2. **选台是证据不是授权**（设计 §6.1 的原样适用）：Jev 只产不可变、带版本的
   decisions 行；激活谓词=版本化 thresholds 带；缺省方向=超集（能力单调
   向多，退化只花 token 不丢能力）；Jev 不决定预算、不直接建 effect、
   不组合置信度。
3. **实例归 effect，状态归 PG**：duck 实例每 effect 一次（fresh `:memory:`）；
   工具间只经 artifacts 交换（ch7 纪律）；正确性不依赖任何易失进程状态。
   温实例不进 v13.1（台账，§7）。
4. **duck 方言只进校验器**：模型产出的 duck SQL 必须过只读 validator
   （非 SELECT/DML/DDL/多语句/注释拒——v6 W7 移植）；连接打开后立即关
   auto_install/auto_load/external_access 且**永不** `INSTALL`/加载 `postgres`
   扩展（v6 边界逐字）；表白名单/行上限/字节上限是目录行数据，不是代码。
5. **数据面只读**：v13.1 全部 duck 工具 `mutating=false`——lease 过期恒回
   `ready` 重放（幂等：fresh 实例 + at-least-once 执行 + settle 恰一次）；
   写能力（文件写回/AST 改写落盘）= 台账项（v6.1 B005 需显式批准）。
6. **不建第二真相源/第二 IO 通道**（设计 §8 元原则）：duck 侧只有可从
   artifacts/PG 重建的派生物；duck 执行器 IO 只发生在 worker（effect 纪律），
   库内 IO 例外有且仅有 pg_typesafe 纯判断（wb Noul 属于此例外）。

### 3.3 M3 `v13/duckdata/` —— 数据工作台执行器（真 fork duckdb，repo 内离线全绿）


## 8. 风险与开放问题

1. **sitting_duck/duck_block_utils 的本地构建与分发**：社区扩展需预构建
   （路径+SHA-256 进 manifest）。需一份 runbook（构建步骤/存放路径/升级
   演练）；AGPL 无关（均 MIT），但分发审查照 stannum 先例记录。
2. **双 duckdb 环境的依赖管理**：repo 根 pin fork（v6 纪律）+ duck_codex
   独立 uv 环境的具体形态（嵌套 pyproject / 兄弟目录 / constraint 文件）
   实施期定，M4 前收口；gate 不依赖其具体形态（marker 制）。
3. **wb 问的 CJK 面**：能力卡与 question ASCII（DDL CHECK 强制），中文
   任务文案只进 state——Jev CJK 短板纪律原样；低置信被缺省超集兜底。
   阈值 0.60 是 shadow seed，本地校准（三类任务 fixture 集）后才收紧。
4. **thresholds action='pass' 语义复用**：wb 激活带借 route 词表的 'pass'
   ——语义上是「可激活」非「路由放行」。若认为词表污染，替代=扩 action
   词表（改 DP1 DDL，代价大）或 v13_policies 载体（丢探针键闭环，需补键）。
   本 plan 裁决用 'pass' + 注释；**呈报设计侧**（v3 erratum 候选，不阻断）。
5. **快照重放的新鲜性**：at-least-once 重放可能读到更新的 PG 数据（非
   mutating 可接受）；若未来需要「重放字节一致」，预案=effect request 冻结
   各源 content_hash（快照前先哈希）——成本高，触发条件=审计需求真实出现。
6. **`v13_canonical_state` 的第三处换体**：tools 摘要扩为 tools×workbenches
   联合摘要——与 DP2 分片哈希投影声明有交互（若 DP2 先行且声明了投影面，
   wb 摘要必须并入其声明，否则「未声明字段进请求」执法面击穿）。实施时
   对照 DP2 加载态；已列 §1.3 DP2 行。
7. **本 plan 未过 L4**：按 DP1 先例（12 轮修复台账），实施前应走多轮
   L4 双通道评审；尤其 §3.2 换体的单快照物化细节与 §3.1 触发器的
