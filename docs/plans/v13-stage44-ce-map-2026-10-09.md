## 1. Summary

stage 44 是尾部追加，不是运行时重构。在 `SQL_LOAD_ORDER` 与 `STAGE_THROUGH` 末尾加上 `ce_map` / 44，新增零参 `public.v13_ce_map()`。函数体只有一条静态 jsonb `SELECT`。父计划要求 E2 只做静态对照；oracle 把对照收成一份不查询、不执行的闭集。`v13_advance`、驱动器、stage 43 分类函数都没有这个扩展点，所以不改它们。

**声称句（README、矩阵 #90 使用这一段，不准加宽）：** stage 44 在连续装载 1–43 之后提供 `public.v13_ce_map()`。它是 `LANGUAGE sql`、`STABLE`、`SECURITY INVOKER`、非 `STRICT` 的零参函数，返回 oracle 那一份静态 jsonb。`map` 把父计划 E2 的 CE 原语指到既有 PG 签名，或把 `shutdown` 写成字符串 `unsupported`。调用它不执行这些签名，不读 `external_executor`，不是 CE 会话运行时，不交付 stage 45。

gate 另外分开确认：六个被映射签名还在，两列 effect 租约字段还在且类型未漂移，`v13_ce_shutdown` 不存在。映射函数不查询控制状态，不产生控制写入。签名或列还在，不证明 CE 会话运行时、task lease、进程恢复或 stage 42 的启动路径。

### 3.2 `v13_ce_map()` 合同

一个 PostgreSQL 函数。不新增类型、表、辅助函数、政策行或 `tools` 行。文件只有 `v13/ce_map/v13_ce_map.sql`。调用方只有测试里的 `SELECT`。不进入 `ALLOWED_CONTROL_SQL`，不进入 `tools`，`v13_advance` 不调用它。

```text
public.v13_ce_map() → jsonb
```

| 属性 | 固定设计 |
|---|---|
| 语言 | `sql`。体只有一条 `SELECT '<§3.3 jsonb>'::jsonb`。不用 plpgsql，因为没有必须按顺序短路的语句 |
| 易变性 | `STABLE`。不写成 `IMMUTABLE` |
| 安全 | 默认 `SECURITY INVOKER`。源文件不得出现 `SECURITY DEFINER` |
| `STRICT` | 不写。零参 `STRICT` 不会改变调用结果，但 `proisstrict` 必须为 false |
| NULL | 无参数。不声明 `STRICT`，也不写 `CALLED ON NULL INPUT` |
| `search_path` | 函数 `SET search_path = pg_catalog, public` |
| 属主 | 安装者，等于 `current_user`。不 `ALTER OWNER`，不建角色，不转给 `v13_spawn_owner` |
| EXECUTE | `REVOKE` FROM `PUBLIC`；只 `GRANT` TO `v13_route`。不授 `v13_recall`、`v13_resolve`、`v13_spawn_owner` |
| 执行 | 当前语句内同步返回。无 `COMMIT`、无动态 `EXECUTE`、无 `EXCEPTION`、无 `IF NOT EXISTS` |
| 写入 | 零。体无 `INSERT` / `UPDATE` / `DELETE`，无 `FROM` |
| 读 | 不读 `pg_proc`、`sessions`、`v13_policies`、`effects`，不调用映射函数 |

选择单条 SQL 而不是在函数里 `to_regprocedure` 的理由：oracle 规定体是字面量；签名是否还在由测试证明。函数内查询会把静态映射变成目录读取。

安装事务顺序固定，语句之间不插入别的语句：

1. `BEGIN`；
2. `CREATE FUNCTION`（不是 `CREATE OR REPLACE`，不是 `IF NOT EXISTS`）；
3. `REVOKE EXECUTE ON FUNCTION public.v13_ce_map() FROM PUBLIC`；
4. `GRANT EXECUTE ON FUNCTION public.v13_ce_map() TO v13_route`；
5. 函数体外英文 `COMMENT`；
6. `COMMIT`。

无 `INSERT`、无 `DROP`、无 `ALTER`。函数已存在则整笔失败回滚，不做 upsert，不接管已有对象。`pg_get_functiondef` 会印出 `CREATE OR REPLACE FUNCTION public.v13_ce_map()`。这是目录显示，不是源文件里的语句，不在禁止令牌内。源文件不得出现这串针对 `v13_ce_map` 的 `CREATE OR REPLACE`。

`COMMENT` 逐字为，含末尾句号：

```text
STABLE read; returns the closed static CE primitive map; does not execute or query; not a tools row; does not raise.
```

注释不写四个工具名，不写 `v13_agentctl_answer`，不写 `v13_external_exec_classify`，不写 `external_executor`。`does not raise` 指正常零参调用不 RAISE，不是函数体内的异常处理器。SQL 函数也不写 `EXCEPTION`。

函数体用 `$fn$`。jsonb 文本放在 SQL 单引号字符串里。§3.3 的值没有单引号、没有 `$$`、没有 `$fn$`。可以排版 SQL 空白；字符串内部不得改。测试独立维护预期 jsonb，不从生产 SQL 抽取预期，避免实现与测试一起漂移。

数据流：测试 `SELECT` → 规划器执行那条常量 `SELECT` → 返回 jsonb。没有监听者，没有第二份缓存，没有通知。同一后端上连续两次调用返回 jsonb 相等。

`search_path` 的比较沿 `v13_spawn_writer_ok` 已有写法：`cardinality(proconfig) = 1` 且 `replace(proconfig[1], ' ', '') = 'search_path=pg_catalog,public'`（`v13/agentctl_verbs/v13_agentctl_verbs.sql:34-35`）。44 不改那个函数，只在测试里用同一比较。

安装 SQL 仍然只 `GRANT` 给 `v13_route`，不 `GRANT` 给安装者。`REVOKE` / `GRANT` 会把 `proacl` 从 `acldefault` 物化出来，属主的 `EXECUTE` 行会留在存储的 ACL 里，不是另一条授权语句。仓库证据：`v13/acl/test_acl.py:175-183` 的 `acl_of` 用 `aclexplode`；`:349-352` 对已 `REVOKE`/`GRANT` 的函数要求 grantee 集合含属主。那些函数还 `GRANT` 给了 `v13_spawn_owner`（`v13/acl/v13_acl.sql:475-481`），44 不复制这条。因此 `cmap_execute_grantees_closed` 的 `EXECUTE` grantee 集合等于 `{current_user, v13_route}`。

### 3.5 零写与禁止令牌扫描

零写分两段，都在同一条连接上，每表单独断言，不合并成一个总数：
