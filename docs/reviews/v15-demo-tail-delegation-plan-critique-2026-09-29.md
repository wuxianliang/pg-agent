## 3. Under-specified in both

**`finish_length` profile.** `max_output_tokens` is a legal llm key and `complete` sends it as `max_tokens` (`deepseek.py:333-335`). `v15_register_profile` is `INSERT` (`v15/config/v15_config.sql:371`). Reusing `FLASH_PROFILE` raises a primary-key error. A new profile that open does not reference is unused: suspend resolves the **parent scope** (`v15/tree/v15_tree.sql:442`). Either `v15_update_profile` on the demo database's existing flash profile and keep `FLASH_SCOPE`, or register a new profile **and** a new scope and pass that scope to `open_root`. "另注册 profile" alone does neither.

**Real base URL.** Keyless command unsets `OPENAI_API_URI`. The M2 command does not. Constructor prefers that variable over `_DEFAULT_BASE`. An https non-DeepSeek URI passes preflight (`endpoint_rejected` is only scheme/hostname) and `complete` bills the wrong host. P classifies URL mistakes as operator `provider_rejected` after the fact; it never says the real entry must pin or clear the override.

**Gate-run damage order.** Covered above. The failure-path stdout currently says only that `DROP ROLE` will fail.

## 4. Absent from both

`v15_loop_compose_inputs` renders `b.value::text` (`v15/loop/v15_loop.sql:82-99`). The model sees `hops: 3` and `role: "root"` / `note: "<quoted>"`, not raw text. `NOTE_V1` has no internal quotes, so a model that copies the JSON string contents still matches. A model that stores the quote characters fails jsonb equality (`relay_value_mismatch` / `mission_not_forwarded`) while `tail_ok` can still hold. Fake scripts bypass this because they embed the value themselves. If relay on the real path matters, the note has to say the rendered quotes are syntax, not part of the value. That does not change the `tail_ok` milestone.

No second writer, cancel, or replay gap beyond what P §3.8 already states. `KeyboardInterrupt` leave-the-db is the right failure behavior. Do not add a repair worker.
