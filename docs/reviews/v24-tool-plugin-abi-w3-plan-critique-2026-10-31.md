# W3 registry/transport plan critique — 2026-10-31

Scope is limited to `registry.py` and line-JSON v2. Lane 2 of `prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md` is the preservation baseline. This is a plan critique, not an implementation or gate result; only targeted source/vector probes were run.

## 1. Lane-2 implementation content lost or weakened

1. **Frozen `output_schema` write-back was dropped.** Lane 2 writes back `descriptor`, `output_schema`, and both closures (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:620`); the plan writes back only `descriptor` and closures (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:304`). In **Component design → `ApprovedTool.__post_init__`, v2 branch**, also `object.__setattr__(self, "output_schema", frozen["tool"]["output_schema"])`; otherwise an equal but caller-mutable schema remains in a supposedly frozen approval object.
2. **Safe version probing regressed to indexing.** Lane 2 uses `descriptor.get("v")` (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:618`), but the plan uses `descriptor["v"]` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:302`). In the same `ApprovedTool` section, use `v = descriptor.get("v")`; a missing `v` must produce `invalid_descriptor`, not leak `KeyError` outside D12.
3. **Two exact `match_tool` predicates were generalized away.** Lane 2 rejects a non-string `key` as `pin_key_mismatch` and lowercases the pin digest (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:704-707`). The plan's six-step text omits both (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:359`). Restore `not isinstance(key, str)` in step 2 and `pin["descriptor_digest"].lower()` in the digest comparison in **Registry union / `match_tool`**.
4. **Manifest cardinality is no longer checked at the manifest boundary.** Lane 2 requires `provides` to contain 1..16 objects before descriptor processing (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:987-993`); the plan checks only `list` at `from_manifest` and defers cardinality to `ApprovedPlugin` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:327,345-349`). Add an early length check to **D2 / `from_manifest` step 2**, with `manifest_invalid` for malformed manifest shape; retain `tools_invalid` for direct `ApprovedPlugin` construction. This also removes the empty-list ambiguity in the “all non-2” version branch.
5. **The v2 process-error reason surface disappeared.** Lane 2 explicitly includes `spawn_failed` and `process_spec_invalid` (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:1341-1355`), while the plan's `run()` paragraph covers only post-result classification (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:401`). In **Component design → `line_json.run`**, specify the existing v1 mappings: `_spec_v2` `AttributeError`/`ProcessError` → `LineJsonPreflight("process_spec_invalid")`; `run_process` `ProcessError` → `LineJsonPreflight("spawn_failed")`, both before an `Invocation` (`v24/host/line_json.py:160-170`).
6. **Closure acceptance was reduced to presence/identity checks.** Lane 2 requires legal and illegal values to exercise the compiled validators (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:1621`); the plan tests equality, replacement, and v1 `None`, but no v2 validator behavior (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:178,437`). Add valid/invalid parameter and output probes, with `InstanceError` on invalid instances, to **`test_registry.py` case 17 / D8 acceptance** (`v24/host/tool_schema.py:365-378`).

## 2. Under-specified seams and contradictions

1. **D12 arithmetic is correct, but “closed 14-token construction set” is not.** There are exactly eight new plus six reused tokens, and the reused six are exactly `invalid_descriptor`, `descriptor_key_mismatch`, `renderer_not_approved`, `renderer_digest_mismatch`, `mixed_descriptor_versions`, `timeout_exceeds_cap` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:210-223`). However, `_hex64` and descriptor-digest mismatch retain prose, and `ApprovedPlugin` deliberately reuses v1 process-field prose (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:301,306,325`), contradicting the universal wording at `:366-367`. Rename it the **14-token v2-specific set plus explicitly enumerated legacy prose failures**, or normalize every v2 construction failure; do not claim total closure as written.
2. **The `ApprovedTool` dataclass syntax is valid.** `field(hash=False)` supplies no default, so `descriptor` and `output_schema` remain required fields and may precede/follow the other required fields exactly as shown; only the two `init=False` closures have defaults (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:286-296`). No `default=None` should be added to the required fields.
3. **The frozen manifest digest reproduces, but the gate's input form and general byte semantics need pinning.** The vector stores semantic `input` plus canonical `expected_hex` (`v24/s13/vectors/manifest_adapter_v2.json:210-215`). A direct probe confirmed `compact_json(input) == bytes.fromhex(expected_hex)`, length 4745, and both SHA-256 values equal `0ad584415af8743045dd12275a54fa2f43a65395fc8669753416688c9c3e3db5`. Thus **Done-when #2 / registry case 3** should explicitly pass either `case["input"]` or those exact expected bytes—not the vector file's source bytes (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:25,423`). For other byte strings, the plan's raw-byte hash (`:344-350`) differs from lane 2's canonical-for-all rule (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:1007-1015`), though it agrees with design `sha256(manifest_bytes)` (`docs/designs/v24-tool-plugin-abi-v1-2026-10-30.md:520-525`). State this divergence and define `str` raw bytes as UTF-8; the current text defines raw bytes only for `bytes` and `dict`.
4. **D14 does not implement Appendix C.2 in the stated order.** `strict_loads` rejects floats and unsafe integers before shape checks (`v24/host/canonical.py:230-250`; plan step 6 at `docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:395`), so the later `compact_json` probe at `:398` cannot return `invalid_tool_output` for those raw-frame values. Cycles cannot arrive in `bytes` at all. This contradicts C.2's syntactically-valid-success rule (`docs/designs/v24-tool-plugin-abi-v1-2026-10-30.md:1195-1200`) and makes D14's two new tests (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:256,451`) impossible as specified. Either add a location-aware fallback for numeric-domain errors in a valid invoke success `value`, or withdraw D14 and clarify C.2; do not merely reorder `compact_json` after `strict_loads`.
5. **The existing 55 rows do not resolve D14.** They contain `NaN`/`Infinity`, which C.2 explicitly keeps as `bad_frame`, and safe integer/generic values, but no finite float or unsafe integer success `value` (`v24/s13/vectors/frames_v2.json:337-356,407-439`; `docs/designs/v24-tool-plugin-abi-v1-2026-10-30.md:1200`). Therefore there is no direct 55-row conflict today; the conflict is between D14's added expectations and its parser ordering. Any fallback must preserve the `nan`/`infinity` rows.
6. **The two timeout bounds can coexist, but §3.4 is not the sole evidence.** Per-tool `T` is constrained by `1 <= T <= C <= 25000` (`docs/designs/v24-tool-plugin-abi-v1-2026-10-30.md:419-429`), and descriptor validation independently caps v2 tool timeout at 25000 (`v24/host/descriptor.py:53-55`). The `(0,300000]` bound is the generic/v1/lifecycle and process bound (`v24/host/registry.py:117-119`; `v24/host/process_io.py:74-77`); design §3.4 gives lifecycle operations the adapter timeout but no separate upper bound (`docs/designs/v24-tool-plugin-abi-v1-2026-10-30.md:429`). In **Component design → `ApprovedTool` shape step 1 / `ApprovedPlugin` step 6 and O4**, state that the wider bound accommodates v1 synthetic tools and lifecycle operations, while v2 tool timeout is narrowed by descriptor consistency and the plugin cap.
7. **`replace(descriptor=…)` is not generally a viable acceptance probe.** The plan requires digest equality and descriptor/timeout/render/output consistency (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:304-306`), yet D8 and case 17 promise descriptor-only replacement succeeds (`:178,437`). Change the probe to replace all derived fields consistently, or replace an unrelated field and verify recompilation; descriptor-only replacement must fail when the derived values change.

## 3. Corrections supported by code or required scope

1. **“Five `match_tool` failures” is arithmetically wrong.** Done-when #3 says five (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:26`), while the authoritative test lists six (`:433`) and lane 2 also lists six (`prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:1391`). Change **Done-when #3** to six.
2. **“`from_manifest` does not touch the filesystem” is too broad.** The plan itself requires `workspace_root` `realpath`/`isdir` checks (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:329`), and shared process validation requires an existing absolute `cwd` (`v24/host/registry.py:103-104`). Correct D2 and the `from_manifest` boundary (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:120,353`) to “does not read artifact bytes or execute the artifact; path metadata checks still occur.”

## 4. Failure/lifecycle behavior still omitted by both plan and export

1. **`run()` builder-exception behavior is unspecified.** Add to **`line_json.run`** that a `LineJsonPreflight` from `build_frame_v2` propagates unchanged, with zero `run_process` calls and no `Invocation`/started receipt; do not catch it as `spawn_failed` or convert it to unknown. This matches the existing v1 placement outside the process `try` (`v24/host/line_json.py:152-170`) and needs a gate assertion alongside the five builder preflights.
2. **The required `language` argument is absent from both signatures.** `from_manifest` later calls `adapter_declaration_digest(language)` and must populate `ApprovedPlugin.language` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:321,348`; `v24/host/registry.py:68`), but D2's signature has no `language` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:112`; same omission at `prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:961-977`). Add required keyword-only `language` to **D2 and `from_manifest`** before deriving the declaration digest.
3. **`from_descriptor` can leak pre-validation digest failures.** Both texts derive descriptor fields before the constructor's `validate_descriptor` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:304,308`; `prompt-exports/oracle-plan-2026-10-31-012139-w3-deep-plan-registr-5952.md:624`), but `descriptor_digest`/`pg_jsonb_text` can raise `TypeError`, encoding errors, or recursion errors on malformed Python objects (`v24/host/canonical.py:79-109`). In **`ApprovedTool.from_descriptor`**, validate before derivation or explicitly normalize derivation failures into the D12 descriptor reasons; add missing-`v`, cyclic, and non-JSON-value probes.
4. **The two suggested registry examples are already covered, not omissions.** Non-list `provides` maps to `manifest_invalid` (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:345`), and duplicate `adapter_id` is rejected by the union registry's unchanged logic and case 15 (`:357,435`; existing implementation at `v24/host/registry.py:194-195`). Do not invent a new per-`ApprovedPlugin` duplicate-ID check.

## 5. Decisions that affect implementation order

1. **Resolve C.2/D14 before W3-4, not at gate time.** A location-aware numeric-domain fallback changes the v2 parser architecture and test fixtures; withdrawing D14 instead requires a design clarification and repin. Either choice moves design work ahead of transport implementation rather than leaving all normative edits to W3-5 (`docs/plans/v24-tool-plugin-abi-w3-registry-transport-2026-10-31.md:499-500`).
2. **Choose raw-byte versus canonical-for-all manifest identity before W3-2.** The frozen vector cannot distinguish them, but noncanonical `bytes`/`str` inputs can. Restoring lane 2 requires changing the digest algorithm and design wording; retaining raw bytes requires explicit UTF-8 `str` handling and additional noncanonical-input tests. This decision must precede freezing the registry API and its gate, not follow the planned design repin.
