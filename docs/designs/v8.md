# Postgres-Native Agent · Native 版

> 独立新稿，不改 V1、修正案、两份中间 v2、`v2最终版.md` 及既有附录。
>
> 本版收录：SQL 拥有循环、无状态 worker、Cordis 法则、zcordis-pgembed 的核（yield 五件套 / 目录列 / 四缝 / 第三态）、以及 **dsh-compat 作为第二实现**。
>
> 双模式的目的不是两套产品，而是同一份行为合同的两种实现。
> **未来插件实现可以不一致，行为必须一致。漂移是 bug。**

---

## 0. 一句话宪法

- **Native**：默认。循环在 SQL（yield-loop）。插件是目录行 + `apply` 只登记 + handler。TS / Python / Swift / SQL 四运行时平等。不实现 Fiber / `next()` / isolate 子树。
- **dsh-compat**：可选会话 driver。官方 Cordis + 官方 `dsh-agent-loop` 跑在 Node host 里，经 persistence-pg / storage-pg 把同一份 `session_events` 写进同一库。用来跑社区 bundle，并作为行为对照面。
- **同一 `session_id` 只有一个 driver。** 两种实现可以同时存在于集群，不能同时认领一行会话。
- **可移植插件** = 在两个 driver 上通过同一套 fixture 的插件。只在一边能跑的，标注 `compat-only` 或 `native-only`，不准默默混装。

## 1. 双模式：实现可以分叉，行为不能

### 1.1 什么叫「实现不一致」

同一能力允许三套代码：

| 实现 | 写法 | 跑在哪 |
|---|---|---|
| compat | DSH `apply(ctx)` + `ctx.on(..., next)` + `defineTool` | `dsh-compat` host，官方 loop |
| native 应用语言 | 同一 `name/inject/apply` + `define_tool`，handler 返回补丁而非 `next()` | TS / Py / Swift worker |
| native SQL | `COMMENT ON FUNCTION` 的 `cordis_plugin` JSON，或 `register_host_plugin` | `locus=sql`，`step_once` / fold 函数 |

这三套 **不必** 源码级相同。compat 可以继续洋葱；native 必须是投票 + 文档化折叠代数。

### 1.2 什么叫「行为一致」

两边写的是同一组表，观测的是同一组不变量。可移植插件在两个 driver 上，对同一 fixture 会话必须得到：

1. 相同的 `session_events` 类型序列（允许时间戳和 `assistant/chunk` 密度不同，见 1.3）
2. 相同的工具 canonical JSON（`execute` 返回值）和 `output.render` 产物
3. `agent_inject` / reminder 类注入 **不** 把空闲会话打成新 turn
4. reject 之后没有新的 `llm` / `assistant/message`
5. compact 锁 `compaction/start…end` 期间不派 LLM
6. 取消后未派出的工具是 `ABORTED_BEFORE_DISPATCH`；已流出前缀写成 `interrupted`
7. 卸载后下一次 assemble 不再看见该工具，没有悬空 handler
8. fork 时 `inherited_event_count` 切点相同
9. 同一 `(session_id, step_name)` 的 LLM 调用使用同一幂等键，重试不双计费

过不了这 9 条的插件，不能标「可移植」。

### 1.3 允许的实现差（必须写进插件 README）

| 允许不同 | 可移植插件因此不能依赖 |
|---|---|
| compat 可写 `assistant/chunk`；native 默认可批成 `turn/delta` 或只写最终 `assistant/message` | 逐 token 听者 |
| compat 用 `next()` 包裹；native 用 priority 折叠 | 「我改了下游 listener 的返回对象」 |
| compat 的 Fiber isolate；native 的 slice + grant | 活对象身份、进程内 Map |
| compat 进程退出丢失 pending plan-mode（DSH 已有的洞）；native 行还在 | 「重启后堆状态还在」 |
| 宿主语言 / 队列实现 | 直连业务表、私有调度器 |

UI 流式走带外通道（NOTIFY / gateway），不进行为合同。合同只看落盘事件和工具 JSON。

### 1.4 为什么要双模式

- **compat** 保证：今天的社区 DSH bundle 有地方跑；官方 loop 的行为是一份活的对照实现。
- **native** 保证：loop 不写三遍、三语言平等、崩溃可恢复、基因组可进化。
- **两边对同一套 fixture 打分** 保证：以后用 SQL 或 Swift 重写某个 DSH 插件时，不是「看起来像」，而是行为合同没破。

没有 compat，native 的折叠代数没有对照面，重写会静默漂。没有 native，三语言平等和 RSI 基因组落不到默认路径上。两个都要，且必须被同一份 suite 拴住。

## 2. Native 核（收录 zcordis-pgembed）

### 2.1 三态

| 态 | 表 | 权威？ |
|---|---|---|
| log | `session_events`（及 compat 写入的同一张） | 历史唯一真相 |
| projection | `projections`、assemble 用的 fold 视图 | 派生，可重建 |
| workspace | grant 范围内的工作区（worktree、未提交编辑、REPL 变量） | run 私有执行态，**不是历史**。结束可扔，需要留下的先 append 进 log |

worker「无状态」= **无会话真相**。可以握着：PG 连接、API 密钥、进行中的 HTTP、当前 claim 的 workspace。崩溃后 workspace 按政策重建或丢弃；log 必须还在。

### 2.2 循环：一份 yield-loop，写在 SQL

会话行上 `driver = 'native'`。核动词（与 pg_cordis 五件套对齐，不另起一套词）：

```text
claim(session_id, worker_id) -> fence
checkpoint(fence, events[])
yield(fence)                  -- 让出，下一步可被另一 worker 认领
wait(fence, event_key)
sleep(fence, until)
complete(fence) / fail(fence, cause)
heartbeat(fence)
release_stale()
```

一步默认边界：**一次 LLM + 本步工具**。不是逐 token，不是整段 turn 钉死一条连接。

```text
claim
  → 四缝：recall / fold / env_read / authorize_tool
  → 阶段：compact锁? → hook 投票 → assemble → llm
  → tools（并行度与 exclusive 由 tick 计数器管）
  → checkpoint
  → yield | wait | complete | fail
```

`agent_tick` 是这些动词的编排函数，不是第三套状态机。  
**禁止第二队列。** `jobs`（或等价的一张任务表）就是 effect 总线。不要再套一层 pgmq/Absurd 当第二个主人。Absurd 的分区函数可以偷来维护这张表，不能再开一个「执行引擎」。

LLM 幂等键在库内算：`provider_key = md5(session_id || '/' || step_name)`，与哪只 worker、第几次认领无关。

子 run 一律 `enqueue`（新 `session_id` + 继承切点）。一步之内的普通 tool 不是 spawn。

### 2.3 四缝（唯一合法 IO）

插件和 worker 不准直选业务表。只许走：

| 缝 | 作用 |
|---|---|
| `recall` | 按 slice 已签发的 named corpus 检索 |
| `fold` | 按 slice 作用域折 log → 模型可见消息 |
| `env_read` | 读 grant 范围内的 workspace |
| `tool_dispatch` | 只返回「当前 slice 被授权且已登记」的工具描述，不执行 |

缺任一缝，feature closed（失败封闭）。这是 isolate 的结果面：可查询、可回滚，不是 Fiber 子树。

RLS 继续按 `workspace_id` 做租户隔离。slice + grant 做 *agent 内* 隔离。两层不是二选一。

### 2.4 插件目录

```text
plugin_catalog
  identity            -- 稳定逻辑名（跨 driver 相同）
  version
  locus               -- sql | ts | python | swift | compat
  invocation          -- queue | session_select | host_tool
  effect_class        -- read_only | transactional | external
  retry_class         -- replayable | idempotent | non_retryable
  required_grants[]
  inject jsonb        -- 服务 key 列表
  provide jsonb
  entry               -- SQL regprocedure 或模块入口
  portability         -- portable | native-only | compat-only
```

- SQL 插件：`COMMENT ON FUNCTION` 含 `cordis_plugin` JSON，或等价登记函数。
- 应用语言插件：导出 `name / inject / Config / apply`，`apply` 只登记。
- `refresh_plugins()`：扫描源、全体校验、通过才 DELETE + 重填。失败则旧目录不动。这是 RSI 的世代边界。

activator 按 `inject` 偏序把 `plugins.state` 从 pending → active。provide 不齐不能 active。

### 2.5 Native 作者法则（Cordis 运行时已弃，法则保留）

```text
name, inject, Config?, apply(ctx, config) -> disposer | None
```

`ctx` 只许：`tools.register(define_tool(...))`、`systemPrompt.section`、`on(event, handler)`（登记 hook 投票）、`get(key)`。  
禁止：直连业务表、在 `apply` 里 `while claim()`、`waterfall(next)`、进程内 `Map<Agent, …>` 当权威。

`define_tool` 字段与 DSH `DefineToolOptions` 对齐：`name, description, parameters, output.{schema,render}, execute, timeoutMs?, isConcurrencySafe?`。

Hook 不包 `next()`。返回封闭代数，由 tick 折：

```text
pre_step:  任一 reject → 拒绝；否则 enter，messages 按 priority 拼接
post_tool: 任一 block → 阻断；additionalContexts 按序 prepend
缺席 / 超时 = pass
纯数据 hook 做成 SQL 函数，不入队
```

进程内 LIFO 只撤 **本进程** 登记。权威是目录行。崩溃后栈没了，下一只同类 worker 重新 `apply`。

20 行 poller 属于运行时，不属于插件：

```text
LISTEN work_wake
apply_all_active_plugins()
loop:
    task = claim(...)
    dispatch(task)          -- 只调已登记 handler
    checkpoint / complete
```

谁把业务写进 poller，谁拆掉法则。

## 3. dsh-compat（保留，并升格为对照面）

### 3.1 形态

Node host 内嵌官方 Cordis + `@deepseek-ai/dsh-session|tools|system-prompt|agent|agent-loop|llm`。profile overlay 只替换 provider：

```yaml
- delete:
    name: '@deepseek-ai/dsh-session-persistence-jsonl'
- insert:
    - name: '@pgagent/dsh-session-persistence-pg'
    - name: '@pgagent/dsh-session-projection-cache-pg'
    - name: '@pgagent/dsh-storage-pg'
    - name: '@pgagent/tool-catalog-publisher'
```

persistence-pg **复用官方 PersistenceCoordinator**，只实现 stored reads / append / repair / listing。storage-pg 过官方 `tests/contract.ts`。

对 DSH 插件，这就是 DSH：真 `ctx`、真 `next()`、真 `defineTool`、真 isolate。对本系统，它只是一个经 SQL 协议连库的 worker，`sessions.driver = 'dsh-compat'`。

路径 C 仍在：官方 `deepseek-harness-sdk` 经 stdio JSON-RPC 驱动这个 host。它是客户端，不是第三条循环。

### 3.2 分级（对社区包）

| 级 | 判定 | 处置 |
|---|---|---|
| T0 | 只经 persistence / storageDomain / settings；事件只收发 | 零改，挂 compat |
| T1 | config 里有文件路径 | 改配置 |
| T2 | 直接 `node:fs` | 改走 storageDomain |
| T3 | pty / LSP / spawn | 留在 host，状态仍入库 |
| T4 | 自己实现 Persistence、Web UI slots | 我们替换或排除 |

T0/T1 若还声称「可移植到 native」，必须另交 1.2 的 suite，不能只用「在 compat 上能跑」过关。

### 3.3 compat 对行为合同的义务

compat host 必须：

- 只经 `append_events` / persistence facade 写 `session_events`，禁止另做一份 JSONL 当真相
- 把 `ctx.tools.register` 同步进 `tool_catalog`（`locus=compat`）
- `agent.inject` 走「append 且不 `work_wake`」
- 崩溃恢复对齐 DSH `load()`：合成 `tool/result` + `turn/end {interrupted}`，已提交事件不改
- 认领会话时检查 `driver='dsh-compat'` 且 fence 匹配

允许它多写 `assistant/chunk`。可移植 suite 比较时，把 chunk 折叠进所属 `assistant/message` 再比类型序列。

## 4. 可移植插件怎么写（给未来作者）

目标：一份逻辑，两边行为相同。推荐顺序：

1. **先写行为契约**：事件序列、工具 JSON、inject 是否唤醒、失败码。放进 `tests/behavior/<identity>.fixture.json`。
2. **native 实现**：`define_tool` / hook 投票 / 或 SQL 函数。过 native suite。
3. **compat 实现**（若需要社区形态）：DSH `apply` + `next()`，内部只做与 native 相同的补丁语义（reject / inject / block），不要依赖「改下游返回对象」。过同一 fixture。
4. 目录行 `portability=portable`，`identity` 两边相同。

不要：在 native 里仿 `next()` 以便「更像 DSH」；在 compat 里把状态只放进 `Map<Agent>` 还声称可移植。

RSI 只进化 native 基因组（目录版本 + `refresh_plugins` + fork-eval-rollback）。compat 不参与自动进化；它是对照面和生态通道。进化出来的 portable 插件，仍要用 fixture 在 compat 上回归一次，防止折叠代数和官方洋葱在结果上分手。

## 5. 数据面要点（与修正案一致，不回归）

- 两套时钟：会话 `(session_id, seq)`；KV 独立 `kv_rev`。禁止共享 `global_rev`。
- `session_events` 含 `surface_op` / `source_event_seqs` / `ignorable`；`UNIQUE(session_id, seq)`。
- `kv_current` + `kv_history` + `leases`（fence + `lease_until`）。
- `sessions.driver ∈ {native, dsh-compat}`，同一时刻一个 loop 持有者。
- 唤醒：固定频道 `session_wake` / `kv_wake` / `work_wake`，payload 只带 id；断线按 seq/rev 补拉。禁止 demo 那把全局 advisory lock 当协议。
- worker 无 `session_events` 直接 DML。
- 记忆仍是显式 `memories` + 三个工具，不靠社区私有 SQLite 当真相。

## 6. Conformance（两个 driver 各跑一遍）

共享 fixture，断言相同（chunk 先折叠）：

1. `greet`：catalog 出现；execute / render 分离；卸载后消失。
2. 连续 `user/message` + `surface_op=append`，seq 无洞。
3. 杀进程后 `load`/`repair` 提交合成 closer，已提交事件不被改；`inspect` 不提交。
4. inject / reminder：下一次 request 看得到，且不新开 turn。
5. reject：无后续 LLM 行。
6. compact 锁期间无 LLM。
7. 超时：工具失败事件，turn 可继续。
8. 取消：未派出 = `ABORTED_BEFORE_DISPATCH`；前缀 = `interrupted`。
9. 丢掉 notify 仍能按 seq 追上。
10. fence 失配的 checkpoint 被拒。
11. 同一 `(session_id, step_name)` 重试不产生两次计费侧效应。
12. 样例插件源码禁止出现驱动 / 直接 `INSERT INTO session_events`。
13. persistence-pg 过官方 coordinator 契约；storage-pg 过 `tests/contract.ts`（compat 必跑，native 的存储缝同样要过）。

只在一边绿、另一边红：该插件不能标 portable。

## 7. 路线图

**P0**

- §5 schema + `append_events` + 冷加载修复 + 两套时钟
- yield 五件套 + `jobs` 单表 + `release_stale`
- 四缝空壳（失败封闭，先让 tick 能过）
- native：`claim → assemble → llm.complete → greet` 证明应用语言里没有 while
- compat host：persistence-pg 复用 coordinator，官方 profile 叠 patch，跑通一次 turn，写入同一 `session_events`

**P1**

- `plugin_catalog` + `refresh_plugins` + locus
- storage-pg；tool_catalog 由两边同步
- 行为 suite 的 greet / inject / reject 三条在 **两个 driver** 上变绿
- LLM `provider_key`

**P2**

- Python / Swift `define_tool`
- 第二语言工具出现在同一 native turn
- memories；settings-pg / credentials-pg
- slice + grant 接到四缝
- workspace 第三态的最小 worktree 政策

**P3**

- 一个真实 T0 社区包在 compat 上零改跑
- 把它的行为契约抽成 fixture，native 侧重写一版，标 portable
- RSI：`evolve_propose/eval/commit/rollback` 只动 native 基因组，portable 插件仍在 compat 上回归

**明确不做**

- SQL 内 Cordis Fiber / HMR / `next()`
- 共享 `global_rev`、单表 kv、demo 触发器
- 第二队列当 loop 主人
- 在 worker 里仿瀑布以便「更像 DSH」
- 把官方 Python SDK 当成插件内核
- 让同一 session 两个 driver 同时认领

## 8. 对外怎么说

- 这是 **一份行为合同、两份运行时**。
- Native 是默认产品循环：Postgres 状态机 + 无状态 effect worker + 目录即插件法则。
- dsh-compat 是官方 loop 的对照实现和社区通道，不是「以后删掉的临时桥」。它存在，正是为了让未来用另一种实现重写的插件，还能证明自己没改行为。
- 不要说「实现了 Cordis」。说：法则来自 Cordis，核来自 yield-loop，对照面来自 DSH。
