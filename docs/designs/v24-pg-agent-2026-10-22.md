# v24 pg-agent：三面一核实现规格

日期：2026-10-23。状态：[规格] 候选实现合同；[已实现] 仅表示被引用的 v99/v13 源码存在，不表示 v24 已实现或 gate 已通过。本版为 R5 修订（Oracle chat `untitled-chat-1EDE09`）：class 闭集增 `claim`、wrapper 派生 `effect_id`、pins 拆分消费者两列、错误闭集补 `receipt_conflict`、锁向量与 T1/T2 措辞修订。所有修订均为行内改写，行号相对 R4 版未位移，各文档的 `L###` 引用继续有效。

> 核心裁决：所有可改变语义状态或外部世界的动作，必须由 `advance(effect_id, outcome)` 唯一接纳并提交。start/cancel/steer/respond、agent loop、Cordis 生命周期只产生 effect 或作为 effect kind 解释；poll/wait 是无副作用读。外部 IO 仍在事务外，advance 只提交资格、可信结果、资源债务和后继，不声称与远端原子。

## 1. 命题、判据与旧稿关系

### 1.1 命题

[规格] 本规格把 agent loop、六个控制原语、Cordis 插件生命周期定义为同一个持久化 effect 代数的三个使用面。唯一改变状态的函数是 `v24.advance(effect_id, outcome)`。该函数不决定业务意图，不读取自然语言，不调用模型、工具、进程或任意插件代码；它校验一个已冻结 effect 的结果并原子提交领域变化和有限后继。

[规格] “原生”需同时满足四条可证伪条件：

1. 每个领域状态写入口最终调用 advance；控制面没有直接改 run/fiber/slot/episode 的旁路函数。
2. 每种外部副作用先由 advance 提交唯一 effect 身份和执行资格，再事务外执行；结果只能由 advance 接纳。
3. claim/lease/token 仅属于统一 effect 表，不按 CE、plugin、spawn、cleanup 分叉出第二套资格账。
4. 恢复只做 `resolve` 重算资格和扫描未结算 effect；不得有独立恢复状态机、隐式队列或自有 claim。

[规格] 不变量 N1：一个 effect 的语义结果最多接纳一次。N2：一个 advance 的事件、投影、预算变化、pin 变化和后继同事务提交或全回滚。N3：旧 pin 固定的是能力身份，不代表仍可创建新消费者。N4：未知外部事实不被 cancel、dispose 或重试洗成成功。N5：卸载必须等待其激活消费者与 run 消费者都释放 pin。

### 1.2 三面关系

| 面 | 请求成为何种 effect | advance 解释结果后产生什么 | 独立权力 |
|---|---|---|---|
| [规格] agent loop | `model_call`、`tool_call` | 新消息/工具事实、预算扣减、interaction 投影、下一 effect 或 seal | 无 |
| [规格] 六动词 | start/cancel/steer/respond 命令 effect；poll/wait query | run/epoch/interation 状态与后继 | 只有 poll/wait 只读 |
| [规格] Cordis | install、fiber_control、dispose 命令 effect | install/fiber/episode/slot/pin 状态及有界清理后继 | 无 |

[规格] 三面可以有不同验证器和解释器，但只有一个提交协议、一个 effect 身份空间、一个 claim/fence 机制、一个请求 journal 与恢复扫描。解释器是纯数据库代码，输入仅为已验证 outcome 与冻结 effect.request；不得将策略分支重新焊成总 advance 决策树。

### 1.5 版本边界

[规格] 本版限定单 PostgreSQL、一个受信执行宿主、有限模型/工具回合、受信声明式插件，暂不承诺任意 JS 闭包、分布式主机接管、外部 exactly-once 或任意恢复逆。

[规格] 数据库拥有资格、授权校验结果、领域事实和提交顺序；host 负责事务外 IO 并提供受信执行回执。DB 无法验证远端世界是否真的按声明执行，此项列为信任债务，不能写成数据库证明。

## 2. 唯一核心 advance

### 2.1 类型与入口

[规格] 可执行 SQL ABI：

```sql
CREATE FUNCTION v24.advance(
  p_effect_id uuid,
  p_outcome jsonb
) RETURNS jsonb
LANGUAGE plpgsql SECURITY DEFINER;
```

[规格] `outcome_v1` 精确外形：`{"v":1,"class":"command|claim|success|failure|unknown","claim":{"attempt":N,"fence":N,"owner":"..."}|null,"body":{...},"receipt_key":"..."}`。command 与 claim 的 claim 必须 null，body 为已验证的命令负载；外部 effect 必须携当前 attempt/fence/owner。unknown 不能携可执行后继。`receipt_key` 可省略且不参与任何匹配；receipt 身份由 `effect_id` 与 outcome digest 共同确定。

[规格] 返回 `{v:1, disposition:"committed|replay|deferred", effect_id, emitted:[uuid...], revision, claim:{attempt,fence,owner}|null}`；`claim` 仅当 class=claim 且 disposition=committed 时非空，其余情形为 null。参数无效、权限错误、digest 冲突、过期资格返回稳定错误 JSON；错误与冲突不得有领域写。意外 SQL 错误必须抛出回滚，不吞掉。

[规格] 命令 admission 不是独立 SQL 写入口。客户端先以稳定 request UUID 选定 `effect_id`（§B.3 的公开 wrapper 没有该参数，因此 wrapper 必须按 `f(principal_id,request_key,kind)` 确定性派生；advance 校验 p_effect_id 与该派生值相等，不等返回 `effect_id_conflict`，从而同一 request_key 重试恒得同一 effect_id），然后调用 `advance(effect_id, {v:1,class:"command",body:{op:"admit_and_apply",kind,payload,request_key,canonical_bytes}})`；首次调用在 G 下原子插入 request、已结算 command effect/receipt、事件、领域变化和后继 effects。相同请求重交返回首次 response；不同 bytes 返回 conflict。不存在先写 ready command 再二次提交的窗口。start/cancel/steer/respond 与 install/fiber_control/dispose/scope_control wrapper 均只组装该参数并委托 advance，不得 DML。

### 2.2 事务边界

[规格] 调用方以 READ COMMITTED 短事务执行 advance 并 COMMIT；SQL 函数不自行提交。advance 首先取得事务级全局 advisory lock `G=(v24,1)`，之后依附录 B.1 锁行。外部调用前必须确认 claim 提交并且控制连接 IDLE。advance 绝不等待外部 effect、其他事务、人类回答或屏障清空。

[规格] G 在每个写入口的第一把数据库锁；不得存在先锁 request/run/fiber 后补 G 的入口。读取与纯 resolve 不取得 G，但执行资格和最终提交必须在 G 内复验结果相关身份。

### 2.3 按序处理

[规格] 一次 advance 执行次序固定：

1. 形状/字节上限校验；认证真实 session_user/OID→principal；不采信 p_actor、GUC 或 outcome 自报身份。
2. 取得 G；按 `(principal_id,request_key)` 锁 request 身份并检查精确 replay。相同键同 canonical bytes 返回首次响应；不同字节 `request_conflict`，零领域写。
3. 按附录 B.1 的全序锁 scope、run、effect、install、fiber、episode、slot、pin 关联行；验证 effect 未结算或 outcome 与已存 receipt 完全一致。
4. 按 outcome class 分流验证：`claim` 不校验 token，只校验 effect 可被 claim（kind 非 command、未结算或 lease 已过期）并签发 attempt/fence/claim_owner/lease_until；`success|failure|unknown` 校验 claim token 与请求 digest。共同校验 kind 对应 schema、run generation、fiber epoch、经 session_user 派生的静态 service-role 权限、pin、预算预留与 successor 上限。v1 不保存可变的 actor→plugin grant；能力准入由 install 声明、scope 路由与已绑定 pin 决定。
5. 对 `command` outcome 运行对应窄解释器；对 `success|failure|unknown` 校验受信 adapter receipt，再运行被冻结的 reducer/解释器；`claim` 不运行解释器、不产生 delta，只提交资格行。所有 interpreter 必须只读输入并返回 delta，不直接更新表。
6. 验证 delta 足迹：只能写 effect.kind 声明的表/目标；清理顺序 DAG 无环；生成后继不超过 16 且 idempotency key 唯一；预算不为负。
7. 原子写 receipt、事件、领域行/投影、pin/slot/episode 变化、请求响应、后继 effect；COMMIT 是唯一线性化点。

[规格] replay 顺序必须在 lease 到期、run terminal、配置漂移检查之前，但在主体身份和原请求 digest 校验之后。旧 attempt 的 late evidence 可按 kind 允许追加 `late_observation`，永远不能发布新业务后继。

### 2.4 resolve 与 reduce

[规格] `resolve(scope_id, keys[])` 是只读 SQL 查询，在一个 MVCC snapshot 中按 `scopes.route_path` root→leaf 求每个 key 的唯一 realm，再只在该 realm 解析唯一 live slot、provider fiber/episode、descriptor digest 和 live predicate。路由条目按叶优先覆盖；slot 不跨 realm fallback。它不写 pin、不分配 effect、不登记 dirty work、不拥有 claim；解析结果不是授权凭据。

[规格] run_start advance 在 G 内调用等价私有 resolver 并将返回项固化成 run pin；fiber 激活也在 advance 内解析全部硬依赖并写 activation pin。每次 claim/结果接纳复验该 pin 仍属于对应打开 episode；provider withdraw 仅阻止新 pin，旧 pin 可用于排空。

[规格] `reduce(policy_ref,state,fact)->(new_state,intents)` 是部署期注册、不可变版本、确定性只读 reducer。agent loop 只交付一个 `chat_tool_v1` reducer：model 的 tool_calls 变成被 pin 授权的 tool effect，assistant final 变成终结候选；reducer 不能选择未 pin 能力、调用 SQL、花预算或写状态。

[规格] v13 的教训是 reducer 策略不得焊进 advance：advance 只校验 reducer 输出是封闭 intent 集并提交，不含 prompt、路由、工具选择策略树。

### 2.5 advance 绝不做

[规格] 不执行网络、模型、工具、fork/exec、插件 callback；不 `pg_sleep` 等屏障；不在事务内等待；不解释任意 SQL/代码；不获取第二套 runtime/plugin lease；不做无界子树遍历；不将 unknown 转成功；不创建独立队列/recovery plan；不以全局 catalog revision 使所有 pin 失效；不因同名控制入口写第二份状态机。

### 2.6 effect 状态与唯一性

[规格] effect 状态仅 `ready,claimed,succeeded,failed,unknown,cancelled`。每 effect 至多一个未替代 claim；attempt/fence 单调。每行 `effect_id` 即唯一 receipt 身份，`requests(principal_id,request_key)` 保证 request replay 唯一；同一父 effect/ordinal 唯一 successor。command effect 不需 host claim，可由 `advance(..., command outcome)` 直接提交；仍须有 receipt 与 request journal。

[规格] ready effect 取消可落 `cancelled`；claimed effect 不能谎报取消完成。先撤其后继资格并置 `cancel_requested`，等待原回执或转 unknown；旧结果不得发布业务后继。

## 3. 数据模型：十张表

### 3.1 表清单与列承重

[规格] v24 目标 schema 十张表。视图、索引、约束、函数、触发器不计表；禁止第十一张“方便状态表”承载同一事实。

#### 3.1.1 `scopes`

[规格] 列：`scope_id uuid PK` 身份；`parent_id uuid NULL` 自引用父节点；`root_id uuid` 根 scope；`route_path uuid[]` 从 root 到本节点的不可变路径且末项必须为 scope_id；`realm_routes jsonb` 本节点显式的 key/alias→realm 路由覆盖；`default_realm text NULL` 本节点默认 realm；`owner_principal uuid` 创建者；`created_by_effect uuid` 创建该节点的 scope_control effect；`close_requested_at timestamptz NULL` 关闭意图时间；`closed_at timestamptz NULL` 完全排空时间。

[规格] 根 scope 只可由已认证 system-admin 的 `scope_control(action=create_root)` command 通过 advance 创建；应用 role 无根表 INSERT 权限。子 scope 只可由有权 parent 的 `scope_control(action=create_child,parent_id,realm_routes,default_realm)` 经 advance 创建；root_id 与 route_path 由父 scope 推导，不接受调用者自报。root_id、parent_id、route_path、realm_routes 与 default_realm 创建后不可改；要更改 realm 路由必须关闭旧 scope 并在新 child scope 上声明覆盖。

[规格] 每个 non-root 的 `parent_id` 必须存在、同 root、未关闭；`route_path = parent.route_path || scope_id`，root 的 path 为 `[scope_id]` 且 `root_id=scope_id`。本行端点（`route_path` 末项必须等于 `scope_id`）由 CHECK 保证；`route_path = parent.route_path || scope_id` 与 child 同 root 属跨行不变量，CHECK 无法表达，由 advance 在 G 下校验、并以 DEFERRABLE INITIALLY DEFERRED 约束触发器兜底；parent 环与跨 root 引用同样由 advance 拒绝。`closed_at` 单调且只有排空屏障满足后可写：scope 下每个 install 均为 `disposed`，且无未解决 host_prepare/host_release 资源责任；`preparing`、`prepare_unknown` 先经同 reservation inspect 再释放引用。无 inspect 时 scope 保持 `close_requested_at`（closing），不得写 `closed_at`。

[规格] scope 关闭先写 `close_requested_at`，立即拒绝 start、install、child create 和新 pin；然后以有界 successors 取消/封口其非 terminal runs、retire fibers，并为该 scope 下所有 install（包括未激活 install）发起 dispose，按子 scope 先于 parent 排空。claimed IO 不谎称已停止，按 unknown/debt 收敛；即使 run 已 terminal，引用 pin 的 effect 未确认静默前也不释放 run pin。`closed_at` 前，该 scope 下每个 install 必须为 `disposed`，且无未解决的 prepare/release 资源责任；preparing/prepare_unknown 必须经同 reservation inspect 后才能释放引用。没有 inspect 时保持 closing，拒绝 closed_at。业务 unknown 保留在 run/effect 审计事实中；关闭不可逆。

[规格] realm 路由对每个请求 key 沿 `route_path` 从 root 到 leaf 扫描，取最深（leaf 优先）显式 `realm_routes[key]`；无显式项则取最深非空 `default_realm`；不存在时返回 `dependency_unresolved`。得到 realm 后只在该 realm 查唯一 live slot，不跨 realm fallback。此路由只决定 key→realm，不能覆盖 slot 唯一性或 pin 资格。

#### 3.1.2 `runs`

[规格] 列：`run_id uuid PK` 身份；`scope_id uuid` 所属 scope；`parent_run_id uuid NULL` spawn 谱系；`spawn_key text NULL`；`spawn_request_digest bytea NULL`；`owner_fiber_id uuid NULL` 绑定服务 fiber；`owner_episode_id uuid NULL` 精确服务代次；`status` running/waiting/completed/failed/cancelled/blocked_unknown；`epoch_no bigint` 对话连续期；`registration_generation bigint` waiter 注册代次；`turn_no bigint` 已提交模型步骤数；`driving_generation bigint` steer/respond/cancel 争用代次；`remaining_steps integer` 总预算；`remaining_tokens bigint` 可选硬额度；`remaining_tool_calls integer`；`remaining_wall_ms bigint`；`interaction jsonb NULL` 当前交互；`pending_steer jsonb NULL` 最新尚未续链的 steer 指令及其 driving_generation；`close_intent jsonb NULL` final/cancel 请求事实；`result jsonb NULL` 终值；`revision bigint` poll 版本；`created_at/updated_at/ended_at`。[S4]（D-S4-8）三枚模型摘要不落 `runs` 列：`runs` 不加 `policy_digest`、`schema_digest`、`toolset_digest`，`result` 也不承载；三摘要落 `model_call.request.digests` 的 `{policy,schema,toolset}`（各 hex64），同一 run 的所有 `model_call` 的 `request.digests`（`policy`/`schema`/`toolset`）必须逐字节相同。[S4] 派生：`policy` = 对 `v24.loop_policy()` 的 canonical JSON 取 sha256；`schema` = 对冻结的 `chat_tool_v1` schema 对象 `{v:1,name:'chat_tool_v1',fields:['text','tool_calls','interaction','final','usage']}` 的 canonical JSON 取 sha256；`toolset` = 对 live run pins 的 canonical JSON 数组 `[{key,descriptor_digest(hex)}] ORDER BY key` 取 sha256。

[规格] CHECK：预算非负；terminal 状态与 `ended_at` 同真；waiting iff interaction 非空；terminal 时 `pending_steer IS NULL`；owner fiber/episode 同时空或同时非空。`epoch_no` 标识对话连续代，非 terminal steer 使其变化；若旧 model_call 仍 claimed，steer 写/覆盖 `pending_steer`，旧调用静默后由其 settlement advance 消费最新值并创建唯一新 model_call；`registration_generation` 标识 run 接入注册代，start 初始化为 1，wait/poll 只校验而不递增，重启/重连同一 run 不改变它；新 run 以新 run_id 开始新注册代。它不同于可随对话变化的 epoch。parent、owner、scope 的 FK 限制及同 scope/owner episode 由复合 FK/advance 复核。

#### 3.1.3 `effects`

[规格] 列：`effect_id uuid PK`；`parent_effect_id uuid NULL`；`ordinal int NULL`；`requester_id uuid` 认证 principal（successor 继承发起 principal）；`request_key text` 幂等身份（successor 由父 effect id 与 ordinal 确定）；`scope_id uuid NULL`；`run_id uuid NULL`；`fiber_id uuid NULL`；`episode_id uuid NULL`；`pin_id uuid NULL`（实际使用的 run pin FK）；`epoch_no bigint NULL`；`generation bigint NULL`；`kind text` 闭集；`status` 上述六状态；`request jsonb` 冻结输入；`request_digest bytea` canonical hash；`replay_policy text` no_replay/replay_safe/manual；`attempt_no bigint`；`fence bigint`；`claim_owner text NULL`；`lease_until timestamptz NULL`；`cancel_requested boolean`；`outcome jsonb NULL`；`resource_quiesced_at timestamptz NULL`（success/failure receipt 确认 IO 已返回时置位；unknown 仅由受信 inspect receipt 证明静默时置位）；`created_at/settled_at`。

[规格] kind 闭集含 `command_start,command_cancel,command_steer,command_respond,command_install,command_fiber_control,command_dispose,command_scope_control,model_call,tool_call,host_prepare,host_release,inspect_resource,fiber_reconcile`。`spawn` 是 model outcome 内的 DB-only intent，不属于 kind 闭集、不 claim、不执行 IO。kind 决定验证合同，不授权 caller 自选执行域。

#### 3.1.4 `pins`

[规格] 列：`pin_id uuid PK`；`consumer_type` activation/run；`consumer_episode_id uuid NULL` 与 `consumer_run_id uuid NULL` 两列严格 XOR；`consumer_id uuid` 为 `GENERATED ALWAYS AS (coalesce(consumer_episode_id,consumer_run_id)) STORED` 的生成投影；`consumer_epoch bigint`；`key text` 能力键；`slot_id uuid`；`provider_fiber_id uuid`；`provider_episode_id uuid`；`descriptor_digest bytea`；`created_by_effect uuid`；`released_by_effect uuid NULL`；`released_at timestamptz NULL`。activation/run 类型严格 XOR；唯一键分别为 `(consumer_type,consumer_id,consumer_epoch,key)`；provider 的 FK 组合绑定 slot/episode。

#### 3.1.5 `episodes`

[规格] 列：`episode_id uuid PK`；`fiber_id uuid`；`epoch bigint`；`activation_effect uuid`；`state` active/retiring/closed/blocked；`target_seq bigint`；`opened_at/retire_started_at/closed_at`；`failure jsonb NULL`。显式 `UNIQUE(fiber_id,episode_id)` 是 `installs(owner_fiber_id,owner_episode_id)` 与 `fibers(owner_fiber_id,owner_episode_id)` 复合外键的不可变目标；FK 只证明 episode 身份从属于 fiber，不约束其是否为当前代。一个 fiber 最多一个未关闭 episode；`UNIQUE(fiber_id,epoch)`。

[规格] episode 是一次成功激活到完全清理的资源/依赖身份，不是对话 epoch。pin 不能替它：没有 run 的持久 fiber 消费者仍阻止 provider release；而 pin 行本身不能表达激活是否已完整建立或一次配置反转期间旧/新 activation 的身份。episode 保存这个最小事实，关闭只在 pin 清零、owner children 清零、贡献撤销后发生。

#### 3.1.6 `fibers`

[规格] 列：`fiber_id uuid PK`；`install_id uuid`；`scope_id uuid`；`owner_fiber_id uuid NULL`；`owner_episode_id uuid NULL`；`want_on boolean`；`control_seq bigint`；`current_episode_id uuid NULL`；`disposed_at timestamptz NULL`；`failure_seq bigint NULL`；`failure jsonb NULL`；`next_contribution_seq bigint`；`created_by_effect uuid`。`current_episode_id` 是当前代投影指针，历史 owner FK 不引用它。

[规格] 关闭的 fiber 不复活；retry 必须在未 dispose 的 fiber 上递增 `control_seq`。owner 代次固定，owner episode 关闭会级联处置其 child fiber。

#### 3.1.7 `slots`

[规格] 列：`slot_id uuid PK`；`fiber_id uuid`；`episode_id uuid`；`realm text`；`key text`；`descriptor jsonb`；`descriptor_digest bytea`；`contribution_seq bigint`；`withdrawn_at timestamptz NULL`；`released_at timestamptz NULL`。

[规格] descriptor 不可变；同一 `(realm,key)` 只允许一个未 release slot，即使 withdrawn 仍占槽直到旧引用排空。provide 唯一性以真实注册生命周期计，不在 install 声明阶段抢占；这对齐 Cordis `provide()` 而不是目录预留。`requires[].check_policy` 是 manifest 中封闭、版本化的纯数据谓词，只能读 advance 已锁定的依赖/episode projection；不执行 JS callback，不通过则 activation 原子失败。

#### 3.1.8 `installs`

[规格] 列：`install_id uuid PK`；`scope_id uuid`；`owner_fiber_id uuid NULL`；`owner_episode_id uuid NULL`（两个 owner 列同时 NULL 或同时非 NULL；复合 FK 指向不可变 `episodes(fiber_id,episode_id)` 身份）；`identity text`；`version text`；`manifest jsonb` canonical 完整声明；`manifest_digest bytea`；`requires jsonb` 全硬依赖（每项含 key 与可选 check_policy）；`provides jsonb` 含 realm/key/descriptor/schema；`artifact_digest bytea`；`adapter_digest bytea`；`owner_principal uuid`；`state` preparing/installed/prepare_failed/prepare_unknown/dispose_pending/disposed；`created_by_effect uuid`；`dispose_effect uuid NULL`；`disposed_at timestamptz NULL`。

[规格] install、fiber、episode 分离：install 是受信声明/制品身份；fiber 是作用域中的组件实例；episode 是一次有效激活。root install 的 owner 两列为空；child install admission 在 G 内锁定并校验 owner fiber 未 disposed、`want_on=true`、`current_episode_id=owner_episode_id` 且该不可变 episode 行为 active，再在同一 advance 写固定的 `owner_fiber_id/owner_episode_id`。`installs(owner_fiber_id,owner_episode_id)` 复合 FK 指向 `episodes(fiber_id,episode_id)` 的 `UNIQUE`，不指向 `fibers.current_episode_id`；当前有效性只在 admission 时检查。owner episode 关闭由该 episode 身份下所有 child install=`disposed` 的屏障裁决，不依赖历史 FK 绑定 current 指针。状态迁移为 preparing→installed（host_prepare success）或 preparing→prepare_failed|prepare_unknown；prepare_failed 可显式 retry→preparing；prepare_unknown 仅同 reservation 的 inspect 确认静默后可 retry→preparing 或 dispose；dispose_pending→disposed，其他跳转拒绝。`UNIQUE(scope_id,identity,version)` 将同 scope 的身份版本绑定到单一声明；相同 identity/version 的重装必须比较 `manifest_digest` 与 `artifact_digest`，相同 digest 返回既有 install，不同 digest 以 `install_identity_conflict` 拒绝，不覆盖历史。禁止用 install=active 代替 fiber 状态。

#### 3.1.9 `events`

[规格] append-only 事实：`event_id`、`effect_id`、`seq`、`entity_type/entity_id`、`event_kind`、`payload`、`payload_digest`、`created_at`。`seq` 在每个 entity 内单调递增（同一事务内取该 entity 的 `max(seq)+1`；G 串行保证无并发分配；事务回滚后该号可重用，故不承诺无空洞；replay 不重新分配），`UNIQUE(entity_type,entity_id,seq)` 保证事件游标无歧义；`UNIQUE(effect_id,entity_type,entity_id,event_kind)` 防解释器重放重复事件。wait 的 `p_after_event_seq` 对应 run entity 的该列。

#### 3.1.10 `requests`

[规格] `principal_id,request_key` 主键；`kind`；canonical `request_bytes bytea` 与 digest；`effect_id` UNIQUE；首次 response；时间。request/effect 由同一次 advance 在同一事务建立，`requests.effect_id → effects.effect_id` 使用 DEFERRABLE INITIALLY DEFERRED 外键：先插 effect，再插 request，事务提交时闭合。重放先查 request 主键及 bytes，再返回关联 effect 的首次 response；没有 request 可见但 effect 已存在的中间窗口。

### 3.2 索引与约束

[规格] 必要约束：

- `effects`: system effects 用 `(parent_effect_id,ordinal)` 唯一；command 的 request 唯一性归 `requests(principal_id,request_key)`；每 run 至多一个未结算 `model_call`，partial unique `(run_id) WHERE kind='model_call' AND status IN ('ready','claimed')`；多个 `tool_call` 可并行 ready/claimed；每行仅一个 outcome/receipt；`resource_quiesced_at` 由成功/失败回执或 inspect 置位；unknown 仅 inspect 可置位。
- `scopes`: root `parent_id IS NULL` iff `root_id=scope_id`；route_path 末项=scope_id；关闭时间单调（`closed_at ≥ close_requested_at`）。以下各项是跨行/跨表不变量，CHECK/UNIQUE 无法表达，由 advance 在 G 下强制、并以 DEFERRABLE 约束触发器兜底，此处记录口径而非声明为 DDL 约束：child 同 root 且 `route_path=parent.route_path||scope_id`；`closed_at` 前子 scope closed、run terminal、fiber disposed、episode closed、slot released；本 scope 下每个 install=`disposed`，且 host_prepare/host_release 无未解决资源责任；preparing/prepare_unknown 必须同 reservation inspect 后才能释放；无 inspect 只可保持 closing。
- `episodes`: `UNIQUE(fiber_id) WHERE closed_at IS NULL`；`UNIQUE(fiber_id,epoch)`；必须有 `UNIQUE(fiber_id,episode_id)`，供 `fibers.current_episode_id` 的当前投影约束及 `installs(owner_fiber_id,owner_episode_id)` 的历史身份 FK 使用；后者仅引用 `episodes(fiber_id,episode_id)`，绝不引用 `fibers.current_episode_id`。
- `pins`: partial unique `UNIQUE(consumer_type,consumer_id,consumer_epoch,key) WHERE released_at IS NULL`（consumer_id 为生成列）；索引 `slot_id WHERE released_at IS NULL`；消费者 XOR CHECK 落在 `consumer_episode_id`/`consumer_run_id` 两列，consumer_id 由二者生成；pin provider epoch 必须等于 slot episode；`effects.pin_id` 是可空 FK 到 pins。run pin 只有 run terminal 且不存在引用它的 effect（`status IN ('ready','claimed')` 或 `status='unknown' AND resource_quiesced_at IS NULL`）时才可释放；claimed 与未静默 unknown 均阻止释放。
- `slots`: `UNIQUE(realm,key) WHERE released_at IS NULL`；`UNIQUE(fiber_id,episode_id,contribution_seq)`；withdrawn/released 单调；release 前检查无活 pin。
- `fibers`: owner/self FK、owner_episode FK、disposed 墓碑 CHECK；owner 图与 inject/pin 图组合无环由 advance 在 G 内验证。
- `runs`: terminal/interaction/close_intent 组合 CHECK；`owner_episode_id` 必须属于 owner_fiber_id；`UNIQUE(parent_run_id,spawn_key) WHERE spawn_key IS NOT NULL` 且 spawn digest 固定输入；cancel 后不可 steer/respond。
- `installs`: `UNIQUE(scope_id,identity,version)`；manifest、requires、provides 与 manifest_digest 同行不可变且 canonical digest 匹配；owner fiber/episode 两列空值配对，非空时 `FOREIGN KEY(owner_fiber_id,owner_episode_id) REFERENCES episodes(fiber_id,episode_id)`，目标有 `UNIQUE(fiber_id,episode_id)`；该 FK 固定历史身份，不引用 `fibers.current_episode_id`。admission 在 G 内另校验 `fibers.current_episode_id=owner_episode_id` 且 episode.state=active、owner.want_on=true、未 disposed；child install 的 prepare/release 收束前 owner episode 不得关闭；状态迁移 preparing→installed|prepare_failed|prepare_unknown；只有 installed 可激活；同 identity/version 不同 manifest/artifact digest 拒绝。
- `requests`: canonical bytes/digest 一致；同主键不同输入 conflict；request 与 effect 外键闭合。
- `events`: append-only trigger 禁 UPDATE/DELETE/TRUNCATE；effects 的 request/kind/主体/目标在首次提交后不可变。

[规格] 常用索引：`scopes(parent_id,closed_at)`、`scopes(root_id,scope_id)`；`effects(status,created_at)` partial ready；`effects(lease_until)` claimed；`runs(scope_id,status)`、`runs(parent_run_id,status)`、`runs(owner_episode_id,status)`；`pins(slot_id)` 活 pin；`fibers(scope_id,disposed_at)`、`fibers(owner_fiber_id,disposed_at)`；`installs(scope_id,identity,version)` unique；`installs(owner_fiber_id,owner_episode_id,state)` 用于 owner 排空闭包；`slots(realm,key,released_at)`；`events(entity_type,entity_id,seq)`。

### 3.3 不建哪些表

[规格] 不建 `turns`：turn 是 model effect 与 advance 的序号事实，写在 runs/events/effects。无独立 claim attempt 表：attempt/fence 列在 effects 同一权威行，pin 中只存冻结能力身份。无 receipt 表：每 effect outcome 一次，存 effects.outcome/settled_at。无 snapshot/wake、work_item、dirty、recovery_plan 或 runtime lease 表；snapshot 可由 runs 投影，唤醒由可丢 NOTIFY+定时扫描，维护只提交普通 effects。无双账本/commit_bundle：单一 events 与效果行共用一个事务，v24 旧稿双账本会制造“哪个 ledger 有权”的新承重面。

[规格] 本表数为十。若后续发现 cleanup 要跨事务逐项持有不可变逆事实，必须改本规格的数据模型与总表数；不能塞进任意 JSON 偷藏第二状态机。

### 3.4 约束表达的 Cordis 不变量

[规格] scope root/path 与 parent 不可变，realm 路由逐 key 叶优先；closed scope 不再接纳 run/install/pin，且关闭前 child/run/fiber/resource 全排空。同 realm/key 唯一未释放槽；空 inject 的 fiber 可以激活；非空 inject 必须全部 resolve 成 live slot；provider descriptor 与 episode 固定；新解析不能看到 withdrawn；旧 pin 继续有效到释放；owner 子实例先 dispose；消费者 pin 释放前 provider episode 不得 close；dispose 墓碑不能复活；激活失败时 slot/pin/episode 全回滚，写明失败 outcome 后可重试。

## 4. 六动词合同

### 4.1 公共调用边界

[规格] 所有公开 API 以 `principal_id` 从认证 session 派生；公开 `p_actor` 不作为授权证据。请求 key 1–512 字符，payload canonical bytes ≤1 MiB。所有写 command API（六动词中的四写，以及 install/fiber_control/dispose/scope_control）wrapper 调用 `advance` 的 `admit_and_apply` outcome；不先插入 command effect。advance 在一个事务中建立 effect、request journal、receipt、领域变化和后继。request/effect 行按 §3.1.10 的延迟 FK 规则同事务闭合，原请求 response 与 effect receipt 同事务提交。

[规格] 命令幂等键 `(principal_id,request_key)`，包含 verb、target、expected version、payload 的规范字节；同键异参数返回 `request_conflict`，不覆写首次 response。所有写 command 持 G。

### 4.2 `start`

[规格] 签名：`start(p_scope uuid,p_owner_fiber uuid NULL,p_input jsonb,p_budget jsonb,p_request_key text)->jsonb`。语义：提交 `command_start` effect；advance 锁 scope/fiber 后解析插件依赖、写 run、打开对话 epoch=1、生成 model effect 和 run pins。start 不创建 child fiber，不加载插件实现代码。

[规格] 写列：runs、pins、effects、events、requests。幂等键 principal/request_key；建议另有 `(parent_run_id,spawn_key)` 规则仅用于 spawn。

[规格] G 顺序：先 G，后 request、scope、fiber/episode/slot/pin。start 与 dispose 两序：start 先则 run pin 令 dispose 拒绝/等待；dispose 先则 fiber 墓碑/episode closed，start 拒绝 `provider_unavailable`。两者均不得产生悬空 pin。

[规格] 错误：`unauthorized,invalid_args,request_conflict,scope_closed,provider_unavailable,budget_exceeded,dependency_unresolved`。对插件影响：只绑定既有 fiber episode，不能把一次 run 当成新插件激活。

### 4.3 `poll`

[规格] 签名：`poll(p_run uuid,p_after_revision bigint DEFAULT 0)->jsonb`。只读 MVCC 查询授权后的 runs 投影与 events。无 snapshot 表、无 request journal、无 effect、无 G、无锁写；可重复调用返回提交状态，不增加 revision。

[规格] 幂等键不适用；读游标是输入条件而非消费标记。错误以统一不可探测 `not_found_or_denied` 返回。对插件没有生命周期影响。

### 4.4 `wait`

[规格] 签名：`wait(p_run uuid,p_registration_generation bigint,p_epoch bigint,p_after_event_seq bigint,p_timeout_ms int)->jsonb`。`registration_generation` 来自 start 返回的 run handle；与 `epoch_no` 不同，前者是 run 接入注册代、后者标记对话代次。wait 不递增任何 generation；不匹配返回 `registration_stale`，先 poll 确认 run_id 后重试。`p_after_event_seq` 是 events 的已读游标；NOTIFY 仅为可丢提示。SDK 执行“短事务读检查→COMMIT→LISTEN/等待→短事务重读”，阻塞时绝不持连接事务。每 waiter 自有游标；timeout 必须最终重读。数据库 `wait_check` 子函数 STABLE 只读。

[规格] wait 整体无幂等键，不改变事实、预算、revision、pin、effect。对插件仅观察其状态。超时是 wake 条件，不是 effect。

### 4.5 `cancel`

[规格] 签名：`cancel(p_run uuid,p_expected_generation bigint,p_request_key text)->jsonb`。advance 提交 `command_cancel`，锁 run/fiber/episode，generation CAS；归档未 claim 后继，取消 ready effect，已 claimed 标 `cancel_requested` 并撤销其后继发布权，run=cancelled 且写 seal 事件，列出未知/在途 effect。cancel 只递增 `runs.driving_generation`，不改 `effects.fence`；当前 token 仍可结算事实/成本，reducer 按当前 generation 丢弃后继。

[规格] 幂等按 principal/request_key 精确 replay；不同 key 对已 cancelled 返回 `already_terminal`；同提交双 cancel 只有一个 seal，另一返回 terminal/replay 语义，不重复事件。

[规格] cancel 不退役共享 fiber。若 run 是 child run，取消该 run 的 owned child run 以有界后继 effect 展开；run.owner_fiber 的 unload 只有显式 deactivate/dispose 或 owner 退役触发。cancel 竞争：T2/advance 先则事实保留、后继若已提交可见；cancel 先则撤销 driving_generation 发布权；原 claim token 在被新 attempt 替代前仍可结算事实/成本，但不发布工具/model 后继。run pin 要等 terminal 且无引用它的未结算、资源未静默 effect 才释放。

[规格] 插件影响：不修改 activation pin；若 cancel 作用于 fiber_control 所拥有的维护 run，只取消该 run 的后继资格，已有 cleanup obligation 仍可由独立普通 effect 完成。v1 权限撤销通过授权操作者发起 cancel 终止特定 run，不另存 actor→plugin grant 或 revoke_epoch 状态。

### 4.6 `steer`

[规格] 签名：`steer(p_run uuid,p_expected_generation bigint,p_instruction text,p_request_key text)->jsonb`。steer 是业务意图/对话连续性变化，递增 driving_generation 与对话 `epoch_no`；仅限非 terminal run。对 completed/failed/cancelled/blocked_unknown 一律返回并记稳定业务错误 `already_terminal`，绝不重开、重绑 provider 或复用已释放 run pin。active run 保持配置/能力 pin 不变，旧 ready effect 归档；旧 claimed effects 标 `cancel_requested`，若任一旧 model/tool effect 尚未 settled 且静默，则保存/覆盖 `runs.pending_steer`，不生成 model_call。最后一个旧 token 结算且确认静默的 advance 按最新 generation 消费 pending_steer、清除旧 interaction 并生成唯一 model_call；旧结果只记事实/成本，不可发布旧后继。旧 effect 若落 unknown，则 run blocked_unknown、清空 pending_steer，不自动续链。

[规格] steer 清除当前 interaction；不改 fiber episode、install version、scope `realm_routes` 或已绑定 pin。配置升级必须独立 plugin activate/deactivate，不能借 steer 换 provider。旧 epoch claim 的迟到成功可计费/审计，但无法发布交互、后继或最终结果。

[规格] race：active steer 先于 fiber withdraw，保留旧 pin 排空；withdraw 先则 active steer 仍可用旧 pin，但不准新 run bind；terminal steer 在两种提交序均返回 `already_terminal`。有旧 claimed model/tool effect 时 pending_steer 等旧 token 全部结算且静默后再续链。授权操作者若需立刻撤发布权，提交 `cancel` command；slot withdrawn 本身不拒绝已准入 pin。

### 4.7 `respond`

[规格] 签名：`respond(p_run uuid,p_interaction_id uuid,p_response jsonb,p_expected_generation bigint,p_request_key text)->jsonb`。一次 model outcome 至多产生一个 interaction，`interaction_id = source_model_effect_id`，由该 advance 写入 `runs.interaction` JSON 对象；对象还含 `origin_effect_id,generation,schema_digest,prompt_digest,created_at`。验证当前 waiting interaction 精确 id、类型 schema 与 responder principal；command effect 在一个 advance 中消费 interaction、追加 human/responded 事实、generation+1、准入下一 model effect。不是 worker human lease，不另建 settlement 表。

[规格] 精确 request replay 优先于当前 interaction/generation 检查；同键异响应 conflict。两个不同 request 同时答：G/锁序赢家先消费；后者 `interaction_mismatch`，零写。cancel 先则 respond `already_terminal`；respond 先则 cancel 关闭其刚生成的 ready model effect。respond 只提交该 interaction 的业务答复，不改变 install manifest 或 capability pins；v1 不提供动态 plugin grant。

[规格] 六动词总览：start/cancel/steer/respond 为写命令 effect；poll/wait 为纯读查询。不是“六个都共用一口写”而是四个写者共用 advance、两个读者无写，因此不引入伪造 read effect。

## 5. 原生 agent loop

### 5.1 turn 定义与闭环

[规格] turn 定义为一次 effect 执行及唯一 advance：`ready → claim COMMIT → IO outside transaction → advance(outcome) COMMIT`。模型与工具分属独立 turn。`model→tool→model` 是至少三个 turn；多个并行工具为多个 tool effects，各自独立接纳。

[规格] start 的 advance 写首个 `model_call` effect；model success 若有 tool_calls，advance 校验每项 tool key 存在 run pin、schema 正确、工具预算允许后生成 tool effects；每个 tool success 各自产生事实和下一 reducer input，满足批次屏障後生成 continuation model effect。工具不可在模型 advance 事务内执行。

[规格] 禁止 tool effect 直接生成任意 SQL；tool descriptor 是固定 host adapter id + digest，参数只按冻结 JSON schema 校验。模型输出是候选，不是授权。

### 5.2 预算

[规格] run 存 `remaining_steps`、`remaining_tokens`、`remaining_tool_calls`、`remaining_wall_ms` 的准入上限与已承诺数。effect admission 先预留最大成本；success/failure 按受信 receipt 实际 usage 结算，unknown 保留 uncertain，不释放预算。工具数量、并发数、输入/输出字节和每次 advance 后继数均有硬上限。

[规格] 每次 advance 最多新增 16 个 effect；若模型返回更多 tool_calls，拒绝整份 outcome 为 `invalid_outcome` 并进入可审计确定失败，不部分截断，除非 reducer 合同定义稳定 truncation 规则并计入版本摘要。

[规格] 预算耗尽生成一次封口命令，不准 loop 自行写 terminal。最终 seal 要求无 ready/claimed business effect、无 pending interaction；unknown 允许 cancelled seal 但需列明；正常 completed/failed 不允许业务 unknown。

### 5.3 封口与 unknown

[规格] reducer 只提交 close intent；同一 advance 若工作/interaction/资源均满足，可原子 seal；否则写 `close_intent` 并准入维护 effect。最终一个清理 effect 可在自己的 advance 中完成 seal。取消 seal 不被 cleanup 结果改写。

[规格] 外部调用结果为 unknown 时 effect=unknown，run=blocked_unknown，不生成业务后继。普通 steer/respond 拒绝 unknown wall；cancel 可 seal 并保留 unknown。cleanup unknown 形成独立资源责任，允许新 inspect/dispose effect 取证，但不改原 unknown。

[规格] 在途 cancel：未 claim effect 直接 cancelled；claimed effect 设置 cancel_requested 并递增 run driving_generation，不改 claim fence。原 token 在新 attempt 真正替代前可提交成功/失败/unknown 事实与成本；因 generation 过期不得生成新业务后继。只有新 attempt 实际取代该 claim 时 fence 才递增，之后旧 token 为 stale。cancel 后 run terminal 不等于资源静默，pin 留到引用 effect 正常回执确认静默，或 inspect 将 `resource_quiesced_at` 置位。

### 5.4 effect reducer 与工具批次

[规格] [S4]（D-S4-8）每 run 固定的 `policy_digest`、`schema_digest`、`toolset_digest` 三枚模型摘要不落 `runs` 列，而落 `model_call.request.digests` 的 `{policy,schema,toolset}`（各 hex64）；派生：`policy` = 对 `v24.loop_policy()` 的 canonical JSON 取 sha256，`schema` = 对冻结的 `chat_tool_v1` schema 对象 `{v:1,name:'chat_tool_v1',fields:['text','tool_calls','interaction','final','usage']}` 的 canonical JSON 取 sha256，`toolset` = 对 live run pins 的 canonical JSON 数组 `[{key,descriptor_digest(hex)}] ORDER BY key` 取 sha256。[S4] 同一 run 的所有 `model_call` 的 `request.digests`（`policy`/`schema`/`toolset`）必须逐字节相同；settlement 独立重算 `v24.model_digests(run_id)` 并要求与 `request.digests` 全等，不等即结构性 `invalid_outcome` 且零写。旧配置更改不追改已有 run；新的 run 按新 resolve 绑定。reducer 的持久 state 必须是 JSON 且有最大字节限制；不能持 JS continuation 或 callback。

[规格] model effect 只接受结构化 `{text,tool_calls,interaction,final,usage}`。互斥检查：tool_calls 与 final 不可并存，interaction 不得与 tool_calls 并存；assistant text 可与任一共存。tool result schema 按 descriptor 固定版本验证。

[规格] tool batch 屏障是事实查询，不自建队列：同一 source model 可生成多个并行 ready/claimed `tool_call`；G 串行接纳各 tool outcome，只有该 batch 所有 ordinal 均 settled 且资源静默后，最后一个 advance 才创建一个 model continuation。唯一 `(parent_effect_id,ordinal)` 和 batch digest 防重复 continuation。唯一未结算索引只约束 `model_call`，不串行化工具。

### 5.5 spawn 边界

[规格] spawn 由 model outcome 的 `tool_calls[]` 中命中保留 intent key `agent.spawn` 触发；它不是 effect、不可 claim、不可做外部 IO。该模型 outcome 的同一 advance 解释受限 intent，校验 `(parent_run_id,spawn_key)` 与 canonical digest，原子创建 child run、spawn edge（由 child 的 `parent_run_id,spawn_key,spawn_request_digest` 承载）、扣父 quota、写 child 初始 quota、固化可选 child owner_fiber/episode pin，并生成 child 首个 `model_call` effect。任一失败全部回滚。spawn 不 install child fiber，也没有独立 replay 合同；请求幂等由模型 outcome receipt 与 spawn 唯一键共同保证。

[规格] 仅当子任务需要一个独立插件组件实例/持久服务身份/独立生命周期时，才另有 install(child fiber) effect；普通 agent child 是 run。run owner_fiber 是资源依赖关系，不能用 owner_fiber 代替 parent_run 谱系，反之亦然。

[规格] `(parent_run_id,spawn_key)` 唯一绑定 canonical input bytes、role/policy/scope/budget 请求。相同 bytes replay 同 child；同 key 不同 bytes 返回 `spawn_key_conflict`，即使 request_key 改变亦然。child birth、parent remaining budget 扣减、child 初始 quota、edge、response 同一 advance 原子提交，接纳失败全无；没有独立 escrow 表或责任账。

### 5.6 loop 的两种 effect

[规格] `model_call`：固定 provider descriptor、prompt digest、run epoch/generation、预算 reservation；成功只接结构化模型响应。`tool_call`：固定 slot id/descriptor digest/schema/pin，参数过 schema 且 replay 权利明确。

[规格] 二者共用 effect.status/attempt/fence/lease/outcome，差异只在 schema 和 adapter。模型策略不得绕过 advance 直接生成下一 effect；工具不能自行改 run 或 fiber。

## 6. Cordis 生命周期解释器

### 6.1 三个解释器同一 advance

[规格] `install`、`fiber_control`、`dispose`、`scope_control` 是四种 command kind。wrapper 均用同一个 `admit_and_apply` 首次 outcome；advance 内解释器校验、写事实和生成有界后继，同事务插入 request/effect/receipt。不存在生命周期专属 ready-command 提交阶段。没有 `plugin_install()` 另写安装状态机、没有 `activate()` 直接 update、没有 `dispose()` 独立清理 worker。

[规格] 安装记录 manifest/artifact/adapter digest 和完整声明，不执行安装脚本，不自动下载。install 完成不表示 fiber active。激活/停用属于 fiber_control；dispose 释放一个 install 自有的内容寻址引用，不能因共享 artifact 拒绝释放本 install 引用。

[规格] 外部 host 需要准备制品时，install admission 写 `preparing` 并发出 host_prepare effect；receipt 经 advance 后 `preparing→installed`，failure/unknown 进入 `prepare_failed|prepare_unknown`。此为统一 effect 的跨提交过程，不是第二 claim。host CAS 外部引用的物理变化不可能和 PG 原子；commit 前后崩溃靠 reservation idempotency/reconcile 收敛，这是显式债务。

### 6.2 install

[规格] 函数/API：`install(scope_id,owner_fiber_id,manifest_bytes,artifact_digest,request_key)->jsonb`，只经 `admit_and_apply(kind=command_install)` 提交。root install 的 owner 两列为空；child install 由 advance 在 G 内锁定 owner fiber/current episode，校验 owner 未关闭、`want_on=true`、episode active，再从当前 episode 推导 owner_episode_id，并在同一事务写两 owner 列与完整 manifest/requires/provides/digest、`preparing` 或 `installed` 状态。owner 不接纳 child 或 scope 已 closing 时拒绝；拒绝同 identity/version 不同 manifest/artifact digest；生成 host_prepare effect 如需外部制品引用。command 和 request/effect receipt 同事务可见，无 ready-command 窗口。

[规格] install 幂等键 `(principal,request_key)`；制品 digest 和 manifest canonical bytes 一同绑定。并发相同声明只得到同一 install；不同 digest 冲突，不覆盖已安装历史。

[规格] install 不自动激活，也不预留 provide slot。resolver 看不到未激活 fiber 的服务。缺依赖 install 仍可存在，组件处于 pending，不伪造成功 activation。指定 owner 时，owner fiber 必须在 admission 时仍处于可接纳子 install 的当前 active episode；检查与 installs 两列写入同事务。`fiber_control(on)` 仅接受 installed；其余准备态返回稳定错误 `install_not_ready`，disposed 返回 `already_terminal`。

### 6.3 fiber_control

[规格] 签名：`fiber_control(fiber_id,action,expected_control_seq,request_key)->jsonb`，action 闭集 `on|off|retry`，以 `admit_and_apply(kind=command_fiber_control)` 进入 advance。advance 验 CAS，写 want_on/control_seq；若目标和当前 episode 已一致则幂等零领域差异；否则产生唯一 `fiber_reconcile` effect。reconcile 仍是普通 effect，且只可由 advance 结算一个阶段。

[规格] activate：先要求所属 install 状态严格为 `installed`，否则返回 `install_not_ready`；再 resolve 全部 hard inject；任一缺项/check=false/slot冲突则 activation 失败且无 episode/slot/pin 半行，fiber 保持 inactive/pending；空 inject 可激活。成功时创建新 episode E2，写 `fibers.current_episode_id=E2`、activation pin、贡献 slot，state active。

[规格] deactivate：先 episode=retiring，所有本 episode slot withdrawn、撤新解析；关闭准入；级联 children 先 dispose；等待 activation pins 清零；run pins 仅在对应 run terminal 且无 `effects.pin_id` 引用它的 ready/claimed effect 或 resource_quiesced_at 为空的 unknown 后清零；按本 fiber contribution_seq DESC 逐项撤销；最后释放 slot、pin 并 episode=closed。每次 reconcile advance 只执行一个有限阶段，遇屏障返回 `deferred` 且不写副作用，可由扫描同一未结算 effect 重试。

[规格] off→on 路径：off 将 E1 置 retiring，先等 E1 的 run/activation pins 与 owner child installs 排空/全部 disposed，再撤贡献、close E1 并清空 `current_episode_id`；历史 install 的复合 FK 固定指向 `episodes(fiber_id=F,episode_id=E1)`，不引用或约束 `fibers.current_episode_id`。因此清空 current 后仍可保留 C→(F,E1) 的历史边，关闭 E1 后 F 可合法创建 E2 并将 current 指针从 NULL 切到 E2；已 disposed 的旧 child install 不阻止新代，也不修改其 owner 历史行。目标 on/off 在清理中反转只更新 control_seq；旧 episode 不复活。每 fiber 最多一个未结算 reconcile effect，避免第二个 lifecycle 队列。

### 6.4 最小 episode 与 pin 裁决

[规格] **最终裁决：保留最小 episode 表；pin 不足以替代 episode。** pin 解决“谁仍引用哪个 slot”与释放屏障，但不能证明激活曾完整成功、当前要撤的是哪一代、配置反转时迟到 outcome 属于旧还是新实例，也不能表示无 slot 的空贡献 fiber 已 active。

[规格] 最小反例：fiber F 激活并注入 provider P，当前无任何 run。若只存 run pin，则 P off 时引用计数为零，P slot 可释放；但 F 的持久激活消费者仍需旧 binding 执行其后续受控回调/退出流程。再次 on 后迟到的旧 F 结果若只有 fiber_id，会污染新代。activation pin 可挡释放；episode_id/epoch 将旧、新激活隔开。因此 episode 与激活 pin 各自承重，不能二选一。

[规格] `episodes` 最小事实为 fiber_id、epoch、state、activation_effect、retire_started_at、closed_at、failure。不开 episode event stream、committed_view、恢复 range 或按值快照；不可变 slot descriptor + pins 足以冻结 v1 能力身份。若以后允许跨多事务可逆 setup，则需要另加有序逆账并重审表数。

### 6.5 resolve、依赖、provide 唯一性

[规格] manifest 的 `requires[]` 是全硬依赖；`provides[]` 给 `(realm,key,descriptor/schema)`。依赖解析先由 scope 祖先链解析 key→realm，再在该 realm 找唯一未 withdrawn、未 released 的 slot；不是从祖先挑最近 provider。active 和受控 `check` 必须真，空 inject 成立。

[规格] activation 时把每个 required key pin 到 slot_id/provider episode。pin 按两类消费者：`consumer_episode_id`（激活身份）或 `consumer_run_id`（业务使用者），严格 XOR。fiber 本身成为消费者即使它暂时无 run，所以有效满足 P1-1 的持久消费者反例。

[规格] slot 唯一键 `(realm,key)` 直到 `released_at` 才释放；withdraw 立即阻新 resolve，但保留旧 pin。release 必须无 live pin、无 owner child、无未结算 owner effect。新 provider 同 realm/key 只能等旧 slot 真正释放，接受切换空窗。

### 6.6 owner 级联与逆序撤销 DAG

[规格] owner 边与 dependency pin 边分开保存。owner child 不隐式获得父的 inject；dependency provider 不自动成为 owner。退出偏序为：业务 run drain → consumer fiber retire → owner child install/fiber dispose（子优先，包含 child install 的 prepare/release obligation）→ 本 fiber contribution 逆序撤销 → provider episode close → slot release → owner install dispose。child install 即使尚无 child fiber，也由 installs.owner_fiber_id/owner_episode_id 枚举；preparing/prepare_unknown 未经同 reservation inspect 不得越过 owner 屏障。该遍历以不可变 `(owner_fiber_id,owner_episode_id)` 为键，不联接 `fibers.current_episode_id`；当前代切换不改变旧 episode 的清理闭包。

[规格] 同一 fiber 内贡献按 `contribution_seq DESC` 逐个撤销（Cordis effect 内部串行 LIFO 的可持久化子集）。跨 fiber 不声称 vendor 顶层全局严格 LIFO；规定先退消费者，再 provider，owner child install/fiber 依赖 owner 先。把 child install→owner fiber/install、owner child fiber→owner episode 与 consumer→provider 依赖合并成有向清理图；advance 在 G 下拒绝环，环错误 `cleanup_cycle`。该偏序仍满足 owner episode close 前 child install disposed，provider release 前 consumer pins 清零。

[规格] 未证明的外部贡献不声明“可逆”。v1 slot/child 仅数据库原子登记；host 资源仅以独立 dispose/inspect effect 管理且留 unknown obligation。逆序撤销只适用于本系统登记且可证明归 owner 的贡献；任意工具已发出的外部业务效果保留历史，不随卸载撤销。

### 6.7 dispose

[规格] `dispose(install_id,request_key)->jsonb` 以 `admit_and_apply(kind=command_dispose)` 进入 advance。advance 将 install 标为 dispose_pending、禁止新 fiber/child install；检查该 install 下所有 fibers 已 disposed、episodes closed、slots released；并检查这些 fibers 所属 episode 下通过 `installs.owner_fiber_id/owner_episode_id` 找到的 child installs 均已 disposed，且无待处理 host_prepare/release obligation。该检查只遍历固定历史 episode 外键，不读取 owner fiber 的 `current_episode_id`；即使 owner fiber 已切换到新 episode，旧 install 的 child 检查仍以原 owner episode 身份闭合。preparing/prepare_unknown 必须先以原 reservation inspect；缺 inspect 时保持 dispose_pending/closing，不得声称 disposed。满足后发 host_release effect；成功 receipt 后标 disposed。共享 CAS 字节仍被其他 install 引用时，本 install 的一份引用照常释放；底层字节物理删除由 CAS 引用集合决定。

[规格] dispose effect 的 release reservation 稳定唯一；receipt 丢失可 replay/inspect，不能重复释放两份引用。DB 不能原子提交文件系统 refcount，最小代价是宿主 CAS 预留账与对账接口；这属于明确的跨世界原子性债务。

### 6.8 install/activate 与 run 的边界

[规格] install 是插件声明/制品实例；activate/deactivate 是 fiber_control 的目标，不是 CE start/cancel；run_start 解析绑定现有 episode 并持 run pins。一个 fiber episode 可服务多个 run；run final 只释放 run pins，不关闭共享 episode。

[规格] child agent spawn 默认 `run_start + parent_run_id + owner_fiber/episode pin`，不是 install child fiber。只有 manifest 明确声明 child 是长活组件、具有独立 provide、需跨多个 run 共享时，才生成 child fiber install/control；由 parent fiber owner 持有并级联 dispose。

## 7. 三面交点矩阵

### 7.1 读法

[规格] 每格描述先提交者/后提交者的结果。所有“提交”均是 advance 成功提交；poll/wait 没有提交序，也不能抢锁决定先后。`F-off` 指 provider withdraw/retire，`R-cancel` 指 run cancel，`T1` 指 ready→claimed 的执行资格提交（写入 attempt/fence/claim_owner/lease_until 的那次 advance），`T2` 指外部结果接纳（class=success|failure|unknown 的那次 advance），包括 model/tool outcome 与 host_prepare/host_release 回执。

| 六动词/loop × lifecycle | install/activate | deactivate/retire | dispose |
|---|---|---|---|
| [规格] start | start 先：run pin 绑已激活 episode；activate 后：resolve 新 episode；install 未激活不能 bind | start 先则 run pin 挡 release；retire 先则拒新 run，已有 run 可排空 | start 先阻 dispose；dispose 先则墓碑，start 拒绝 |
| [规格] poll/wait | 读到前后已提交状态；不触发激活 | 可观察 withdrawn/retiring/blocker；不帮清理 | 可观察 dispose_pending/disposed；不延长引用 |
| [规格] cancel | cancel 只关 run；不改变 activation pin | cancel 先 seal run 但保留被 claimed/unknown 未静默 effect 引用的 run pin；retire 等静默；retire 先则 cancel 正常收 run，随后按同一 pin 条件释放 | cancel 不替代 install dispose；dispose 等所有 run pin |
| [规格] steer | 不改配置 pin；terminal run 一律 already_terminal | active steer 先则旧 pin排空；retire 先后 active steer 仍沿旧 pin；claimed model_call 结算前 pending_steer 不生成第二个 model_call | 已绑定 run 的对话连续性不复活 disposed fiber；权限撤销另发 revoke |
| [规格] respond | 只在原 run interaction 精确消费；不换 plugin | respond 先生成旧 pin continuation；retire 先则 interaction仍可答且 run排空 | dispose 不取消有效交互；run owner/授权撤销可 fence |
| [规格] model/tool advance | 先提交可按冻结 pin执行；激活后 resolve 新绑定；spawn intent 同事务建 child/quota/首个 model effect | T2 先：结果/后继按当时 generation处理；retire 先：迟到结果仍可由当前 claim 结算事实/成本，旧 generation 不生 successor；run pin 待资源静默；slot不得提前释放 | 外部结果不会令 install复活；未结算 effect/资源债务挡 dispose |

### 7.2 两次提交序裁决细则

[规格] start 与 activate 若无可用 episode先提交 start，则 start 失败零 run；本版不创建“等待插件”的半run。先 activate 后 start 成功并 pin。该裁决避免 run 隐式持第二个待依赖生命周期状态。

[规格] run pin 与 deactivate 的线性化均由 G：run pin 先则 retire 能撤新可见但不能 release；retire 先则 run_start resolver 看见 withdrawn 并拒绝。terminal run 的 pin 仍受 `effects.pin_id` 屏障约束；不能出现“检查时未 pin、提交后 pin”窗口。

[规格] T2 与 cancel：T2先则其成本/事件保留，cancel随后关闭 ready successor；cancel先则原 claim token 仍可结算事实/成本，但按当前 driving_generation 不生成新业务；pin 保留至 IO 静默。T2 与 steer 同理，steer前先落地的结果事实保留但旧 generation 不续链。

[规格] cancel 先、retire 后：cancel seal run，不释放被 claimed/unknown 未静默 effect 引用的 run pin；retire withdraw slot 并等待。IO 正常回执确认静默或 inspect 置位后，由对应 advance 释放 pin，再由 reconcile 继续。retire 先、cancel 后：同样先 withdraw，cancel seal 后仍保留 pin 到静默；cancel 不自动卸载 owner fiber。

[规格] owner retire/dispose 与 child install 两序：child install 先提交，则 owner 的 G 后 advance 必须通过 installs.owner_fiber_id/owner_episode_id 找到该行；即便 child 仍 preparing/prepare_unknown，也不得关闭 owner episode 或 disposed owner install，先等同 reservation inspect、release 与 child install dispose。owner retire/dispose 先提交，则 want_off/dispose_pending 阻止 child install admission，返回稳定 `owner_closing`，零 child install。两序均由 G 与完整闭包锁定，不依赖扫描顺序。

[规格] respond 与 cancel/steer：generation CAS及G决定赢家。respond先可生成下一模型effect；cancel随后取消 ready effect。cancel先后respond返回terminal。active steer 先使旧interaction失配并推进 generation；若旧 model_call claimed，则 respond 必须匹配当前 interaction/generation，否则返回 mismatch；terminal steer 直接 already_terminal。

## 8. 崩溃矩阵

| kill 边界 | 已提交事实 | 重启收敛动作与禁止项 |
|---|---|---|
| [规格] command 请求已发出、advance COMMIT 前 | 无 command/request/effect 行可见；事务失败完整回滚 | 客户端以同 effect_id、request_key、bytes 重交 advance；不得扫描一个预先提交的 command 行 |
| [规格] claim COMMIT 后、IO前 | attempt/fence/pin/预算reservation已提交 | 只有显式 replay_safe kind可在资格过期后重投；否则转unknown并阻业务链。不得凭“lease过期”推定未执行 |
| [规格] IO完成、advance前 | DB仍claimed，host可保留原receipt | 同原 effect/token重交原outcome；无可信receipt则unknown+obligation，不建第二 effect偷重试 |
| [规格] advance中途错误 | 单事务回滚，无领域半写、无successor可见 | 重交原可信outcome；唯一约束挡重复。不可重新IO |
| [规格] advance已COMMIT、应答丢失 | receipt、events、领域变化和children/effects均提交 | 相同请求键/bytes replay首次response；不重复预算、事件或effect |
| [规格] provider withdrawn、fiber尚未清理 | slot不可新resolve，旧pins及episode还在 | 全扫resolve和未结算reconcile；run terminal 不释放引用 claimed/unknown IO 的 pin；成功/失败回执或 inspect 静默后才释放；不得级联delete |
| [规格] 子fiber已清理、父尚未清理 | 子墓碑、父episode仍retiring、父贡献未release | 从未结算effect继续；若effect已结算，resolve发现剩余差异再提交下一个控制effect |

## 10. 明确不做与证伪

### 10.1 明确不做

[规格] 不声称 PostgreSQL 事务能原子包住模型/API、OS 进程或文件系统；外界 exactly-once 不成立，采用明确 replay 权利与 unknown。

[规格] 不做完整 Cordis JS 兼容、活对象/闭包/同步事件总线、任意 disposer、任意可逆 effect、跨事务共享值覆盖逆。

[规格] 不做多主机 lease、分布式锁、跨库双写、租户安全沙箱、自动扩权审批、任意 SQL 插件、热改执行中 adapter 字节。

[规格] 不做父取消自动卸载共享 fiber；不做 cancel 自动停进程；不做普通 run 自动 install child fiber。

[规格] 不建独立 queue/work_items/recovery_plan/dirty/wake 事实表；不维护第二恢复状态机。周期扫描公平性是部署前提，停摆只影响活性，不可改变权限和状态。

### 10.2 显式债务

[规格] D1 外部 effect 的结果可信度依赖受信 host adapter 身份与执行记录；DB 单独无法证明远端真的执行了声称的调用。最小代价：固定 adapter digest、attempt token 绑定、host durable journal、fake crash gate；若 host 丢 receipt且无外部查询，则unknown并阻断业务续链。

[规格] D2 Host CAS 文件引用与 PG 无原子事务。最小代价：稳定 reservation、幂等 CAS ref operation、inspect/reconcile effect；CAS 不提供幂等引用操作时保留 debt并阻dispose，不能删掉 responsibility row。

[规格] D3 纯 resolver 不能保障公平进度。无 dirty 表意味着周期全扫描；部署必须运行唯一内建 scheduler，但 scheduler 只提交普通 effect、不持 claim/lease。若需要水平扩展，应先重证 G 与唯一effect约束，不得暗加第二租约。

[规格] D4 取消不能保证停止已发外呼。最小代价：撤数据库发布权、记录 cancel_requested、保留迟到事实/unknown；产品 UI 显示“取消已提交”不等同“远端已停止”。

### 10.3 十条证伪问题

| 假设 | 最小反例 | 推翻条件 |
|---|---|---|
| [规格] advance 真是唯一写口 | 找到任何直接改 run/fiber/slot/episode 的公开函数 | 入口 ACL 可绕过advance即失败 |
| [规格] pin+episode 足以保生命周期 | activation consumer 无run时撤provider | provider提前release或旧代污染新代即失败 |
| [规格] loop 一步一effect | model一次返回两个tool和final混合 | 隐藏多次IO或非原子残缺后继即失败 |
| [规格] cancel与插件分离 | cancel唯一run后销毁共享provider | 任一其他run/persistent consumer失效即失败 |
| [规格] steer只是对话代次 | steer与升级并发后旧结果绑定新provider | 配置身份随steer变化即失败 |
| [规格] spawn是run不是fiber | child为单次任务却永久占provide槽 | 引入多余child fiber即失败 |
| [规格] 全序锁无环 | 两入口相反顺序锁scope/run/fiber | 有死锁或锁后补锁即失败 |
| [规格] 恢复无需恢复状态机 | kill在withdraw/slot清理/receipt窗口 | 只能读自有work queue才能继续即失败 |
| [规格] replay rights封闭 | tool timeout后自动再打一次 | 未声明安全合同仍重放即失败 |
| [规格] Oracle 可独立审读 | brief缺签名/表约束/竞态输入 | 评审者需主规格才能判断即失败 |

[规格] 最脆弱假设：G 事务级全局串行化覆盖所有受控 mutation 且不被函数 ACL/裸 DML 绕过；一处遗漏即使其余单入口成立也是假原生。

## 附录 B：锁与 ABI 的可执行细则

### B.1 锁序及对象集合

[规格] 写事务采用以下固定层级，所有对象集合内以稳定 UUID 字节序升序加行锁：

1. G：`pg_advisory_xact_lock(24,1)`，transaction scoped。
2. request 身份行或其唯一键冲突槽；内部生成 successor 时没有外部 request 行则跳过该层。
3. scope 路由行，从 root 到 leaf，路径同层按 scope UUID 排序。
4. run 行，包含 parent 与 child 时按 run UUID 排序。
5. conversation epoch 所属 run 已锁，不另设 epoch 行锁；effect 行按 effect UUID 排序。
6. install 行按 install UUID 排序。
7. fiber 行，owner 与 child 同时涉及时按 fiber UUID 排序。
8. episode 行，fiber UUID 后按 episode UUID 排序。
9. slot 行按 `(realm,key,slot_id)` 字节序排序。
10. pin 行按 pin UUID 排序。
11. event 序列与 projection 行最后写；projection 按 `(entity_type,entity_id)` 排序。

[规格] 上表顺序中 install 固定在 fiber 之前：最终锁向量为 G → request → scope → run → effect → install → fiber → episode → slot → pin → event/projection。任何入口不能临时改变层次。

[规格] 在取得 G 前，入口只能做无锁输入解析、认证和 canonicalization；不得以 `SELECT ... FOR UPDATE` 预锁对象。取得 G 后可用普通 MVCC 查询发现 owner/依赖闭包，再锁全集；因 G 排除了其他 writer，闭包不会被并发 writer 改写。

[规格] 普通 reader、resolve、poll、wait 不取 G、不锁写行。它们允许读到提交前的 MVCC 旧视图，但不可把查询结果直接当作执行资格。

[规格] 一个 outcome 需要锁未预见的新对象时，必须回滚并返回 `retry_with_closure`，不得持有低层锁再补锁；调用方重交时 advance 在 G 下重新发现完整闭包。

[规格] 禁止 advisory lock 与行锁混用成不同入口顺序；G 是所有协议写者首锁，内部 catalog/DDL 管理属于部署维护窗口，不可在线与运行期 effect 并发。

### B.2 典型死锁反例与测试

[规格] 反例一：start 先锁 fiber、dispose 先锁 install，再各自等对方。修正为都先 G，再按 install→fiber 统一顺序。

[规格] 反例二：run cancel 锁 run 后等待 fiber；fiber retire 锁 fiber 后等待 run pin。G 与 run→install→fiber→episode→slot→pin 序列让第二事务只能在第一事务提交后开始。

[规格] 反例三：spawn 先锁 parent run 再 child；cancel child 先 child 再 parent。两个 run 均按 UUID 排序一次锁完，不能用 parent-first 的树遍历顺序取行锁。

[规格] 反例四：两个 provider 切换事务分别以不同 key 顺序释放 slot，产生 slot A→B 与 B→A。必须对完整 slot closure 以 `(realm,key,slot_id)` 排序。

[规格] 反例五：respond 锁 interaction 所在 projection、cancel 锁 run 后再 interaction。interaction 不独立加锁对象，所有交互写随 run 锁提交。

[规格] 负例必须在两个真实连接中用屏障强制触发上述相反意图，断言无 deadlock、无 `pg_blocking_pids` 环、最终由 G 顺序确定赢家；只断言命令成功不够。

### B.3 函数形状与错误边界

[规格] 唯一 SECURITY DEFINER 写函数签名为：

```sql
CREATE FUNCTION v24.advance(p_effect_id uuid, p_outcome jsonb)
RETURNS jsonb LANGUAGE plpgsql SECURITY DEFINER;
```

[规格] EXECUTE 只授予受信 service role；函数内校验实际 `session_user` 到 principal/host 身份的绑定。调用者不得直接 INSERT/UPDATE/DELETE 十张领域表；迁移 owner 只在离线 migration role 下持 DDL 权。

[规格] 只读解析签名为：`v24.resolve(p_scope_id uuid,p_keys text[]) RETURNS TABLE(key text,slot_id uuid,provider_episode_id uuid,descriptor jsonb,descriptor_digest bytea,live boolean)`，SQL STABLE，不调用函数产生写。

[规格] 只读查询签名为：`v24.poll(p_run_id uuid,p_after_revision bigint) RETURNS jsonb`，`v24.wait_check(p_run_id uuid,p_registration_generation bigint,p_epoch bigint,p_after_event_seq bigint) RETURNS jsonb`；授权通过但无权对象统一映射 `not_found_or_denied`。wait generation 过期返回 `registration_stale`。

[规格] 写动词签名：`v24.start(p_scope_id uuid,p_owner_fiber_id uuid NULL,p_input jsonb,p_budget jsonb,p_request_key text) RETURNS jsonb`；`v24.cancel(p_run_id uuid,p_expected_generation bigint,p_request_key text) RETURNS jsonb`；`v24.steer(p_run_id uuid,p_expected_generation bigint,p_instruction text,p_request_key text) RETURNS jsonb`；`v24.respond(p_run_id uuid,p_interaction_id uuid,p_response jsonb,p_expected_generation bigint,p_request_key text) RETURNS jsonb`。四者是 SQL 调用包装，不具有 SECURITY DEFINER 表写权限，只调用 advance。

[规格] 生命周期 wrapper 签名：`v24.install(p_scope_id uuid,p_owner_fiber_id uuid NULL,p_manifest_bytes bytea,p_artifact_digest bytea,p_request_key text) RETURNS jsonb`；`v24.fiber_control(p_fiber_id uuid,p_action text,p_expected_control_seq bigint,p_request_key text) RETURNS jsonb`；`v24.dispose(p_install_id uuid,p_request_key text) RETURNS jsonb`；`v24.scope_control(p_action text,p_parent_scope_id uuid NULL,p_realm_routes jsonb,p_default_realm text,p_request_key text) RETURNS jsonb`，action 闭集 `create_root|create_child|close`。这些 wrapper 只构造 admission outcome 并委托 advance。

[规格] wrapper 对入参做长度、格式和 schema 快检，但完整授权、CAS、resolve 和幂等裁决全部由 advance 重做；helper 的本地校验不能成为另一种持久化裁决。

[规格] 错误返回类别闭集：`invalid_args,unauthorized,not_found_or_denied,request_conflict,effect_id_conflict,receipt_conflict,stale_generation,registration_stale,already_terminal,owner_closing,install_not_ready,interaction_mismatch,provider_unavailable,scope_closed,dependency_unresolved,provide_conflict,install_identity_conflict,budget_exceeded,invalid_outcome,stale_claim,cleanup_cycle,retry_with_closure,blocked_unknown`。

[规格] 可恢复错误保持无写；业务失败若属于有效 command，则作为已结算失败 receipt 与 request response 原子记录，使相同请求重放得到相同失败而不会重复竞争。

### B.4 attempt、receipt 与回放权利

[规格] `effects.attempt_no` 每次受准入 claim 加一；`fence` 严格单调，只在新 attempt 实际替代旧 claim 时递增；cancel/steer 不改 fence。两个字段不可由 host outcome 提供新值，只能与 claim 内返回 token 对比。

[规格] `claim_owner` 绑定受信 host 的登录身份（`session_user::text`），而非 worker 任意字符串；它与 `principal_id` 分开，用于判定「另一个 host 能否结算该 claim」——同名登录角色即同一 host，v1 单受信宿主下成立，多宿主需另立 token；`lease_until` 只用于判断何时需要 inspect/unknown/reclaim，不构成“旧 IO 必未执行”的证明。

[规格] 每个 `effect_id` 一个最终 outcome。相同 outcome digest 重放返回 `replay`；异 outcome 在 terminal 后返回 `receipt_conflict` 并保留首次事实。

[规格] late outcome 若 token 仍是当前 fence，可结算事实/成本并进入 `late_observation` evidence；当 run driving_generation 或 fiber episode 已变时，不可生成领域 successor；若该证据会造成相互矛盾的 terminal receipt，则记录为 host journal 引用并将 effect 标为 unknown，禁止覆盖旧 receipt。

[规格] `replay_safe` 不是“可重试”布尔值，而是 adapter 版本绑定的声明：同一 effect_id、同一 canonical request、同一外部幂等 token重复调用不会追加第二个不可逆业务作用。

[规格] `no_replay` 的 lease 过期后直接 unknown，除非 host journal/外部 inspect 可证明尚未开始 IO；超时本身不等于失败。

[规格] `manual` 需要显式治理命令决定是否接受已有外部结果或保留 blocked；治理不能重写原 effect 的第一次 receipt。

[规格] model provider 即使接受 idempotency key，也必须单独声明计费/生成重试语义；若供应商可能对同 key 重复计费，则默认 `manual` 或 `no_replay`，不可推定 replay_safe。

[规格] tool 若是纯读取且输出确定，可以按 adapter 和目标资源版本声明 `replay_safe`；写工具只有目标系统提供稳定 idempotency key 或可验证 inspect 才可进入该类。

[规格] host_prepare/host_release 的 reservation id 必须由 advance 确定性绑定 effect_id，host journal 以 reservation id 唯一；reservation 相同但参数 digest 不同视为安全冲突，不产生第二次外部改变。

[规格] inspect_resource 只产生资源观察，不修改原业务 outcome；观察可以结清具体资源 obligation，但不能把 unknown model/tool 改写成 success。

### B.5 请求与效果的状态转换

[规格] command 首次事务的逻辑状态是“不存在→settled”，request row、effect row、receipt 和 projection 同事务可见；不存在对外的 `ready command` 状态。

[规格] 系统 successor 的逻辑状态是“不存在→ready”；由父 effect settlement 同事务插入，不允许另一个 scheduler 先建工作行再通知 advance。

[规格] 外部 effect 状态转换为 `ready→claimed→succeeded|failed|unknown`；claim 是执行资格事实，settlement 是结果事实，两者均经 advance 提交。对已结算或已取消的 effect 再发 claim 属非法资格请求，以 `invalid_args` 零写拒绝。

[规格] ready effect 被 cancel 时可直接转 `cancelled`；claimed effect 只能标 `cancel_requested` 并撤 successor 权，需由原结果、host inspect 或 unknown 收束。

[规格] command 语义验证失败分为两类：结构/认证/幂等冲突在无写路径返回；通过认证但目标条件不满足时，以稳定业务错误 receipt 收束 request，避免相同 key 在状态变化后突然成功。

[规格] run 尚未建立但 start 的 scope/provider 不满足时，advance 仍应决定是否保存失败 request receipt；本规格裁决保存失败 receipt，调用者换 request_key 方可在条件修复后重新 start。

[规格] 这一裁决是幂等边界：重放表达“重取同一次决策”，不是“重新尝试当前条件”。

[规格] generation CAS 失败也不保存成功领域效果；若 request_key 对应的首次错误已作为 business receipt 保存，完全相同请求返回同错误。客户端需刷新 generation 并用新 key 表达新的意图。

[规格] 重复 `respond` 的同 key 精确重放可在 interaction 已消费后读取首次成功响应；不同 key 争答同一 interaction 只允许 G 序列赢家成功。

[规格] `fiber_control` 的重复 on/off 若 expected_control_seq 和请求 bytes 一致，重放首次答复；新 key 对已满足目标可提交一个 no-op command receipt，但不得新建 reconcile successor。

[规格] `dispose` 命令成功后 tombstone 不可撤销；对同一 key 返回原 receipt，对新 key 返回稳定 `already_terminal`。

[规格] 以上规则适用于 event、预算、pin、slot、episode 和 owner 边，重放不得重复加减任何资源计数；计数应从唯一行事实推导或与事件一同原子校验。


## 附录 A：类型闭集与函数签名

### A.1 效果种类

[规格] `kind` 闭集：`command_start,command_cancel,command_steer,command_respond,command_install,command_fiber_control,command_dispose,command_scope_control,model_call,tool_call,host_prepare,host_release,inspect_resource,fiber_reconcile`。`spawn` 是 model outcome 的 DB-only intent，不在闭集中。命令 kind 由首个 `admit_and_apply` outcome 建立且同事务 settled；其余 kind 由已结算 effect 的 successor 插入为 ready。新增 kind 需扩 schema、handler registry、schema digest 与 gate，不能插件自注册任意 SQL handler。

### A.2 关键函数合同

[规格] `advance(effect_id,outcome_v1)->jsonb`：唯一持久化写入口。首次 command call 的 effect_id 由调用方稳定生成；首次事务将 command effect 从不存在推进至 settled，避免 admission 独立提交。

[规格] `advance(effect_id,{v:1,class:"claim",body:{lease_ms}})`：统一执行资格提交。只把 ready 外部 effect 变为 claimed 并递增 attempt/fence/lease，不执行 IO，也不提交领域后继。claim token 由 DB 产生并返回；owner 来自经认证的 host identity，不采信任意 JSON 自报主体。

[规格] `advance(effect_id,{v:1,class:"success|failure|unknown",claim:{attempt,fence,owner},body,receipt_key})`：接纳对应外部结果。相同 effect/token/receipt replay 返回首次响应；过期 token 不可取得新状态写权。任何 `claim_effect` 或 verb helper 若为调用便利而公开，只能构造 outcome 并委托 advance，不得取锁或 DML。

[规格] `resolve(scope,keys)->rows`：STABLE只读，返回 slot/episode/provider/descriptor digest与live布尔。

[规格] `poll(run,after_revision)->jsonb`、`wait_check(run,registration_generation,epoch,after_event_seq)->jsonb`：STABLE只读。SDK wait 在事务外LISTEN/等待，超时再读。

[规格] `install(...)`、`fiber_control(...)`、`dispose(...)`、`scope_control(...)`：command wrapper，只能调用 advance 的 `admit_and_apply`；不得预先插入 command effect 或修改生命周期事实。

### A.3 唯一写口的事务展开

[规格] 公共 command 的客户端先生成 UUID `effect_id`；公开 wrapper 无该参数时按 `f(principal_id,request_key,kind)` 确定性派生。所有 command wrapper 将认证 session 与原始 canonical bytes 交给 advance。advance 在 G 下先校验 `effect_id` 等于该派生值（不等返回 `effect_id_conflict`），再查 `(principal_id,request_key)`：首次则在同一事务创建 settled command effect、receipt、request response、领域事件、目标行变化和 successors；重放则返回首次 response；冲突或验证失败不留下 request/effect 半行。调用者从未观察到 ready command。

[规格] 外部 effect 有三段持久协议，但每一段均是同一个 advance 函数：producer 的 advance 生成 ready effect；host 调 `advance(effect_id, claim outcome)` 取得并提交 attempt/fence；事务提交后才做 IO；最后 `advance(effect_id, host outcome)` 接纳结果。所谓 claim API 仅是 RPC/SQL wrapper 的语法糖，不能直接 claim/update，也不拥有 lease 表。

[规格] “一次 effect，一次 advance”指每个执行结果只能被一次成功 settlement 接纳，不限制该 effect 为资格获取和 outcome 各调用一次 advance。command effect 不执行 host IO，可在 admission 的一次 advance 中直接 settled。禁止的模式是一个 effect kind 有另一套提交、回滚、恢复或资格状态机；不是禁止同一 SQL ABI 接收不同 outcome class。

[规格] command 和 host outcome 都必须带 v1 schema；claim token由advance生成，结果体内的 actor/owner 字段只用于比对，不作为身份来源。所有大小/深度限制先于锁；任何不匹配均不进入 interpreter。effect_id 重用但 request key 不同、或 request key 重用但 canonical bytes 不同，分别返回 `effect_id_conflict` / `request_conflict`，且不覆盖已存事实。
