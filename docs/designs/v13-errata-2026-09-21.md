## 2. E1 · §4.2 chunks 重摄取 — file 面 erratum

### 2.1 被改写的冻结稿合同

冻结稿 **§4.2**「chunks 是可重建投影,三纪律」纪律②原文:

> 重摄取=与新 artifacts 同一事务 delete by source_hash + insert——索引随事务一致,无同步器、无失效协议。

纪律③:外部一律引用 `content_hash`,不引用 chunks 主键——行会随重摄取死亡。G-ctx2 同步断言「重摄取同事务一致」。该合同把「旧投影行死亡」写成无条件 delete-by-`source_hash`。

### 2.2 erratum 正文

**仅 file 面**改写。文件面摄取走 **append-only 收据**(`file_receipts`,settle INSERT,含失败尝试;触发器拒 UPDATE/DELETE)+ 指针(`workspace_files`,PK=`(ws_id, normalized_path, population)`,同 settle UPSERT;热路径只读指针)。不变量:每行指针存在同批同值收据;违约即双源。

blob GC = **引用可达性**:`content_hash` 被以下任一引用则不可回收——① 任一 `workspace_files` 指针;② 未 GC 的 context artifact / manifest section;③ session 水位。重摄取不得删除仍被引用的旧版本;file 面无「按 `source_hash` 无条件清旧代」。

文档语料 / 记忆语料的 **delete-by-source_hash** 纪律②字面保留(含既有「只删无引用行」收窄面)。chunks 行自证(纪律①)与外部只记 `content_hash`(纪律③)不动。

## 3. E2 · §4.5 存在性 Noul 先行 — erratum(论域)

### 3.1 被改写的冻结稿合同

冻结稿 **§4.5**「过滤管道:存在性 Noul 先行 + per-chunk Score」原文无条件:

> 顺序:先一个存在性 Noul 闸住整批花费(语料无答案时 1 次调用替代 k 次),再逐 chunk Score。

G-ctx4 同步断言「存在性 Noul 先行」。论域未区分开放世界与封闭世界;「语料无答案」被写成可短路整批 Score 的闸语义。

### 3.2 erratum 正文

仅 `bootstrap_done=true` 后先行。`bootstrap_done=false`(开放世界)期间禁止对 file corpus 发存在性 Noul;「已注册子集是否足够」的 `no` 不得短路为「仓库无答案」,不得跳过整批 per-chunk Score。空召回只证明已注册闭包内无命中,不是仓库论域已穷尽。

封闭语义绑定 `(ws_id, corpus_epoch, files_cutoff, 策略版本)`(secret/admission policy 版本);任一变化即失效。旧答案不跨 epoch 复用。全库扫触发仍禁 Noul(v2 §7 行「v13 §6.7 / §6.2 触点 3」,遵守,非本条翻案)。
