# v13.1 工作台平面设计:PG 底座 × DuckDB 超级工作台 × Jev 路由

> 状态:**草案 v1**(2026-09-21)。
> 输入:v13 设计冻结稿(`docs/designs/v13-context-on-pg.md`)与 DP1–DP8 八份已验收 plan、
> v13 教程 ch06/ch08/ch09/ch10、v6 完全体(`v6/duck_tools`、W7 方言护栏)、
> v6.1 调研(ABI 墙、双平面、tigerfs)、stepfun 设计审查。
> 定位:**v13 的第一个功能增量**——不动 v13 承重件一根毫毛,新增一个平面。
> 本文与 v13 冲突时:v13 是底座合同,v13.1 只做增量;实现规范冻结后以冻结稿为准。

## 0. 一句话

**PG 是唯一的真相与账本(底座);DuckDB 是数据/代码/文本的超级工作台——
唯一性在镜像层(digest 钉住的 bundle)与合同层(handler='duck'),不在进程层
(每 effect 一个 :memory: 实例,温实例只是缓存);Jev 从工作台能力清单里选
「当前任务启用哪个工作台」,选择是版本化证据、动作授权仍在 SQL 路由;
一切输入输出走 artifacts,文本产物回流 chunks/recall/manifest。**

## 1. 作用力(先于设计的事实)

1. **ABI 墙是物理的**(v6.1 实测):一个 DuckDB 进程只能装一个精确版本;
   社区扩展(sitting_duck/duck_block_utils)面向发布版构建,fork(dev 构建)
   不能互载,`allow_unsigned_extensions` 不绕过版本校验。
   ⇒ **bundle 天然是部署单元**;duck worker 必须独立进程+独立环境。
2. **嵌入性买到的正是「实例近乎免费」**:毫秒起停、无服务器协商——
   实例廉价到按任务丢弃。共享一个常驻 DuckDB 进程会踩四条坑
   (单写者排队/跨会话状态渗漏/一崩全崩/常驻要人伺候),
   它唯一买到的东西(热缓存),会话亲和温实例在合同内部就能拿回。
3. **外部 IO 与事务无原子性**(v13 不变量):DuckDB 执行是库外计算,
   永远走 effect 账本+worker+at-least-once,不进 advance 事务。
4. **判断有成本且答案可缓存**(v13 §1 作用力 4):工作台数量 << 工具数量,
   粗粒度路由判断便宜;但候选集仍要 SQL 预筛先缩小
   (「SQL 管算术,Jev 管语义」的又一次兑现)。
5. **文件住在 PG 行**(tigerfs/artifacts):duck 插件吃内容值
   (`parse_ast(code, lang)` 吃内容不吃路径),文件系统访问不是默认路径;
   `enable_external_access=false` 姿态逐字保留。
6. **工作台选择是优化不是正确性**:选错工作台最多多花钱/多一轮
   (答不了会走兜底路由),不会给出错误答案——默认分支可以 fail-open;
   但**纯只读查询的 sql 快路优先级不受工作台选择影响**(它是零成本路径)。

## 4. 承重件

### 4.1 工作台注册表与 bundle 门(P0)

```sql
CREATE TABLE workbenches (
  wb_id         text PRIMARY KEY,       -- v1 唯一居民: 'duck'
  bundle_digest text NOT NULL,          -- sha256(duckdb_version || 扩展名+digest 清单)
  capabilities  jsonb NOT NULL,         -- 能力清单(给判断平面看):
                                        -- {data:..., code:..., text:...} 各含一句话能力+consumes/produces
  cost_class    text NOT NULL CHECK (cost_class IN ('cheap','heavy')),
  manifest      jsonb NOT NULL,         -- 工具声明(bundle 自报)→ 生成 tools 目录行
  enabled       boolean NOT NULL DEFAULT true
);
-- UPDATE OF bundle_digest/manifest/enabled → bump tools_revision
-- (DP1 事件触发器形态复制;在途信封弃批,版本门免费获得)
```

- **digest 门(fail-closed)**:duck worker 启动时校验本地 bundle digest ==
  `workbenches.bundle_digest`,不匹配拒启动、拒领新 effect。
  已在途的 effect 按其 request 内**冻结的** digest 执行完(已发生的执行不可抹,
  新 effect 必须用新版本——ch06 tool_version_guard 同语义)。
- **目录行生成**:`manifest` 自报的工具声明经 SQL 展开成 `tools` 目录行
  (`handler='duck'`,consumes/produces/input_schema/allowlist 全在声明里)。
  生成是幂等 UPSERT,manifest 换 digest → 目录翻新 → revision bump。
- **为什么是表不是 meta 行**:工作台可见性要进判断 state(能力清单)、
  要被路由 SQL join(`enabled=true`)、要审计——目录是表的同一条推导。

### 4.2 Jev 工作台路由(P0,新判断族)

**问题拆两级**:「用不用工作台」(intent.choice 已答:sql_answer 走快路、
tool_action 走目录)是 v13 已有的;v13.1 新增的是**「启用哪个工作台」**
——粗粒度、一次判断、缓存跨 session。

- **判断族**:`workbench_select`(Choice),注册进 `judgment_templates`(DP2):
  - state 投影 = 任务意图摘要 + 候选工作台能力清单(enabled=true 经
    `capabilities` join 预筛后的短清单);
  - 选项 = 候选 wb_id + 一句话能力;
  - epoch = **pre-bind**(Bind 前可定);缓存键含 manifest 版本
    (能力清单变了自动重问——DP2 request_hash 免费获得)。
- **SQL 预筛先行**:任务 artifact 需求 → `capabilities` 的 consumes/produces
  join 出候选集;单候选时**零 Jev 调用**(短路——§6.7「SQL 先短路确定情形」
  的直接兑现),多候选才问。
- **默认分支(fail-open,版本化)**:missing/timeout/review → 全候选工作台
  目录行照常可见,路由退化到现有 tool 判断+consumes/produces 预筛兜底;
  纯只读查询仍优先 sql 快路(零成本路径不因判断缺席而关闭)。
  **Jev 只产证据**:workbench_select 落 decisions 是证据,
  advance 的路由动作仍由版本化策略行裁量(阈值带决定是否采信)。
- **激活语义**:选中工作台 = 该 turn 的候选工具集收窄到该 handler +
  温实例预热线(可选优化)。不建会话级粘性——每 turn 重判(任务会变),
  判断缓存让重判近乎免费。

### 4.3 duck worker 合同(P0)

照 ch08 三步合同,duck 特化五件:

1. **bundle 门**:启动校验 digest(§4.1)。
2. **实例策略**:每 effect `duckdb.connect(':memory:')` + LOAD 扩展(毫秒级);
   **温实例缓存**(key=session_id,TTL 策略行)仅作加速——丢失 →
   `DUCK_SESSION_LOST` fail-closed,从 artifacts 重放后结果一致(v6 W4 纪律)。
3. **输入水化**:从 artifacts 读内容(内容即值);PG 数据面走
   **白名单快照**(worker 侧只读角色 SELECT 注册表集 → 落临时表,
   v6 `wb_duck_register` 纪律原样:注册时刻快照、enqueue-only、不碰 sticky)。
4. **SQL 校验**:v6 W7 validator 移植(禁 DML/分号/注释/外部函数
   `read_csv`/`postgres_*`/ATTACH/INSTALL/LOAD/PRAGMA/SET),
   外加**只读角色执法**(模型 SQL 永远跑在 `default_transaction_read_only` 下)。
5. **有界结果**:行/字节上限(策略行)→ 截断带标记 → settle + 落 artifact。

effect request 冻结:`{tool, params, handler:'duck', bundle_digest,
tools_revision}`(handler/digest 冻结先例=DP1;identity 含 request 哈希,
digest 变≠同 effect)。mutating duck 工具(文件写)标 `mutating=true`,
失败进 unknown 墙——ch06 恢复纪律照抄。

### 4.4 三个工作台面(P1;= bundle manifest 生成的三族目录行)

| 面 | 工具族(目录行) | 底层 | 备注 |
|---|---|---|---|
| 数据 | `wb_register`/`wb_query`/`wb_preview`/`wb_list`/`wb_columns`/`wb_drop` | duck SQL over PG 白名单快照 | v6 七件套原样移植(v6/duck_tools/duck_tools.sql);view 链=定义 artifact+结果 artifact,不走 sticky |
| 代码 | `wb_parse_ast`/`wb_ast_query`/`wb_code_search` | sitting_duck(`parse_ast(code,lang)` 内容即值;ast_* 宏:call_graph/find_references/match/patch…) | 文件住 tigerfs 行或 artifacts;AST=kind='ast' artifact,后续面可 consumes |
| 文本 | `wb_blocks`/`wb_render`/`wb_doc_pipeline` | duck_block_utils(+markdown/read_lines/webbed) | `ast_to_blocks()` 与代码面组合;块=kind='block' artifact |
| (投影) | `wb_embed_batch` | vss/fts | **T2 定位:离线批量重嵌入/分析**(v13 §7),产出回 chunks;不做在线检索 |

### 4.5 与上下文平面回流(P1)

文本/代码产物 → artifact(kind='block'/'ast'/分析表)→ chunks 摄取
(**corpus='workbench'**,与文档语料/记忆语料三区并列——DP4 分区纪律)→
recall(DP5 T0/T1)→ manifest sections(DP3)。
数据面结果是表格 artifact,不进语料(除非显式转文本)。
**工作台产物因此天然进入 exact replay 的证据链**(blob 冻结/chunk_offset/
被引用不可 GC——DP3/DP4 全套免费继承)。

## 5. 表结构增量

```
workbenches(wb_id, bundle_digest, capabilities, cost_class, manifest, enabled)
  + revision bump 触发器(DP1 事件触发器形态)
tools: 目录行由 manifest 生成(handler='duck');无 DDL 改动
策略行: workbench_limits(结果行/字节上限、温实例 TTL、白名单表集)
       / workbench_select 阈值带(版本化,默认分支)
judgment_templates: workbench_select 族(版本化+projection 声明)
effect request 增量: bundle_digest(冻结字段)
```

## 6. Gate 清单(草案 G-wb*)

```
G-wb1 bundle 门: digest 不匹配→worker 拒启动/拒领;在途 effect 按冻结 digest 完成;
       manifest 翻新→目录行幂等更新→tools_revision bump→在途信封弃批
G-wb2 路由: 单候选零 Jev(短路);多候选 workbench_select 落 decisions;
       毒化三形态(missing/timeout/review)→全候选可见 fail-open+sql 快路不受影响;
       manifest 变→缓存 miss 重问
G-wb3 实例: 同 session 并发只读 effect 结果互不污染(隔离);
       温实例丢失→DUCK_SESSION_LOST→artifacts 重放结果一致
G-wb4 方言: DML/分号/外部函数/ATTACH 全被拒(W7 移植);只读角色下写语句直接报错
G-wb5 有界: 超行/超字节截断带标记;上限是策略行数据
G-wb6 回流: workbench 文本产物→chunks(corpus='workbench')→recall 可召回;
       跨 turn 后进 manifest;exact replay 字节不变
G-wb7 合同: duck worker 与 py fake 同队列各领各的;跨 handler effect_id 逐字节一致;
       mutating duck 工具失败进 unknown(恢复扫描不回 ready)
```

## 7. 交付排序

1. **WB1 注册表+bundle 门**(G-wb1):workbenches 表+manifest 展开+digest 校验;
   用最小 bundle(纯 duck SQL,无扩展)跑通「目录行→effect→worker→artifact」。
2. **WB2 duck worker 完全体**(G-wb3/4/5/7):三步合同+温实例+数据面 v6 移植
   (wb_register 白名单快照+wb_query view 链)+W7 方言护栏+有界结果。
   **这是 go/no-go**:ABI 墙实测(bundle 能不能装)、延迟刻画
   (冷/温实例链式分析延迟——ch09 练习 2 的数字)。
3. **WB3 代码面**(G-wb1 扩展):sitting_duck 进 bundle+AST 工具族+tigerfs 接缝
   (行读优先,大小上限记策略行)。
4. **WB4 文本面+回流**(G-wb6):duck_block_utils+blocks 工具族+
   chunks 回流管道(corpus='workbench')。
5. **WB5 Jev 路由集成**(G-wb2):workbench_select 判断族+预筛短路+默认分支+
   经济记账(工作台调用费用进 judgment_calls/effect usage——DP6/DP7 面直接可算)。
   (WB5 排最后:路由判断是优化,工具级路由在 WB1 起就照常工作。)

## 8. 明确不做(台账)

| 项 | 理由/触发 |
|---|---|
| pg_duckdb(嵌 PG backend) | v6 已否决:崩溃连坐/版本耦合/绕开 worker 易失性 |
| 共享常驻 DuckDB 进程 | 单写者/渗漏/一崩全崩;热缓存由温实例拿回 |
| 在线 RAG 走 duck | T0/T1 已裁(stannum/tsvector+vectorchord);duck 只做 T2 离线投影 |
| duck_tails(git 感知)/duck_hunt(日志) | v6.1 台账原样 |
| 跨平面原子提交 | 与 v13 边界一致(外部 IO 无原子性,靠账本) |
| 会话级工作台粘性/latch 化 | 任务会变;每 turn 重判+判断缓存已近免费;latch 留给身份类冻结 |
| tigerfs .history/.undo | 需 TimescaleDB preload(v6.1 已裁不纳入) |
| fork DuckDB 与社区扩展同载 | ABI 墙物理不可能 |
