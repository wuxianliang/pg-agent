# v14.1 exec 扩展规范（骨架）

> 状态：骨架，待 v14.1 自己的裁定循环。**不**随 v14-dev 核心冻结。未裁定前禁止实现 exec。
> 上游：`docs/designs/v14-dev.md` 第 7 版（核心面：write/edit、glob/grep、审批、provider、harness）。本文件承接从该核心面移出的 exec 面。
> 基线：拆分自 v14-dev 第 6 版 `abeb6d3`。本骨架不自含自身哈希。
> 效力：种子条款是草稿，不是〔P0〕冻结。冻结标准仍是裁定至 0 P0 / 0 P1，但是 **v14.1 自己的循环**，不回流改写已冻结的核心面。

## 0. 定位

**V141-ARCH-1**〔草稿〕v14.1 是 v14-dev 的 exec 扩展，不是第二个 agent。判断、beat、审批函数、lease/fencing、fold、degraded 单主、两阶段 reconcile 的**协议**以 v14-dev 为准；本文件只加 exec 动词、exec 出生、exec 造成的工作区变化如何进入那套协议。核心面没有 exec 实现义务。

## 1. 范围（待裁，先圈住）

1. **exec 目录**与进程边界（种子目录 `{run-test, build}`，不是冻结结论）。
2. **read-only exec 与 mutating exec** 的出生、receipt、失败与 unknown。
3. **mutating exec 状态机**：是否与 write/edit 同锁同图（N20 种子），待与核心面 `degraded_effect_id` / renew 续租对齐后裁定。
4. **多路径 effect**：一次 exec 改到的路径集合未在 proposal 里冻结时如何记账。
5. **tree-diff / 目录 / 文件类型变化**：与「严格限制只许改 proposal 列出的文件」二选一（codex P0-5，待裁）。
6. **exec diff 的 reconcile 数据充分性**与 **exec 失败部分写入矩阵**。
7. **G5 `slow-build`**：v14.1 交付后才补回 v14 基准，不在核心面 G5。

不在本范围：任意 shell 的最终开放。v14-dev §9 保留「无任意 shell / 无 bash」。本文件可以裁定闭集 exec，不可以把裁定偷换成任意 shell，除非另开版本并 bump。

## 2. 对核心面的引用（不复制改写）

- fold、`expected`、`explainable`、degraded 单主、两阶段 reconcile、renew：只引 v14-dev，不在本文件另写一套。
- **INV-3 适用面（从核心面移出的原句，供本循环引用）**：exec 走 reconcile 的世界线**只恢复命题 B，不恢复命题 A**。A 只覆盖窗 1 与无 unknown 的路径。未 reconcile 的 exec unknown 世界线不宣称命题 B。
- 核心面 G3 的 resume/双壳**不依赖** exec。exec 的杀点（`execve` 之后、receipt 之前）在本文件自己的 gate 里钉，不回写 v14-dev G3。

## 3. 种子条款（六轮积累，草稿）

> 下列条款是移出时的原文要点，供 v14.1 裁定循环当起点。标「待裁」的没有默认答案。裁定可以否决种子，不可以假装种子不存在。

**V141-SEED-N20**〔草稿〕bash/exec mutating 与 write/edit 共享 apply 锁与状态图。锁覆盖外部进程运行期间（受控 writer 串行是设计语义）。started 前锁内重算基线。seq 在 claim 已提交事务分配。receipt 丢失 → `unknown` 阻塞 workspace。原 G2 要求 exec×write 并发、kill、基线漂移三组测试。与核心面 T2（`degraded_effect_id` 单主）和 T4（renew 后续租才许 started）对齐后才能升格。

**V141-SEED-R11**〔草稿〕exec proposal 摘要与 write/edit 不同型：exec 摘要 = verb + 类型化 argv + envp 闭集 + cwd + 基线哈希 + 有效期；**diff 不入 exec 摘要**，只在事后 `tool/result`。动词目录种子：`run-test = read_only`、`build = mutating`，目录恰 `{run-test, build}`。升格前须先裁 gB P0-3（run-test 路由）。

**V141-SEED-S8-exec**〔草稿〕exec 杀点：子进程 `execve` 之后、receipt 之前。reconcile SQL 成功后才断言命题 B，折叠含该 seq 的 reconcile/diff，只排除 reconcile 前的 unknown 前缀。write/edit 的 temp 重建杀点留在 v14-dev，不在本种子。

**V141-SEED-R6-CODEX-P0-4**〔待裁〕执行前后**双观测面**与**结算矩阵**。一次 exec 至少要有：执行前观测、执行后观测、以及二者相对 proposal/expected 的结算（全成功 / 部分写入 / 失败零写入 / 不可解释）。矩阵未写死前，禁止用「exit_code=0 即 succeeded」单独结算 mutating exec。read-only exec 是否也要双观测，同轮裁定。

**V141-SEED-R6-CODEX-P0-5**〔待裁〕二选一，没有第三态：

- **tree-diff**：exec 可以改 proposal 未列出的路径；diff 必须覆盖执行后观测到的全部变化（含目录出现/消失、file_type 变化）；reconcile 的数据必须足以重放这棵 diff。
- **严格限制**：exec 只许改 proposal 列出的路径；越界变化 = `unknown` + degraded，禁止把越界写成 succeeded。

目录变化与 file_type 变化在 tree-diff 方案里是 diff 的一等字段；在严格限制方案里是拒绝条件。选定前，核心面 fold **不**接受未预声明路径的 diff。

**V141-SEED-R6-GB-P0-3**〔待裁〕`run-test` 路由。种子把它标成 `read_only`，但测试动词会不会写缓存、覆盖率文件、临时产物，没有证据。裁定必须显式选：保持 read_only（并列出禁止写入的负例），或改为 mutating，或拆成两个动词。未裁前不得把 `run-test` 放进核心面出生三分。

**V141-SEED-TOOL-4**〔草稿，自 v14-dev 第 6 版移出，未升格〕执行方式 = `execve(动词目录固定可执行文件绝对路径 + 版本摘要, argv 数组)`。禁止 `shell=True`、禁止 `sh -c`、禁止字符串拼接执行。verb executable = digest 校验的受信二进制，禁脚本、禁 shebang；本体与子进程树禁调 shell/解释器（扫 `sh -c` / `bash -c` / `shell=True` / `os.system` / `os.popen` / `create_subprocess_shell`）。argv 只有目录固定字面量或类型化参数（enum / int / bool / 相对路径闭集；拒绝对路径、`..`、NUL）。envp = 闭集，禁止继承调用方环境。每个 verb 声明 `workspace_mode`：`read_only` | `mutating`；未声明即拒绝。路径解析：workspace root dirfd 逐级 no-follow，父分量 symlink 即拒。超时 kill 整个进程组。输出超限 = failed，不是截断成功。必测负例：shell 元字符逐字节、verb 重解释 argv、父目录 symlink、TOCTOU、exec×write 并发/kill/基线漂移。加动词 = 合同面变更。

**V141-SEED-ADMIT**〔草稿〕exec mutating（`workspace_mode=mutating`）总建 `requested` proposal，不自动批，不收 grant。无人动作到 expires_at → `expired`；显式 deny → `denied`。write/edit 的 grant 门控留在 v14-dev，不在这里重写。

**V141-SEED-RECONCILE-DATA**〔待裁〕exec diff 要进核心面 fold，必须满足 v14-dev `expected` / reconcile/diff 的字段充分性（old_* = expected，new_* = 受信观测）。tree-diff 方案若做不到这一点，不得宣称命题 B。部分写入（有的路径已改、有的没有）的矩阵与 P0-4 同一轮写死：哪些进 unknown，哪些是带 receipt 的 failed，哪些禁止自动重试。
