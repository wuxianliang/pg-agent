# Investigation: stage 41 D-3 vs stage 42 start deadlock

## Summary

死锁是真的，但不在任何已提交裁决里。它由三份未跟踪草稿（2026-10-06 父计划、2026-10-08 stage 41 / 42 计划）自己拼出来。

已提交的 D-3 只要求 S2 的 gate **覆盖**正文消费，并把它和 watermark 分成两项。父计划 2026-10-08 那段把这改成了另一条谓词：必须引用冻结树里已有的 `steer/injected.payload.text` 消费者，否则不得判绿、不得完成。stage 41 计划把这条写成失败测试和提交禁令。同一父计划又规定 stage 42 只能在那次全绿提交进入 `main` 之后开工，并且禁止 42 调用四个 agentctl 动词。1–40 里没有那个读者。42–45 也不允许成为那个读者。

所以生产者在等一个谁都不许写的读者，下一 stage 又在等这次不许发生的提交。42 的功能输入其实只是冻结的 `controller` / 1。

在 stage 41 计划的「不得提交」被明文改掉之前，本调查不授权提交、不授权把 `actl_steer_body_consumed` 改绿、不授权写 `v13/goal_workflow/`。

## Symptoms

- Stage 41 工作区已暂存。`test_plan_arm.py` 退出码 0。`test_agentctl_verbs.py` 只在最后的 `actl_steer_body_consumed` 失败，文案含 `D-3 open`。
- Stage 41 计划禁止在 D-3 开放时提交、标矩阵 ✅、或写台账「已取代 R11」。
- 父计划施工排序：第 3 项（stage 42）在第 2 项全绿并在 `main` 之后。装载前置是 1–41，不能跳过。
- Stage 42 从 41 只消费冻结 `controller` / 1，不调用四个动词，也不实现 D-3。
- 按现有条文：41 不能进 `main`，42 不能开工，后面也没有合法位置去补消费者。

### Phase 1 - 三条谓词

**Hypothesis:** 矛盾在完成条件，不在 stage 41 SQL 少写了一步。

**Findings:** 三份未跟踪草稿组成一个环。已提交的 D-3 / R11 / R3b / F2 单独不成环。

**Evidence:**

| 角 | 位置 | 要求 |
|---|---|---|
| 生产者不能落地 | 父计划 `:409-411`、`:740` | 引用既有消费者 `file:line`；`actl_steer_body_consumed` 证明正文进入后续路径；不发明消费者；不改冻结运行时；未闭合不得判全绿或完成 |
| 同一停止被写成可执行测试 | stage 41 计划 `:9`、§3.10、§6.1 | 不得判绿、不得提交；`CONSUMER` 未设置就失败；不得把读事件行当成通过 |
| 后一 stage 不能开工 | 父计划 `:496`、`:501-502`、`:752`；stage 42 计划 `:5`、`:43-45`、`:666` | 41 全绿并在 `main` 之后才写 `v13/goal_workflow/`。功能上只消费 `controller` / 1。不调用四个动词。不实现 D-3 |
| 装载把等待变成机械拒绝 | 父计划 `:501` 的「这一次变绿的是什么」含「D-3 正文消费闭合」；stage 42 `:666` | 41 仍 staged 就不准 `git add` 42。42 不能跳过 41，因为开会话要已冻结的 `controller` / 1 |

**Conclusion:** 第 2 项草稿把「全绿」定义成一份 1–40 交不出的证明。第 3 项的开工条件等的就是这次提交。环是文本写出来的。

### Phase 2 - 已提交裁决实际义务到哪

**Hypothesis:** 「正文消费」被读成了「消费者必须已经存在」。

**Findings:** 已提交 D-3 的谓词是覆盖，不是预先存在。

**Evidence:** `docs/reviews/v13-agentctl-da-rulings-2026-10-03.md:13`：

> 甲：允许 `source_principal=controller`。身份由当前 `p_sid` 派生，覆盖模型自报。`v13_control_authorized` 硬前置。审计三联。gate 覆盖伪造 operator / 越权零写 / watermark / 正文消费。

同一文件解锁表（`:50-51`）把 S2 写成「三员 + 复访记录 + 全链 gate」。没有写「消费者 file:line 已存在」，也没有把 S2 绑到 stage 42。

对照：

- 路线图 F2，`docs/plans/v13-layered-control-roadmap-2026-09-26.md:71`：正文生产者按 R3b 不做，指令走 `user/message`。

加严出现在父计划 `:409-411`。该段自己标了 2026-10-08 的搜索结论，而文件名是 2026-10-06。stage 41 计划 `:9` 再把它变成「不得提交」。

**Conclusion:** 死锁的第二谓词是草稿加严，不是 `961dfe0` 的原句。已提交 D-3 仍要求 gate 覆盖正文消费，不能假装这项已经证明过。

### Phase 3 - 是不是漏了一个消费者

**Hypothesis:** 冻结树里有读者，2026-10-08 搜索漏了。

**Findings:** 按停止规则自己的定义，点名位置都不是消费者。定义是：非空 `payload.text` 经既有路径进入目标后续的判断、工具参数、goal 或 effect。读回事件、`v13_session_log`、审计三联、水位 stale、`actl_chain_full` 被明文排除。

**Evidence:** 父计划 `:409` 与 stage 41 计划 §2.6 列出的位置：control 测试只写无 text 事件；memory `:113-127` 只收 `user/message|llm/message`；triage `:161-164` 读的是 `user/message`；envelope 白名单排除该类型；`v13_session_log` 能读出 payload，但不进入 LLM、工具参数、goal 或 effect；`v13_triage_steer` 是名字碰撞。

R1 的「settle 后下一格再解析」是近失。它说的是事件 seq 进入下一折，不是读 `payload.text`。Phase A 台账 L4 还写明活体水位谓词只数 `user/message`，加入 `steer/injected` 字面要先 `ASK_USER`。把正文消费收成 `actl_steer_watermark` 会把 D-3 分开的两项并成一项。

**Conclusion:** 假设 2 在已调查范围内排除。本调查没有另做一次全树搜索。新证据只能是列表之外、且满足同一定义的 `file:line`。

### Phase 4 - 为什么 42 解不开

**Hypothesis:** 42 可以先做，或者 42 就是那个消费者。

**Findings:** 42 需要 41 的装载，但不读 steer 正文，也不许修 D-3。

**Evidence:**

- 父计划 `:496`：「42 从 41 只消费冻结的 `controller/1`，不调用四个 agentctl 动词」。
- 父计划 `:501-502`：41 变绿的内容写成「含 D-3 正文消费闭合」；42 的施工排序是「在 41 全绿之后」。
- 父计划 `:752`：「第 2 项全绿并在 `main` 后施工第 3 项」。
- stage 42 计划 `:5`：41 全绿并进入 `main` 之后才追加 42。
- stage 42 计划 `:45`：「只消费冻结的 `controller` / 1，不调用四个动词，不实现 D-3」。
- stage 42 计划 `:43-45`、`:666`：41 还在 index 里就停止；不准把未提交的 41 和 42 打进同一次提交；D-3 不在本 stage 修。

父计划自己把依赖拆成三列：能力消费、连续装载、施工排序。死锁用的是第三列，却把「全绿」定义得比能力消费更宽。43 不自己调用三个写函数。44 只做签名映射，`to_regprocedure` 不是读正文。45 明确不交付。所以这套计划里没有合法位置去放那个读者。

**Conclusion:** 假设 3 的「排给后面的 stage」不是条文原意。假设 4 只对 41→42 这条边成立。

## Root Cause

已提交 D-3 的谓词是：**gate 要覆盖正文消费，并且和 watermark 分开**（`docs/reviews/v13-agentctl-da-rulings-2026-10-03.md:13`）。

未跟踪父计划 `:409-411` 和 `:740` 把它换成了第二条谓词：**冻结树里已经有 `steer/injected.payload.text` 的消费者，否则停止**。stage 41 计划 `:9` 把第二条写成失败测试和提交禁令。父计划 `:501`、`:752` 和 stage 42 计划 `:5`、`:45`、`:666` 再把 stage 42 的开工绑到这次被禁的提交上。

第二条谓词在同一批草稿里无法满足：

- 1–40 的已点名路径不把 `payload.text` 送进后续判断、工具参数、goal 或 effect。
- 设计中的再解析合同读的是 seq，不是正文；L4 禁止悄悄把 `steer/injected` 加进水位谓词。
- 改 memory / triage / envelope / 水位谓词，就是停止规则说的「改冻结运行时」。
- stage 41 的新 SQL 被规定成生产者。计划禁止在那里新写消费者。
- stage 42 被禁止调用动词，也被禁止实现 D-3。43–45 不能当宿主。
- `AGENTS.md` 禁止把红 gate 留在 `main`，也禁止把下一里程碑卷进同一次提交。

所以这不是实现漏了消费者。这是草稿把「覆盖」写成了「预先存在的读者」，然后把所有可以写读者的位置都关掉，再让下一 stage 的开工去等那个读者。

R11（`:241`）和 F2（路线图 `:71`）仍是已提交的 P1 事实：正文当时没写，指令走 `user/message`。D-3 后来允许 `source_principal=controller`，并要求 gate 覆盖正文消费。它没有写「schema 1 必须带 text，且必须已有读者」。载荷里的 `text` 是草稿超集。超集本身不是死锁。死锁是完成条件。

## Recommendations

现有草稿仍然有效，直到被明文修改。实现者应停。下面是改计划的论证，不是改计划，也不是开工许可。

任何被采纳的修改都要大声记：台账和矩阵追加，README 与测试同一次改，R11 / R3b / F2 / D-3 原句不动。仿 R6 勘误：追加，不把旧句涂掉。

### A — 把生产者提交和消费残项拆开（推荐的计划修改）

同时改父计划、stage 41 计划、stage 42 计划。用父计划自己的三列。

1. 42 的能力消费保持「只消费冻结 `controller` / 1」。42 仍不调用四个动词，仍不闭合 D-3。
2. 连续装载保持 1–41 然后 42。42 不能跳过 41，因为 `{"route_policy_name":"controller","version":1}` 需要那一行已冻结政策。
3. 只改施工排序里「全绿」的定义。父计划 `:501` 和 `:740` 把第 2 项的变绿写成含「D-3 正文消费闭合」。改成：第 2 项的绿是三个 DEFINER 动词、`controller` / 1、`controller_surface`、sql 臂夹具，以及 D-3 里的身份、授权、零写、watermark。正文消费保持未关闭，并且不是第 3 项的前置。
4. 不要让 `actl_steer_body_consumed` 通过。通过会被以后引用成「已经消费」。改成残项仍开放的检查：`CONSUMER` 未设置，九个非消费者仍列出，README / 台账仍写正文未被消费。退出码 0 的意思是「生产者已交付，消费公开未闭合」。
5. 收尾和这次绿的生产者提交同笔，不能在旧断言仍红时做。矩阵缺口写明：注入事件不证明消费；R11 未被取代；不交付 42–45、CE 进程控制、wake、无人值守。台账新节写 S41-D3 未关闭，不写「已取代 R11」。可以另起 R6 式勘误，说生产者现在会写入 `text`，所以 R11 的「正文未写」作为本生产者的描述已过时，但消费未交付，原句不改。「取代」在残项开放时是错的动词。

A 不削弱已提交裁决。它撤回的是让 D-3 的「覆盖」变得无法满足的未跟踪加严，并把未满足项公开记成未关闭，和 L4 同一记法。`AGENTS.md` 仍要求改完后的两条 gate 实跑退出 0 才能提交。红树仍然不能进 `main`。

A 故意留下的真话：D-3 的合并守卫只满足了一部分。这次提交不得标成「S2 全链 gate 已满足 D-3」或「D-3 已闭合」。

### B — 保持现状并提问（在 A 或 C 写进计划之前，这就是规则）

不提交已暂存的六个文件。不创建 `v13/goal_workflow/`。不设置 `CONSUMER`。要继续，只能由用户在草稿里写明选 A、选 C，或另行授权一个未来消费者。授权未来消费者意味着改冻结谓词（L4 要求先 `ASK_USER`）或接受 R3b 所说的 schema 2，那是另一次决定。

B 不发明、不改写，也不交付任一里程碑。它就是把死锁记成「继续等」，不是第三条暗计划。

### C — 去掉 `text`，回到 R3b 登记（另一条计划修改，会改已暂存 SQL）

把未跟踪载荷改回恰好 `{schema_version:1}`，或在用户仍要身份规则时只加 SQL 字面量 `source_principal`、不加正文。然后没有正文可消费，失败断言被撤掉是因为前提撤了，不是把弱检查改名通过。R11 保持为真。F2 仍是指令路径。42 的开工可以等这次缩小后的生产者提交，装载理由与 A 相同。

C 比 A 更贴已提交的 R3b / R11 / F2。它要改的是草稿键集，不是已提交的 D-3 原句。在写进三份计划之前，不能直接改 SQL。

### 不是解法

| 动作 | 为什么拒绝 |
|---|---|
| 把 `CONSUMER` 填成 `v13_session_log` 或九个已点名路径之一 | 伪造消费者。断言已经把它们列成非消费者 |
| 在 41、42 或新表/触发器里把 `text` 抄进 goal 或 effect | 发明消费者 |
| 改 memory、triage、envelope 或水位谓词 | 改冻结运行时。水位还要 L4 的 `ASK_USER` |
| 在 `actl_steer_body_consumed` 仍失败时提交六个暂存文件 | `AGENTS.md`：红 gate 不是完成的里程碑 |
| 写「已取代 R11」或矩阵 ✅ 声称正文已被消费 | 残项开放时的超额声称 |
| 就地改写 D-3、R11、R3b、F2 | 历史句保留。勘误只能追加 |
| 41 与 42 同一次提交，或装载跳过 41 | 一里程碑一次提交；42 的开会话需要 41 冻结的 `controller` / 1 |
| 用投影文件、收据或 stage 45 当消费者 | 45 是明确不交付；父计划禁止第二载体 |
| 用 42 的 `v13_plan_todo_fold` 到达 `done` 充当消费 | 那个 fold 读的是 plan/todo 事件，不是 steer 正文 |

## Preventive Measures

- 凡是声称在实现某条裁决的停止规则，旁边引用该裁决的原谓词。D-3 的谓词是覆盖。草稿的谓词是预先存在。2026-10-06 调查没有停止句，父计划在原处加严。以后的加严要单独标成「超出裁决的新增义务」。
- 「必须已经存在」和「任何 stage 都不许创造它」不能同时出现。开放残项记台账「未关闭」，不要做成下一 stage 装载所依赖的那个里程碑的永久红测试。
- 后一 stage 的开工条件先绑能力消费和连续装载，再绑施工排序。42 的功能输入是 `controller` / 1。把开工绑到无关残项上，必须单独写一句，并检查会不会成环。
- 设计成失败的哨兵不能当装载前驱的退出路径。开放项住在台账缺口里。
- 在真有读者之前，名为 `actl_steer_body_consumed` 的断言不得通过。`v13_session_log` 留在非消费者名单里。
- 「取代 R11」只有在真实读者的测试退出 0 之后才能写。生产者提交最多追加「现在会存 text」的勘误。
- 写「不得提交」时，同一轮审查必须读下一计划的开工条件。stage 41 的计划批评把红 gate 当成内部已决，没有对着 42 的 W0 看，所以环没被看出来。
