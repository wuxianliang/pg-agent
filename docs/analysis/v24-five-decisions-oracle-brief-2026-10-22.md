# v24 五个默认决策：Oracle 建议 brief

> 日期：2026-10-22。背景：v24 是 DB 原生 agent 系统设计（六动词、双账本、Cordis 插件面、代理管理代理）。主设计已有“建议默认”，但需要用户拍板。
> 请对每个决策点给出**推荐选项 + 代价 + 证伪测试 + 可否推迟**；不要替用户做最终决定；不要引入跨节点、不可信沙箱、通用补偿定理这些非目标，除非作为选项代价说明。

## D1 效应语言范围

- **A 纯受限 L_eff**：R 类只允许版本化 `REG/UNREG/owned SET/snapshot GET/typed EMIT`；任意代码只能产生 A/C。
- **B 纯任意代码**：插件用 Python/Node 任意逻辑，作者声明 inverse/compensation；系统只做审计。
- **C 双轨（当前默认）**：R 用 L_eff；A/C 经受信 adapter/任意语言；manifest 固定类别，禁止把 R 偷渡进任意代码。

问题：推荐哪个？边界如何强制？如果选 C，最小的“防偷渡”检查是什么？

## D2 independence 级别

- **D1 仅声明**：footprint 只记录不强制，靠作者。
- **D2 语义强制 + 全局 G 短事务（当前默认）**：read_set/write_set/ownership/dependency edge；准入/claim 检查；G 串行事务。
- **D3 运行时冲突图**：动态依赖/选择性恢复，需要模型与成本测量。
- **D4 全效果全局串行**：最简单，吞吐最差；G 仍不证明语义 independence。

问题：推荐哪个作为 P0–P5 默认？D2 最小必须强制的三件事是什么？D3 的触发条件/退出条件是什么？

## D3 升级语义

- **A 仅 drain**：停新 activation，等旧 consumer 退出再卸载；无热切换。
- **B private realm + broker + route revision + canary + drain（当前目标）**：支持热升级/回退；复杂。
- **C 离线重启升级**：停机，最简单。
- **D 百分比/加权流量**：更复杂，首版不做。

问题：推荐哪个作为 P4/P5 目标？A 到 B 的最小增量是什么？回退时哪些外部 emission 不能被撤销，必须如何记账？

## D4 信任模型

- **A 单机受信（当前默认）**：受信插件/adapter/DBA；ACL+审计；不声称沙箱。
- **B 不可信沙箱**：独立进程/容器、能力限制、无 DB 凭据、syscall/网络策略；大工程。
- **C 混合**：核心受信；不可信插件只允许 A/C，不给 R。

问题：推荐哪个作为 v1？如果选 A，设计里必须怎么标注“这不是安全保证”？如果未来要 B/C，哪个接口现在就要预留？

## D5 存储拆分

- **A 同库三 schema（当前默认）**：`v24_exec/v24_sem/v24_gov`，同事务 + `commit_bundle`。
- **B 分库**：exec 与 sem 分开，outbox/2PC；隔离但失去跨库原子提交。
- **C 同 schema 表前缀**：最简单，边界弱。
- **D 单一事件账 + 投影**：另一种架构，改动最大。

问题：推荐哪个作为 v1？A 的最大运维风险是什么？什么指标会触发 B？

|---|---|---|---|---|---|
