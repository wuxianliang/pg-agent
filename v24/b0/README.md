# v24 Tool/Plugin ABI B0 golden baseline

B0 freezes evidence about the existing v1 boundary and proves the SQL multi-provides composition. It adds tests and records only; it does not change production host or SQL behavior, create s13, or count as a closeout gate.

## Boundary record

The labels below distinguish current observations, facts directly proved by B0, and future contracts whose runtime behavior B0 does not test.

- **observed-current — v1 bytes and journal.** The four `golden/*.json` files fix descriptor, line-JSON request/plugin stdout, provider request, and tool-message bytes. `expected_hex` is the bytes authority; the checker is read-only and cannot re-bless. The Python/Node echo subprocesses are separate producers. PostgreSQL `v24.canonical_json(jsonb)` independently checks descriptor canonicalization. The current parser uses `splitlines()` and its EOF, malformed JSON, non-object result, missing LF, CRLF, extra frame, invalid UTF-8, U+2028, and U+2029 classifications are captured. The journal event set is six items; `dispatch_started` precedes handler execution; the journal remains transcript authority. Current tool lease is 30000 ms with no pre-dispatch remaining-lease check. `replay_class` and `concurrency` are declarations and do not alter recovery or successor behavior.
- **proved-by-B0 — multi-provides and vectors.** One install yields exactly two same-realm slots with ordered contribution sequence and distinct expected descriptor digests; one public `start` requiring both yields exactly two matching live public pins sharing provider fiber/episode/install. The cross-realm negative control returns `dependency_unresolved`, with no run or run pin. Process sentinels are asserted at zero in `finally`. Python/PostgreSQL and Python+Node checks compare fixed bytes, with 34 byte cases and six structural cases.
- **contract-frozen/behavior-unverified — Q1/Q2, owned by W5/W6.** Q1: empty file/directory and complete search with no hits allow `offset=1` as an empty page; only `offset>1` is out of range when `total=0`. Q2: pagination advances by the number of complete items actually returned; an item that cannot fit on an empty page returns the operation-specific too-large error rather than a cursor that cannot advance. B0 has no v2 tools and does not verify either rule. W5/W6 must cover empty pages, offset bounds, and pagination convergence.
- **contract-frozen/behavior-unverified — Q3/Q4/Q5, owned by W5/W6 after W1 design synchronization.** Q3: `max_args_bytes` counts the standalone compact args object, excluding invoke envelope and LF; host injects no default. Q4: `max_value_bytes`, `max_content_bytes`, and `max_meta_bytes` count normalized compact JSON for `value`, content array, and meta object respectively; absent meta is tentatively normalized to `{}` (two bytes). Q5: plugin owns value/full-success-frame pagination and budget; the host-owned renderer owns post-render content/meta checks. The whole v2 stdout frame remains subject to the 64 KiB transport cap and is never silently truncated. If the manifest cannot predict the renderer projection or guarantee cursor progress, W5 stops for design review; it does not add RPC, spill storage, or host-driven cursors. B0 does not test these v2 behaviors or amend the external design.
- **contract-frozen/behavior-unverified — W4.** The v2 dispatcher must use the claimed effect's `lease_until` and `HostDB.remaining_lease_ms`, require remaining lease `>= descriptor_timeout_ms + 5000`, return ordinary `lease_insufficient` failure when short, and prove zero spawn with a process count. W4 also owns additive `model_text` in the existing `dispatch_finished.payload.tool_message.content`, journal-only replay after restart without rerendering, v1 byte equivalence to `canonical_json(output)`, and compatibility with the shared resource handler's `(class,result)` and receipt shape. B0 does not implement or test these behaviors; current `dispatch_started` ordering and journal authority remain unchanged.

## Golden authorities and commands

The authorities remain distinct: PostgreSQL `v24.canonical_json(jsonb)` plus `registry.pg_jsonb_text` for descriptor text; `line_json.build_frame` for request bytes; Python/Node echo subprocesses for raw stdout; `DeepSeekAdapter.send`'s scripted transport body for provider requests; and persisted `dispatch_finished.payload.tool_message.content` for tool-message bytes. No real provider is called and transport headers are not captured.

`capture_golden.py` requires `--output` naming a new directory outside the repository and rejects lexical or symlink-resolved paths inside the repository. Capture twice into separate external directories and compare all four files before reviewing/promoting vectors. `test_golden.py` is read-only. Default mode checks Python and PostgreSQL; `--node` additionally runs Node.
