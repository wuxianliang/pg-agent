# pg-agent v8 · Postgres-Native Agent（P0A 核心 + P0B 最小闭环）

一句话定位：按冻结合同 `docs/designs/v8-dev.md`（2026-09-14 T56 终审冻结）实现的 Postgres-native agent 运行时。Postgres 拥有持久化状态机、合法状态转移与 effect 决策；worker 只执行已持久化的 effect，外部 IO 一律不进事务。

**本轮交付范围**：P0A 的核心冻结件（canonical profile、事件 ABI、receipt/binding、双 fence、状态机核心 DDL）+ P0B 最小闭环（`user event → create step（与初始 decision seal 同事务）→ fake LLM effect → dispatch → complete → assistant event → turn 关闭 → finish_session`，含 kill-at-every-boundary chaos 验收）+ native 生命周期 G6（tools seal 第二条 seal 路径与工具批次：`决策返回 tool calls → step ready/decision → seal_batch → tool 批次 dispatch/complete → final_tools 全成功终态化 → 下一 decision step → decision_only 关 turn → finish`）+ G7a–G7c（known_failure 结算与 retry cohort 分配、recovery 接管、repair + turn-end closer 槽位链）+ G8a（request_cancel 粘性停止收束：三窗口收束、pre-dispatch 双表同步、turn/end 派生、与 finish/dispatch 两序竞态）+ G8b（共享取消收束子操作五出口与 AG01 触发源收口、聚合规则 3 补全与 cancel-wins 矩阵、effect 级取消 code 闭合映射、Conformance 6/15）。P0C（dsh-compat）、P1+（插件世代/多语言/安全）与规格中标注 [LATER] 的合同段未实现——范围对照见 `docs/analysis/v8-impl-digest/*.md` 的 [P0B-CORE]/[LATER] 标注。

## 与规格的对应

- 规格原文：`docs/designs/v8-dev.md`（871 行、单行极长）。分节实现抽取摘要：`docs/analysis/v8-impl-digest/`（s2/s31a/s31b/s32a/s32b/s32c/s33 七份）——实现时以摘要为入口、原文为权威。
- SQL 加载序：`v8/load.py`（schema → keys → **stream/v8_stream.sql（G9a 流式地基：session_events 增列 + slice/grant stub；G9b 观测子操作 `v_stream_observe`/等值判定 `v_stream_equivalence`/`stream_completions`——均先于其消费者加载：公开 append 路径消费新列与 `v_grant_valid`，`complete_effect` 与 append 迟到 chunk 钩子消费观测/等值子操作）** → events → effect → tools → **cancel/v8_closure.sql（G8b 共享取消收束子操作，先于其消费者加载：retry 规则 3 判定/applier、takeover、repair、cancel 命令均消费它）** → retry → takeover → repair → cancel；loop 不加 SQL）。
- 命令面（已实现）：`append_events`（公开白名单；**G9a：assistant/chunk 六项归属校验补全 (2) 已结算 attempt 臂/(3) stream_id 归属/(6) 三合取，并增调用方身份参数（缺省 NULL 向后兼容）**）、`prepare_step`（初始 decision seal）、`seal_batch`（tools seal，第二条 seal 路径）、`dispatch_effect`、`complete_effect`（非流式终局路径 + known_failure 结算 + unknown 分流 + tools 批次 `tool/result` 分支 + **G8b：known_cancellation 结算与粘性 latch 下的共享取消收束三分支** + **G9a：流式 `stream_complete` 字段矩阵五形态与计数 ABI，落在四步序第 (iii) 步** + **G9b：非终局流式观测 (iii)/(iv) 经 `v_stream_observe` 五款状态门唯一裁定（quiescing 不阻观测）、(i) 形态记录认证流事实并跑等值/F4 判定；终局 completion 在 quiescing 下 `DRIVER_QUIESCING`**）、`retry_effect`（批次 cohort 重试分配，公开入口）、`recovery_takeover`（G7b recovery 接管：无结果 in-flight attempt 的单一事务原子接管，cohort 分配第二入口；**G8b：粘性 latch 下经共享收束落 `cancelled_after_dispatch`，不再整命令拒绝**）、`repair`（G7c：unknown_outcome 唯一出口三终态、turn-end closer supersedes 链与 `turn_end_closers` 历史表、`blocked_unknown_effect` 恢复出边；**G8b：规则 3 取消收束走共享实现**）、`request_cancel`（G8a：粘性停止 latch、无活跃工作分支三窗口收束、pre-dispatch 双表原子同步、canonical turn/end 派生；**G8b：活跃 step 的收束改由共享判定/落盘函数派生，含 (β) 已知结果处置**）、`finish_session`；lease CAS（claim/recovery_claim/yield）为非 receipt 受控操作。
- 关键不变量落点：seq 无洞（`sessions.next_seq` 行锁内分配）、单活跃 step（部分唯一索引）、双 fence（`effect_requests.current_job_fence` 验收权威 × `effect_attempts.dispatch_job_fence` 证据绑定快照）、receipt/binding 同事务原子、两条 seal 路径零副作用拒绝、sealed tools batch 成员/ordinal 不可变、`tool/call` slot 级 occurrence identity（`(batch_id, dispatch_ordinal)`）。

## 已知边界（[LATER]，后续里程碑）

- seal 授权阶段与 generation 检查（GRANT_DENIED/GENERATION_REVOKED 门）——依赖 §2.1 完整 grant 模型与 §4 世代域。G9a 已插入**最小** slice/grant stub（slices/grants 表 + `v_grant_valid` 有效 grant 谓词），仅服务 chunk 六项第 (3)(6) 项与 event_append/stream_ingest 基础能力；§2.1 完整模型（授权线性化点、seam 清单、RLS、operator 通道、`constraints` 参数级求值、workspace_handles）仍为 P1。
- 流式余量（G9b 及后续）：**G9b 已交付观测路径**——`stream_progress` 五款状态门（`SESSION_TERMINAL`/superseded/`STREAM_CLOSED`/`REPAIR_REQUIRED`/接受）+ 两交叉 + quiescing 三向、observation receipt 三元组与重发幂等、控制态零修改（AF01）、收齐集合精确相等（不物化 {0..N}）、等值断言时序（final 先到 pending → 尾部补齐；窗口耗尽 `STREAM_INCOMPLETE`）、额外 index 冲突事实（F4 三形态 + 空 payload）、`assistant/partial` 合成（unknown + sticky cancelled）、S04 观测 payload 分层、双层 portable 验收器（`v8/stream/observation.py`，gate `stream/test_observation.py` 72 PASS）。**余量**：`reconcile` 入口接线（`OBSERVATION_WRONG_ENTRY` 结构注记）、跨 attempt 残留清理、真实 lease/超时窗口 sweep（本 stage 以 GUC `v8.stream_window_exhausted` 作可判定输入）。
- recovery 接管的 `FORCE_JOB_TAKEOVER` 受控内部命令与完整八位预锁锁序/generation 死锁序断言（依赖 grant 模型与 §4 世代域）；request_cancel 收束族的余量——pre-dispatch 同步的另两触发源（WORKSPACE_LOST failure-drain / §4 generation drain）与 quiescing 下的受控边收束（driver 切换里程碑）〔G8a 已落地 request_cancel 命令本体；G8b 已落地共享取消收束子操作五出口 + AG01 触发源 (α)(β)(γ)(δ)、cancel-wins 矩阵、`known_cancellation` 结算、`v_aggregate_step` 规则 3 完整实现、G7b 接管处 CANCEL_STICKY 结构 gate 与 G7c 最小规则 3 臂的替换〕、compact 三命令、driver epoch 切换、WORKSPACE_LOST/INFRA failure-drain（含 terminal-session repair/reconcile 入口）、audit 指纹三键（rejection_fingerprint@v1 / transport_rejection_key@v1 / malformed_binding_fingerprint@v2）与 occurrences 子表。
- G7c 既定 LATER 注记：槽位 create-when-absent 模式（本 stage 全部 unknown 收束路径恒建 provisional 槽位，repair 处槽位缺失防御性拒 `REPAIR_TARGET_INVALID`）；tools seal 消费 repair 持久化 `decision_result_identity`/规范化 plan 的端到端联测（repair 侧同构持久化已落地并经 CAS 可重算）。
- DECISION_PLAN_INVALID 的同事务 INFRA 收束（当前为纯 receipt 拒绝）。
- 对抗审查后保持现状的偏差（裁定不修，错误码优先级/值域语义留待版本提升）：canonical 管线校验顺序（NFC 先于结构校验导致的错误码优先级差异）、闰秒时间戳拒绝（`:60` 秒位）、安全整数范围内 `{"$int": n}` 转义形式的歧义（范围内 tagged 形式未拒绝）、payload 时间字段非字符串透传（未按 RFC 3339 校验）、steps `created_at DESC, step_id DESC` 选 last step 的并列歧义（P0B 单 decision step 下不可达）。

各 stage 实现代理自报的其余 deviations 见交付报告；golden vectors 的期望值一律由独立 hashlib 脚本手算硬编码，不用被测实现自算。
